## 3. 坑一：中文路径 + ninja 1.10 → native 构建必崩

**现象**

```
ninja: error: FindFirstFileExA(e:/预警器/cr_lbj_receiver/android/app/src/main/cpp):
        文件名、目录名或卷标语法不正确
```

**原因**

* `local.properties` 的 `cmake.dir` 生效了（`CMakeCache.txt` 里 `CMAKE_COMMAND` 是 pip 的 4.4.5）；
* 但 AGP 会把自己挑的 ninja 以 `-DCMAKE_MAKE_PROGRAM=<绝对路径>` 传给 CMake，而它挑的是
  SDK 里**版本最低**那个 CMake 附带的 ninja（`SDK/cmake/3.22.1/bin/ninja.exe`，即 ninja 1.10.2）；
* ninja 1.10 在 Windows 上以 ANSI 代码页解释 `build.ninja` 里的路径。仓库物理路径含中文
  （`…\预警器\…`），UTF-8 字节被当成 GBK，得到非法路径 → `ERROR_INVALID_NAME`；
* ninja 1.12 起按 UTF-8 处理路径，所以换 ninja 就好。

**修法**（`tools/fix_ninja.ps1` 已实现）

把 SDK 里版本最高的 ninja 复制到 `<cmake.dir>\bin\ninja.exe`：

```powershell
pwsh -File tools/fix_ninja.ps1          # 自动探测 SDK 里最新的 ninja 并安装
pwsh -File tools/fix_ninja.ps1 -Check   # 只检查（>= 1.12 才通过）
```

实测 AGP **优先使用 `<cmake.dir>\bin\ninja.exe`**，装好之后：

```
CMAKE_MAKE_PROGRAM:UNINITIALIZED=D:\Python\Python314\Lib\site-packages\cmake\data\bin\ninja.exe
```

`app/build.gradle.kts` 在配置阶段会检查该文件是否存在，缺失时打印一条明确警告（不阻断，
ASCII 路径下旧 ninja 也能构建）。**不要再把 cmake 版本写死**在工作目录里。

## 4. 坑二：中文路径 + JVM 测试 → ClassNotFoundException

**现象**

```
Could not execute test class 'xyz.mlxkj.crlbj.data.LocoRosterTest'
Caused by: java.lang.ClassNotFoundException: xyz.mlxkj.crlbj.data.LocoRosterTest
```

（注意：`compileDebugUnitTestKotlin` 是成功的，class 文件也确实存在。）

**原因**

Gradle 在 Windows 上把测试进程的 classpath 写进 `@argfile`
（`%USERPROFILE%\.gradle\.tmp\gradle-worker-classpath*.txt`），而 **JDK 启动器解析 argfile
时无法正确还原非 ASCII 路径**——命令行里直接 `-cp "E:\预警器\…"` 正常，同样内容放进
argfile 就找不到类。已用最小样例验证：

```
java -cp "E:\预警器\_argtest\classes" p.T          → 正常输出
java @cp_utf8.txt p.T                             → ClassNotFoundException
java @cp_gbk.txt  p.T                             → ClassNotFoundException
```

**修法**（`tools/test.ps1` 已实现）

用 `subst` 给仓库父目录挂一个 ASCII 盘符，从该盘符下跑 Gradle：

```powershell
pwsh -File tools/test.ps1                      # = :app:testDebugUnitTest
pwsh -File tools/test.ps1 -Task :app:assembleDebug
pwsh -File tools/test.ps1 -ExtraArgs '--no-configuration-cache'
```

实测 Gradle **不会**把 subst 盘符规范化回真实路径（`TEST_CLASSES_DIRS=X:\…`），
argfile 里全是 ASCII，测试正常跑；编译产物是同一份物理文件，不会重复构建。

> 结论：`assembleDebug` 在中文路径下可以直接跑（§3 修好后），**单元测试必须走
> `tools/test.ps1`**。

## 5. 坑三：KSP + 配置缓存

`:app:testDebugUnitTest` 在开配置缓存时会报

```
Configuration cache state could not be cached:
field `__classpathStructure__` of `com.google.devtools.ksp.gradle.KspGradleConfig`
→ error writing value of type 'java.util.ArrayList'
```

这是 KSP 2 + Gradle 9 配置缓存的已知序列化问题（`kspDebugUnitTestKotlin`）。
`tools/test.ps1` 的示例命令里带 `--no-configuration-cache`；`assembleDebug` 不受影响，
可以继续用配置缓存（快）。

## 6. 共享资源怎么进 APK

`shared/` 是桌面端与安卓端**同一份**资源：

```
shared/web/railmap.html         地图页（Leaflet + OpenRailwayMap）
shared/web/vendor/leaflet/*     Leaflet 离线副本
shared/data/loco_roster.csv     配属号段表（16622 行 / 131 型号）
shared/data/loco_types.csv      机车代号 → 短型号 / 中文名
shared/data/loco_specs.json     车型参数
shared/data/places.csv          地图预设中心
```

`app/build.gradle.kts`：

```kotlin
sourceSets.getByName("main") {
    assets.directories.add(rootProject.file("../shared").absolutePath)   // android/ 是 rootProject
}
```

于是 APK 内路径为 `assets/web/railmap.html`、`assets/data/*.csv`，
Kotlin 侧 `file:///android_asset/web/railmap.html`，资产读取 `assets.open("data/…")`。

验证（构建后）：

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$a=[IO.Compression.ZipFile]::OpenRead('app\build\outputs\apk\debug\app-debug.apk')
$a.Entries | Where-Object { $_.FullName -like 'assets/*' } | Select-Object FullName,Length
```

## 7.1 两个 .ps1 脚本的编码约定

	ools/fix_ninja.ps1 与 	ools/test.ps1 都带中文注释，**必须存成 UTF-8 带 BOM**：
Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 ANSI 读，中文字符会破坏字符串定界符，
报 The string is missing the terminator 之类的语法错误。用编辑器改完记得确认 BOM 还在；
用脚本批量改写时：

`powershell
$t = Get-Content .	ools	est.ps1 -Raw -Encoding UTF8
[IO.File]::WriteAllText((Resolve-Path .	ools	est.ps1), $t, (New-Object System.Text.UTF8Encoding($true)))
`
