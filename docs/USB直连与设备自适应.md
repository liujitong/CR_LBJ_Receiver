# USB 直连与设备自适应

本文说明 RTL-SDR USB 直连的实现方式、tuner 识别逻辑与参数推荐策略。

---

## 1. 桌面端

桌面端通过内置的 `rtl_tcp.exe` 与 `rtlsdr.dll`（随程序打包）访问设备，也支持直接用 `rtl_tcp`
服务端；两者对上层是同一个数据源接口。

设备识别与参数推荐：

| 参数 | 策略 |
|---|---|
| tuner 类型 | 读取 `rtlsdr_get_tuner_type()`：R820T/R820T2/R828D/E4000/FC0012/FC0013/FC2580 |
| 采样率 | 960 kS/s（R82xx 推荐）；E4000 建议 240 kS/s |
| 增益 | 按 tuner 的可用增益表选择中高档位（默认 15.7 dB），避免过载 |

---

## 2. Android 端

Android 不具备 `rtl_tcp` 的本地回环便利性，直接以 **libusb + librtlsdr** 访问设备：

```
USB 权限授予 → 找到设备（VID 0x0BDA） → 打开 → 设置采样率/频率/增益
→ 异步回调读取 → 环形缓冲 → DSP 线程
```

关键实现点：

| 问题 | 处理 |
|---|---|
| SELinux 阻止设备枚举 | 使用 `LIBUSB_OPTION_NO_DEVICE_DISCOVERY`，通过文件描述符打开设备 |
| 内核驱动占用 | 打开前尝试 detach kernel driver，失败则重试 |
| 失败无信息 | 错误写入 logcat（`RTLSDR_LOGE`），便于定位 |
| 采样中断 | 记录连续丢块与重连次数，状态页可见 |

「检测设备」会读取 tuner 型号、可用增益档位与实际采样率，写入日志并在界面显示。

---

## 3. 供电与稳定性

| 现象 | 原因 | 处理 |
|---|---|---|
| 打开失败 / 中途断开 | OTG 供电不足 | 使用带供电的 OTG 集线器；换数据线 |
| 采样率上不去 | USB 带宽或供电 | 降到 240 kS/s |
| 丢块率高 | CPU 实时性不足 | 降低采样率或增大块大小 |
| 设备被系统占用 | 其它 SDR 应用正在使用 | 关闭其它应用后重新插拔 |

---

## 4. 兼容性说明

程序对未知 tuner 采取保守策略：使用 240 kS/s 与最低可用增益，并在日志提示型号未识别。
所有 ABI（arm64-v8a / armeabi-v7a / x86_64）均包含完整的 USB 直连实现。
