## 1. 总体分层（数据流）

```
[USB fd]  UsbSource(Kotlin) ──fd──┐
                                  ├→ native: Reader线程 → 环形缓冲 → DSP线程 → 解码回调(JSON,每秒几次)
[socketpair fd] RtlTcp/OwrxSource ├→            │
(Kotlin Socket 读原始字节→写pipe) ┘             ├→ StatusFrame: 共享ByteBuffer双缓冲+序号(UI 10~30Hz轮询)
                                                └→ Kotlin: DecodeEvent 流 → 分类/ETA/去重/GCJ-02
                                                       → ViewModel StateFlow → 五页 UI
                                                       → Room 历史库 / 前台服务 / CSV导出
```

- **数据源统一走 fd**：USB 模式把 `UsbDeviceConnection.getFileDescriptor()` 直接传 JNI（libusb_wrap_sys_device 接管）；网络模式（RTL-TCP/OWRX）由 Kotlin Socket 读取原始字节，写入本地 socketpair 的写端，把读端 fd 传给 JNI——native 侧读线程对 USB fd 和 pipe fd 完全同一套代码，同时保持 native 方法只有 6 个（见 §3）。
- **业务逻辑分界**：DSP→POCSAG→BCH→报文解析（含会话合并、经纬度、机车表）在 C++；车次分类、ETA、去重、GBK 线路名解码、WGS-84→GCJ-02、历史库在 Kotlin（理由见 §4）。

## 3. JNI 契约（native 方法仅 6 个）

```kotlin
object LbjNative {
    // 0=成功，负数=错误码。paramsJson: 采样率/频率/带宽/dcOffset/增益/PPM/AFC/RSSI门限/ blockSize
    external fun nativeInit(paramsJson: String): Int

    // mode: 0=USB(fd为UsbDeviceConnection fd) 1=pipe(fd为socketpair读端)
    external fun nativeStart(sourceFd: Int, mode: Int,
                             freqHz: Long, sampleRate: Int,
                             gainCentiDb: Int, ppm: Int): Int

    external fun nativeStop()          // 停线程、释放设备（保留引擎可 restart）
    external fun nativeRelease()       // 销毁引擎

    // UI 定时调用：把最近一帧 StatusFrame(双缓冲+seq) 拷入 direct ByteBuffer，返回 seq
    external fun nativeReadSpectrum(buffer: ByteBuffer): Int

    // 热更新：RSSI门限/迟滞/保持、AFC开关、userOffsetHz、增益等（json）
    external fun nativeSetParams(jsonParams: String)
}
```

**回调（native→Kotlin）只有 2 个**：
- `onDecodeEvent(json: String)` —— 解码帧事件（每秒几次），JSON 字段与 Python `DecodeResult.toDict()` 同名（缺 `category/eta*/uid`，由 Kotlin 补齐；`route` 传原始字节 hex，见 §4）。
- `onLog(level, msg)` —— 日志（状态页展示+可复制）。

**StatusFrame（共享 ByteBuffer 固定布局，seq 递增）**：
`[seq][32×float 频谱bin(dB)][rssiDb][gateState][afcHz][afcErrHz][块率][丢块][重连次数][解码CPU%][缓冲水位][tuner型号id][实际增益dBi×10][实际采样率]`——UI 侧 10~30Hz 轮询，解码页信号条与状态页共用此数据源。

## 4. C++ 类清单（app/src/main/cpp，与 decoder.py 一比一对应）

| C++ 类 | 对应 Python | 说明 |
|---|---|---|
| `firwin` 辅助函数 | scipy.signal.firwin | Blackman-Harris / Gaussian(σ=7) 窗移植，纯函数 |
| `IqCorrector` | IqCorrector | IIR 直流估计 + Q 路增益平衡（[0.9,1.1] 限幅） |
| `DigitalDownConverter` | DigitalDownConverter | NCO 复乘下变频，setOffset/addOffset |
| `HalfbandDecimator` | HalfbandDecimator | 63 阶半带，÷2；240k 输入时 hbN=0 不实例化 |
| `ChannelFilter` | ChannelFilter | 35kHz 信道 FIR，流式状态 |
| `FirDecimator` | FirDecimator | 整数抽取（240k→48k 时 dec=5） |
| `FmDiscriminator` | FmDiscriminator | 共轭乘积相位差 |
| `RssiGate` | RssiGate | OFF/ARM/ON/HOLD 状态机，门限/迟滞/保持 |
| `AfcLoop` | AfcLoop | 截尾均值+自相关评分，闭环调 DDC |
| `FrontendChain` | FrontendChain | computeChain 自动配链 + process 整链 |
| `Dpll` | dpllBitRecovery | 早迟门 NCO，自适应门限，LBJ 反逻辑 |
| `BchDecoder` | calcSyndrome/LUT/bchDecodeFast | BCH(31,21)，31 项伴随式反查表 |
| `PocsagFramer` | processBitStreaming | 32bit 移位同步(Hamming≤2)、正反相、地址/功能码 |
| `LbjParser` | LbjDecoder.decodeLbj | 报文类型判定(短/合并/独立)、会话合并、机车表(135条UTF-8)、度分坐标(经70~140/纬0<v≤60)、**线路名输出原始字节 hex** |
| `SpectrumFft` | LbjCore._run 内 FFT | 1024 点 radix-2，32 bin 池化+平滑 |
| `RingBuffer` | queue.Queue(maxsize=60) | SPSC 无锁环形缓冲，满则丢块计数 |
| `UsbReader` | RtlSdrDirectSource | librtlsdr+libusb，libusb_wrap_sys_device(fd)，读线程 |
| `PipeReader` | （新增） | 与 UsbReader 同一 read(fd) 接口，读 socketpipe |
| `StatusFrameWriter` | buildDiagnostics | 双缓冲+seq 写共享 ByteBuffer |
| `LbjEngine` | LbjCore | 线程编排、JNI 回调分发、nativeSetParams 热更 |

**关键分界说明（待确认①）**：线路名 GBK 解码放 Kotlin——C++ 只输出 16 hex 字符（8 字节 GBK），Kotlin 用 `Charsets.GBK` 解码并按 `isValidRouteName` 校验。理由：Android 自带 GBK 字符集，C++ 侧嵌全量 GBK→Unicode 表（约 60KB+生成成本）不划算。机车表名称是 UTF-8 常量，留在 C++ 无碍。其余全部字段解析在 C++，保证对拍粒度足够。

**对拍方案（M2 交付）**：
1. `tools/capture_iq.py`：连 OWRX（地址已略，dist 配置同款）录 IQ 原始 uint8 文件；
2. `tools/offline_decode.py`：同一文件喂 decoder.py（FileSource 模式），输出 JSONL；
3. `lbj_cli`：同一份 C++ DSP 以 host 目标编译（CMake 双目标：Android .so + Windows exe），输出同 schema JSONL；
4. `tools/compare.py`：逐字段 diff（timestamp 容差、float 容差 1e-6），差异必须为 0。

## 5. 里程碑（每步可编译可验收）

- **M0 骨架**：Gradle 工程（参考 cw2 的 keystore.properties/ABI 过滤做法，仅借鉴结构）、五页导航、一键开始按钮、Source 接口、JNI 占位、CMake 编出 `liblbj.so`。验收：APK 可装、五页可开、logcat 出 `native init ok`。
- **M1 打通采样**：librtlsdr/libusb 源码入 CMake、fd 打开设备、240 kS/s 连续读、环形缓冲、StatusFrame 出块率；拔插与权限重授自恢复。验收：真机状态页块率稳定。
- **M2 出解码**：DSP→POCSAG→BCH→报文解析全链 + 对拍脚本三件套。验收：真机解出真实列车报文；对拍差异 0。
- **M3 完整**：长报文经纬度、去重、ETA、Room 历史库、高德地图（隐私合规+新 Key）、前台服务通知、IQ 录制、无网降级文字卡。验收：30 分钟连续接收无崩溃无内存增长，五页可用。

## 6. 硬性指标

APK ≤ 25MB（release 只打 arm64-v8a + armeabi-v7a）；解码线程 CPU < 5% 单核；手机端默认采样率 240 kS/s（hbN=0、firDec=5，computeChain 原样适用）；硬件频率 = 821.2375MHz − 50kHz，dcOffsetHz=50000（OWRX 模式 dcOffset=0）；增益默认 19.7dB 手动档（R820T 增益表沿用）。
