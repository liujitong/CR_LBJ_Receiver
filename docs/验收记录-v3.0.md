## 2. 桌面端离屏冒烟（18 步全过）

```
$env:QT_QPA_PLATFORM=offscreen
$env:QTWEBENGINE_CHROMIUM_FLAGS='--no-sandbox --disable-gpu --enable-unsafe-swiftshader'
$env:CRLBJ_WORK_DIR="$env:TEMP\crlbj_verify_run"
$ python _verify_v3.py        # 一次性脚本，跑完已删
```

关键读数：

| 检查 | 结果 |
|---|---|
| 版本 | `cr_lbj.__version__ = 3.0.0` |
| 默认配置 | `mapBase=osm mapRail=orm_standard tdtKey='' trainQuerySource=auto` |
| 地图装载 | `hasMap=True`（`shared/web/railmap.html`）、`host.status()` 返回 dict |
| 页面状态 | `{"base":"osm","rail":"orm_standard","coord":"wgs","night":true,"follow":true,"locked":false,"zoom":12,"center":[115.8601,28.6800],"tilesTotal":0,"tilesFailed":27}` |
| 标记渲染 | `updateTrain(...)` 后 `.lbj-marker` 数量 0 → 1 |
| 切底图/夜间 | 标记数仍为 1（**没有重建页面**） |
| 页面内改底图 | JS 侧 `LBJ.setBase('carto_light')` → 1200 ms 轮询把 `config.mapBase` 改写成 `carto_light` |
| 瓦片全失败 | `tile_bad=True`，坐标栏 `底图不可达，换一张` |
| 配属查询 | `HXD1D 0123 → 上局沪段（号段 106-137）` |
| 车次查询 | `G7 · 高速 · 北京南→上海虹桥 · 配属 北京动车段`（RailGo 实测） |
| 菜单 | 视图（含「铁路图层（OpenRailwayMap）」+「底图」11 项）、配置（7 页）、工具（车次查询/机车配属查询/检查数据更新）、帮助 |
| 异常 | `errors=[]`，退出码 0 |

> `tilesFailed=27` 是预期结果：本机无法访问 OSM 瓦片。真实网络下换成天地图/高德可出图。

## 6. 未验证项（明确留白，不当作已验证）

| 项 | 原因 | 建议 |
|---|---|---|
| OSM / CARTO / Esri / OpenTopoMap / OpenRailwayMap 真实出图 | 本机 TLS 被阻断 | 在有代理的网络下逐张切换确认；ORM 图层在中国境内数据稀疏属正常 |
| 天地图 tk 实图 | 无 tk（并需 Referer 白名单） | 申请「浏览器端」tk 后填入设置再验 |
| 高德底图叠加列车点偏移量目视 | 同上（越不出境） | 切 `amap` 底图，看标记是否压在道路上 |
| 真实 RTL-SDR 插棒解码 | 无硬件 | 见 [USB 直连与设备自适应](USB直连与设备自适应.md) 第 8 节清单 |
| 安卓 OTG 真机 | 无设备 | 模拟器只覆盖网络源与 UI 全链路 |
| `rail.re` 接口 | 本机不可达、响应结构无第三方佐证 | 暂不接入（已在 `docs/车次与配属查询.md` §5 说明） |
