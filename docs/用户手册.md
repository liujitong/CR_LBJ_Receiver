## 1. 这个程序能做什么

本程序用一支几十元的 RTL-SDR 接收棒，接收中国铁路列车 **LBJ 列车防护报警设备**
在 **821.2375 MHz** 发出的数传信号，实时解码出车次、机车号、线路、公里标、速度和
（部分车次）**经纬度**，并在地图上显示列车位置。

| 能力 | 说明 |
|---|---|
| 实时解码 | 1200 bps POCSAG 编码，BCH(31,21) 单比特纠错 |
| 全字段解析 | 车次、机车号/代号、线路、公里标、方向、速度、经纬度、报文类别 |
| 三种数据源 | 本机 USB（自动起 rtl_tcp）、局域网 RTL-TCP、OpenWebRX |
| 实时地图 | 高德 JS API 2.0，按方向着色，点击看时间/速度/公里标，支持夜间/日间配色 |
| 2026 车次规则 | X/G/T/K/D/C/S/Z/N/V/B/DH/DJ 新字头，自动兼容旧车次 |
| 历史留档 | SQLite 本地库（含经纬度），可导出 CSV |
| 辅助查询 | 12306 时刻表、机车详情、ETA 到达估算 |
| 择优合并 | 同一次广播的多帧只留最优一条，列表/地图/入库都不重复 |
| 一站式启动 | 内附 rtl_tcp，装完驱动就能收；全屏、界面缩放、触屏惯性滚动 |

**它不是**：不是铁路官方设备，不能发报文，不能用于行车；只做被动接收与解码。

## 2. 三步开始使用

### 第 1 步：装驱动（一次性）

Windows 下 RTL2832U 默认是 DVB-T 电视棒驱动，必须换成 WinUSB：

1. 插上 RTL-SDR；
2. 打开 [Zadig](https://zadig.akeo.ie/)，`Options → List All Devices`；
3. 选中 `Bulk-In, Interface (Interface 0)`（VID `0BDA` / PID `2838`）；
4. 目标驱动选 **WinUSB**，点 `Replace Driver`。

> 已经用 SDR#、rtl_tcp、OpenWebRX 正常用过这支棒子的，驱动通常已经就绪，可跳过。

### 第 2 步：选数据源

打开程序 →「配置 → 配置...」（`Ctrl+,`）→ 顶部「数据源」组：

- 插的是本机 USB 棒 → 选 **本机 RTL-SDR (USB 自动)**；
- 用局域网/本机的 rtl_tcp 服务 → 选 **局域网 / 本地 RTL-TCP** 并填地址端口；
- 连别人的 OpenWebRX → 选 **OWRX** 并填地址端口。

点「检测设备」可确认程序是否认到了棒子。没认到会给出具体原因。

### 第 3 步：开始接收

点左上「▶ 开始」。状态栏显示「DSP 运行中」，工具栏「● 未连接」变成「● 已连接」，
右上「输出 2」里的「信号」方块开始显示 dB 值。收到报文后，上段右侧「当前解码」页签会出现记录，
地图上出现第一个标记，右下的「列车信息」卡片同时被填满。

> 只发基础帧的车次不会出现在地图上，属正常现象，见 [6.1](#61-为什么有的车没有经纬度)。

## 3. 界面总览

界面是**全景式三段布局**（v2.3）：上段回答「这一列车在哪、是谁」，
中段是频谱与两张查询卡，底栏两条输出。**没有页签，所有内容同屏可见**。

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ 文件   视图   配置   帮助                                                     │
├───────────────────────────────────────────────────────────────────────────────┤
│ [▶ 开始] [■ 停止]  频率: 821.2375 MHz   ● 已连接        [日间]  [全屏]       │
├──────────────────────────────────────────┬────────────────────────────────────┤
│                                          │ 当前解码 / 历史记录                │
│                                          │ 时间 车次 方向 速度 公里标 …       │
│          实时位置（高德地图）            ├────────────────────────────────────┤
│              约六成宽度                  │ 列车信息                           │
│            （高德 JS API）               │ 车次 方向 速度 公里标 机车 线路 …  │
│ [夜间] [跟随] [清除] [网页]              │                                    │
├────────────────────┬─────────────────────┴──────────────┬─────────────────────┤
│ 接收频谱   [图形▾] │ 车次信息                           │ 机车信息            │
│  ~~~──~──~──       │ 12306 结果 / 查看时刻表            │ 机型 / 牵引参数     │
├────────────────────┴────────────────────────────────────┴─────────────────────┤
│ 输出 1 · 日志（最近几条）        │ 输出 2 · 接收状态                          │
│ 16:04:35 [启动] 连接 127.0.0.1…  │ ┌信号─┐┌AFC─┐┌干扰┐┌链路┐                  │
```

所有分隔线都可以拖动；窗口整体按屏幕大小自适应并居中。
`F11` 全屏、`Ctrl+L` 看完整日志、`Ctrl+D` 开运行状态仪表板、`Ctrl+T` 切换日/夜配色。

### 3.1 顶部工具栏

| 元素 | 说明 |
|---|---|
| ▶ 开始 / ■ 停止 | 启动、停止 DSP 与网络接收 |
| 频率 | 当前中心频率，正常为 821.2375 MHz |
| ● 已连接 / ● 未连接 | 数据源 TCP 连接状态 |
| 频谱 | 「图形频谱」（pyqtgraph，好看吃资源）/「终端频谱」（字符画，省资源），切换即时生效 |
| 全屏 | 切换全屏（同 `F11`、视图菜单、`Esc` 退出） |

### 3.2 上段左：实时位置

高德地图卡片，约占上段宽度的六成。左上角一组按钮：**夜间 / 日间**（配色切换）、
**中心**、**跟随**、**清除**、**网页**。标记、信息卡片、轨迹的画法与避让规则详见
[第 6 节](#6-经纬度与实时地图)。

「中心」把视野挪回配置里的**默认中心**（一个地名，比如「南昌站」），
只移动视图、不会在图上加任何标记。

### 3.3 上段右：当前解码 / 历史记录 + 列车信息

右列上下两块，中间的分隔线可拖：

| 位置 | 内容 |
|---|---|
| 上（两张表的小页签） | **当前解码**：最近 10 分钟的记录，同一列车只保留最优的一条（就地更新，不刷屏）；**历史记录**：本地 SQLite 库中的全部记录（最多显示 1000 行） |
| 下（列车信息卡片） | 车次 / 方向 / 速度 / 公里标 / 机车 / 线路 / 类别 / 到达时间 / 距离 / 经纬度 / 本站，按可用宽度自动排 2~6 列 |

窗口很矮时，列车信息卡片会自动**收起字段名只留值**（鼠标停在值上仍能看到字段名），
保证 11 个字段不会被裁掉。

### 3.4 中段：频谱 | 车次信息 | 机车信息

v2.3 取消了页签，中段三块**并排同屏**，宽度比例约 5 : 3 : 3，分隔线可拖。

| 位置 | 显示什么 |
|---|---|
| 接收频谱（左） | 一条实时功率谱曲线 + RSSI 门限虚线 + 一行摘要（`±480 kHz · 门限 -55 dB · 峰值 -58 dB`），标题栏右侧带「图形 / 终端」下拉 |
| 车次信息（中） | 12306 查询结论 + 「查看时刻表」按钮（左侧结论、右侧按钮） |
| 机车信息（右） | 机型、牵引参数、简介 + 「机车详情」按钮 |

频谱页左上角那句结论会自动判定为三种之一：

- **有信号**：峰值高于门限且有解调余量，绿色；
- **弱信号**：接近门限，橙色（可微调增益或换天线位置）；
- **静噪**：峰值远低于门限，灰色（该频段暂时没车，属正常）。

> 曲线两端留了内边距、文字按可用宽度省略，所以**任何窗口宽度下频谱都不会撑出边框**；
> 高度随中段自动伸缩，不会出现半截图。
>
> 想看全部细节（AFC、FERR、采样率、块大小、接收字节、运行时长…）？
> 用下一节的**运行状态仪表板**，那里有 48 项。
>
> **频谱模式切换就在频谱卡片的标题栏右侧**（不再占工具栏）：下拉选「图形」或「终端」，
切完立即生效并记住选择。终端模式是字符画，省 CPU/GPU，适合老机器；
它的条形图行数会随卡片高度（2~8 行）、每格重复数随宽度自动伸缩，底部四行状态始终留在可视区。

### 3.5 底栏：输出 1 · 日志 ｜ 输出 2 · 接收状态

底栏左右**各占一半**：

| 位置 | 内容 | 点击行为 |
|---|---|---|
| 输出 1 · 日志（左） | 滚动显示最近若干条日志（按级别着色：白/绿/黄/红） | 打开实时日志窗口（同 `Ctrl+L`） |
| 输出 2 · 接收状态（右） | 信号 / AFC / 干扰 / 链路 **四个等宽方块** | 点任意方块打开运行状态仪表板（同 `Ctrl+D`） |

四个方块的含义与变色规则（正常只有灰色描边，异常时**整块**变黄或变红）：

| 标签 | 正常 | 异常时 |
|---|---|---|
| 信号 | 高于门限时绿色，低于门限灰白 | 弱于 -65 dB 橙色、弱于 -80 dB 红色 |
| AFC | 显示置信度（0~1），灰白 | 置信度 < 0.10 且正在放行 → 「0.06 低」橙色；频偏 > ±200 Hz 也橙色 |
| 干扰 | 「无」 | 近 60 秒有 BCH 错包 → 「N 次」橙色，过期自动归零 |
| 链路 | 已连（绿色） | 断开（红色） |

鼠标悬停在右侧区域，会把这些合成一句话，例如
「● 信号偏弱 · AFC 置信度低 · 近 60 秒干扰 3 次」。

> **告警只显示一次。** 日志里会出现完整的 `[告警] ⚠ 探测到下行信号 干扰严重`，
> 底栏右侧只加一个「干扰 N 次」计数——v2.1 那种同一句话在日志和状态栏各刷一遍的重复已经去掉。

### 3.6 运行状态仪表板（`Ctrl+D`）

「帮助 → 运行状态仪表板」，或者按 `Ctrl+D`，或者点输出 2 里任意一个状态方块。

v2.3 起改成**分组卡片 + 指标方块**：每组一张卡，每个指标一个小方块，
正常是灰白，**良好标绿、注意标黄、异常标红**（边框与数值同时变色），
扫一眼就知道该看哪一项。想发文本给别人时仍可点「复制全部」：

| 分组 | 主要指标 |
|---|---|
| 链路 | 数据源、地址、连接状态、重连次数、接收字节、块率、数据速率、抖动 CV、运行时长、诊断 |
| 射频与频谱 | 中心频率、采样率、增益、门限、峰值、均值、占用带宽、频谱模式 |
| 门控与 AFC | RX 门控状态、AFC 偏移、频率误差（FERR）、置信度、噪声底、判定建议 |
| 解码与去重 | 已解帧数、有效报文、BCH 纠错数、同步失败、去重丢弃、择优升级、窗口大小 |
| 界面 | 主题、缩放倍率、窗口尺寸、上段/中段/输出区高度、字段列数、地图状态、干扰计数 |

窗口内几个按钮：

| 元素 | 作用 |
|---|---|
| 自动刷新 | 每秒刷新一次，取消勾选后画面冻结 |
| 立即刷新 | 手动取一次快照 |
| 复制全部 | 把当前所有指标拼成文本放进剪贴板 |

| 入口 | 效果 |

### 3.10 全屏模式

三种进入方式：工具栏「全屏」按钮、`F11`、视图菜单。全屏时菜单栏自动隐藏，
把垂直空间全部让给地图和频谱；`Esc` 或再按一次 `F11` 退出。
全屏与窗口状态切换后布局会自动重算，不会出现地图白屏。

### 3.11 分辨率自适应与界面缩放

**布局自己会调，不用手拖。** 窗口尺寸一变（拖边框、最大化、全屏、换显示器），程序会重算：

| 自适应项 | 规则 |
|---|---|
| 三段高度 | 底栏输出区约 14%（84~132 px）、中段约 38%（不低于 126 px）、上段吃掉剩余 |
| 地图最小宽度 | 窗口 < 1100 时降到 260 px，避免把窗口顶宽 |
| 字段列数 | 列车信息按可用宽度排 2~6 列，最后一行不会只剩一列；卡片太矮时自动收起字段名只留值 |
| 标题显隐 | 宽度 < 980 时收起左上角程序名，把空间让给频率与连接状态 |
| 频谱文字 | 图形频谱的说明文字按可用宽度省略，曲线两端留内边距，任何宽度下都不越界 |
| 终端频谱 | 条形图行数按面板高度取 2~8 行、每格横向重复数按宽度取 1~24，底部四行状态始终留在可视区，不出滚动条 |

只在**尺寸档位**变化时重算（宽度每 160 px 一档、高度每 120 px 一档），
同一档位内你拖过的分隔条不会被系统覆盖。

**缩放基准**在启动时按屏幕宽高综合判断（取更紧的一边，基准 1920×1040 ≈ 100%）：

| 屏幕 | 自动倍率 | 典型设备 |
|---|---|---|
| ≥ 2400×1300 | 1.15 | 2K / 4K 显示器、高分辨率笔记本 |
| 1880×1020 以上 | 1.00 | 1920×1080 |
| 1540×830 以上 | 0.92 | 1600×900 |
| 更小 | 0.88 | 1366×768、1024×600 老机器 |

不满意可在「视图 → 界面缩放」或「配置 → 解码与界面 → 界面缩放」里固定一个倍率
（85% ~ 150%，选「自动」则继续跟随屏幕）。缩放是整体等比缩放——字号、行高、按钮、
分隔条一起变，不只是把字放大。**修改后需重启程序生效。**

另外程序向 Qt 申请了高 DPI 直通（`PassThrough`），Windows 显示缩放设成 125% / 150%
时不会出现界面被系统二次拉伸的模糊感。

### 3.12 触屏设备（Surface 等）

针对触屏 Windows 设备做了这些调整：

- 表格、滚动区域支持**手指惯性滚动**（`QScroller`，触摸手势）；
- 表格行高、滚动条宽度、分隔条宽度整体加宽，手指点得中；
- 按钮最小高度加大，避免误触；
- 分隔条拖拽热区加宽，触控笔/手指都能拖动。

鼠标操作完全不受影响，同一套界面两种输入都顺手。

## 4. 数据源配置

### 4.1 三种类型

| 类型 | 适用场景 | 需要额外准备 |
|---|---|---|
| **本机 RTL-SDR (USB 自动)** | 棒子插在这台电脑上 | 驱动（Zadig）+ `rtl_tcp.exe`（打包版已内附，源码运行需自备） |
| **局域网 / 本地 RTL-TCP** | 同网段有 rtl_tcp 服务（树莓派、另一台电脑） | 对方已运行 rtl_tcp |
| **OWRX (OpenWebRX)** | 连公开或自建的 OpenWebRX | 对方开启 rtl_tcp 兼容端口（默认 8073），**DC 偏移设为 0** |

### 4.2 「USB 自动」是怎么省步骤的

选「本机 RTL-SDR (USB 自动)」后，程序会自己完成以前要手打的一串命令：

1. 按顺序查找 `rtl_tcp.exe`：程序目录 → `tools/rtl` 子目录 → `rtl` 子目录 →
   `RTL_TCP_Server` 子目录 → 逐级上级目录 → `PATH`；
2. 若配置里填了「rtl_tcp 路径」则优先用它；
3. 检查目标端口是否已有 rtl_tcp 在跑，有就直接复用；
4. 没有就用空闲端口启动：`rtl_tcp -a 127.0.0.1 -p <端口> -f <频率-DC偏移> -s <采样率> -g <增益> -P <ppm> [-d <设备序号>]`；
5. 最多等 8 秒端口就绪，失败会把 rtl_tcp 的原始报错贴到日志；
6. 停止接收时自动结束自己拉起的进程（复用别人起的服务则不动）。

> **一站式启动**：发布包把 `rtl_tcp.exe`、`rtl_test.exe`、`rtlsdr.dll`、
> `msvcr100.dll`、`pthreadVC2.dll` 一起打在 exe 里，运行时解压到临时目录的 `rtl/`，
> 所以装完驱动、插上棒子、点「开始」就能收，**不需要另外装 RTL-SDR 工具包**。
> 源码运行时这几个文件放在项目的 `tools/rtl/` 目录下即可，程序会优先去那里找。

### 4.3 多套数据源

「数据源」组顶部的下拉框是「已保存」列表，可保存任意多套，随时切换：

| 按钮 | 作用 |
|---|---|
| 新增 | 新建一套（名称、类型、主机、端口、采样率、增益、PPM、DC 偏移） |
| 编辑 | 修改当前选中那套 |
| 删除 | 删除当前选中那套（至少保留一套） |
| 检测设备 | 调用 `rtl_test -t` 列出本机 RTL-SDR |

切换数据源属于「必须重连」的改动，点「确定」后程序会自动重启 DSP。

### 4.4 其他数据源相关参数

| 字段 | 默认 | 说明 |
|---|---|---|
| 主机 / 端口 | 127.0.0.1 / 1234 | RTL-TCP 地址；OWRX 一般是 8073 |
| 设备序号 | 0 | 多支 SDR 时选第几支（0 = 第一支） |
| rtl_tcp 路径 | 空 | 留空自动查找；也可点「浏览」手动指定 |

## 5. 接收与解码

### 5.1 启动后应该看到什么

| 观察点 | 正常表现 |
|---|---|
| 工具栏连接指示 | ● 已连接（绿色） |
| 中段「接收频谱」卡片 | 一行结论是「有信号」，曲线有起伏 |
| 底栏右侧「信号」标签 | 有数值，随信号起伏；高于门限时变绿 |
| 底栏右侧「AFC」标签 | 显示 0.xx 的置信度；持续显示「低」说明没锁到信号 |
| 底栏右侧「干扰」标签 | 正常显示「无」；短时间内多次出现说明频段被压制 |
| 底栏右侧「链路」标签 | 「已连」（绿色） |
| 日志 | 无反复重连 |

列车经过时才会有报文。821.2375 MHz 是列车防护报警频段，**车少的路段可能十几分钟没有任何报文**，
这不是程序坏了。

### 5.2 读底栏的四个状态标签

主界面不再单独占一页显示接收状态：**精要都在底栏右侧**，细节在仪表板。

| 标签 | 含义 | 怎么判断 |
|---|---|---|
| 信号 | 当前 RSSI（dB） | 越接近 0 越强；低于 -80 dB 基本收不到 |
| AFC | AFC 锁定质量（0~1） | 低于 0.10 且正在放行时显示「低」；频偏 > ±200 Hz 会显示 Hz 值 |
| 干扰 | 近 60 秒 BCH 错包告警次数 | 偶发 1~2 次正常；持续增长说明信号被压制或频偏过大 |
| 链路 | 数据源 TCP 连接 | 断开时变红 |

鼠标悬停会把这些合成一句话。需要看门限、RX 门控、AFC 偏移、FERR、采样率、块大小、
噪声底这些原始数值时，按 `Ctrl+D`（或点这四个标签）打开
[运行状态仪表板](#36-运行状态仪表板ctrld)。

### 5.3 调整接收效果

| 现象 | 调整方向 |
|---|---|
| 完全收不到 | 先确认天线、频率 821.2375 MHz、驱动；再看「检测设备」 |
| 偶尔能出报文但乱码多 | 提高「硬件增益」到 20~30 dB；把天线远离电脑 USB3 口 |
| 频偏大（FERR 长期偏） | 调「PPM 校正」（RTL-SDR 常见 0~60 ppm，先试 ±10） |
| 噪声太多、误报多 | 提高「RSSI 打开阈值」3~5 dB，增加「保持时间」 |
| 电脑卡顿 | 频谱切到「终端频谱」，或把采样率降到 960 kS/s / 480 kS/s |
| 长时间无报文 | 确认所在线路的列车是否真的经过；LBJ 功率小，几公里外就收不到 |

> 默认参数（960 kS/s、增益 15.7 dB、PPM 1.0、带宽 35 kHz）在多数城市环境可直接用，
> 非必要不用改。

### 5.4 重复报文合并（为什么同一次广播只留一条）

LBJ 的报文是**广播式**的：同一列车在几秒内往往连发 3~4 帧（甚至更多）内容几乎相同的
报文，以前每一帧都会进列表、进地图、进数据库，看起来像「同一秒同一车次刷了四行」。

v2.1 起在解码出口做了一次**择优合并**：

1. 按「纯数字车次 + 方向」建槽位，同一槽位在一个时间窗内只保留**一条**记录；
2. 每条报文按内容质量打分：详细报文 > 带坐标 > 无 BCH 错 > 线路有效 > 有机车号 >
   有线路名 > 有速度 > 有公里标，信号强度只做很小的加权；
3. 新报文分数**高出 3 分以上**才替换旧记录 —— 这样既能让「后到的详细报文」升级
   先前的短报文，又不会被 RSSI 抖动来回刷；
4. 替换是**就地更新**：同一条记录（同一个 `uid`）原地换内容，列表不新增行、地图不新增
   标记、数据库同一条记录被覆盖更新，不会留下重复历史。

相关的可调项：

| 位置 | 项目 | 默认 | 说明 |
|---|---|---|---|
| 配置 → 解码与界面 | 重复报文合并 | 2.5 秒 | 合并窗口；设为 0 关闭合并（回到 v2.0 的逐帧显示） |
| 运行状态仪表板（`Ctrl+D`） | 解码与去重 | — | `合并丢弃 / 择优升级 / 占用槽位` |

什么时候该改窗口：

| 情况 | 建议 |
|---|---|
| 车多、日志刷得太快 | 保持 2.5 秒，或加到 3~4 秒 |
| 想看清每一帧原始报文 | 设为 0 |
| 移动中的列车想更灵敏 | 降到 1.0~1.5 秒 |

> 合并只影响**展示与入库**，不影响解码本身：被合并的帧同样经过了 BCH 校验和字段解析，
> 只是内容不如留下的那条好，所以被丢弃。

## 6. 经纬度与实时地图

### 6.1 为什么有的车没有经纬度

LBJ 有两类报文：

| 报文 | 地址码 | 含经纬度 |
|---|---|---|
| 基础帧（车次、速度、公里标） | 1234000 / 1233999 | **否** |
| 时间广播 | 1234008 | 否 |
| 扩展长报文（机车、线路、经纬度） | 1234002 / 1234001 | **是** |

所以：

- 只有当列车发出长报文、且与基础帧配对成功（5 秒内），才会得到经纬度；
- 只发基础帧的车次，「经纬度」显示 `----`，也不会出现在地图上；
- 这不是解码错误，是报文本身没有这个信息。

### 6.2 打开地图

1. 申请高德 **Web端(JS API)** Key 与安全密钥（[申请步骤](高德地图配置手册.md#二申请高德-key)）；
2. 「配置 → 地图与车次」页填入 **高德 Key** 与 **安全密钥**；
3. 同一页的 **默认中心** 填一个地名（如 `南昌站`、`向塘站`、`鹰潭东`）——只写地名，
   不用填经纬度，程序启动时调高德**地理编码**把它解析成坐标，再把视图挪过去，
   **不会在图上添加任何标记**；
4. 确定后「实时位置」卡片立即重建，无需重启 DSP。

关于默认中心：

| 情况 | 开机时的地图 |
|---|---|
| 填了地名 + 有网 | 解析成功后居中到该地，缩放级别取「默认缩放」 |
| 填了地名 + 没网 | 用上次解析成功时缓存下来的坐标居中（存在 `lbj_config.json` 的 `mapCenterLng/Lat`） |
| 地名解析不出来 | 停在缓存坐标（没有则全国概览），并在地图中间提示 5 秒 |
| 留空 | 不再像旧版那样强制北京，而是显示**全国概览**，来车后自动跟随 |

> 想换中心点不用重开程序：改完配置点「确定」，视图会立刻挪过去；
> 平时也可以随时按地图卡片上的 **中心** 按钮回来。

不想申请 Key 也能用：地图区域会提示未配置，但解码、列表、历史、ETA 全部正常，
「网页」按钮仍可在系统浏览器里打开位置页。

### 6.3 地图怎么读

| 元素 | 含义 |
|---|---|
| ▲ 蓝色标签 | 上行列车（车次号 + 速度/公里标）；夜间 `#4C8DFF`、日间 `#003DA5` |
| ▼ 红色标签 | 下行列车；夜间 `#F0604F`、日间 `#DA291C` |
| 黄色标签 | 方向未知（尚未解出方向） |
| 折线 | 该车的轨迹（见 [6.4](#64-轨迹是怎么画出来的)） |
| 标签下方的小球 | **真正的坐标点**：10 px 圆点，白色描边 + 方向色内芯，圆点中心严格落在报文经纬度上，标签浮在它上方 |
| 点击标签 | 弹出不透明信息卡片：时间、车次、方向、速度、公里标、线路、机车、类别、轨迹点数与里程、WGS-84 坐标 |
| 拖动/滚轮 | 手动缩放平移。**一动地图就自动暂停「跟随」**（按钮同时取消勾选），所以不会再被下一条报文拉回去 |

**标签会自己避让。** 一条线路上同时有多列车时，标签容易叠在一起看不清。程序每次
`zoomend` / `moveend` 会算一遍所有标记的屏幕坐标，互相冲突（52 px 内）或缩放级别太小
（< 11.6）时，把次要标签降级：

| 状态 | 表现 | 恢复 |
|---|---|---|
| 正常 | 两行：车次 + 速度/公里标 | — |
| 避让（`mini`） | 只留车次一行，字更小 | 放大或车散开后自动恢复 |
| 淡出（`dim`） | 透明度降到 62% | 同上 |

标签按「最后一次报文时间」排序，**最新报文的标签永远在最上层**，不会被旧的盖住。

**信息卡片是实体卡片**，不再是半透明浮层压在底图上：白（或深色）底、圆角、阴影、
底部一个小三角指向标记，右侧有 ✕ 关闭。卡片里的时间截到 `HH:MM:SS`，
方向用箭头徽标，末尾标注「WGS-84 原始坐标 · 底图 GCJ-02 已纠偏」。

卡片按钮：

| 按钮 | 作用 |
|---|---|
| 夜间 / 日间 | 切换地图配色（见 [6.5](#65-夜间--日间模式)） |
| 中心 | 把视野挪回配置里的默认中心（地名解析，不加标记）；同时自动暂停「跟随」，免得刚看就被拉走 |
| 跟随 | 自动把视野移到最新报文位置；关掉后可自由查看 |
| 清除 | 清掉地图上所有标记与轨迹（不影响列表与历史） |
| 网页 | 在系统浏览器/高德 App 中打开最近一列车的位置 |

**关于「跟随」和手动拖动的关系**（v2.3.1 修正）：

- 「跟随」开着时，程序只在**列车位置真的发生变化**（移动超过约 30 米）时才重新居中，
  不再每次刷新都强制把视野拉回去；
- 你一按下鼠标拖动、或用滚轮缩放，程序立刻判定为「手动查看」，
  自动取消「跟随」的勾选并写进配置，日志里会记一条
  `[地图] 检测到手动拖动地图，已暂停自动跟随`；
- 想恢复跟随，点一下 **跟随** 按钮即可，视野会马上回到最新列车。

> 旧版（v2.3.0 及以前）在这里有个缺陷：地图内部每帧都会无条件重新居中，
> 手指还没拖开就被拉回去，表现为「来车之后地图动不了」。v2.3.1 已修正。

### 6.4 轨迹是怎么画出来的

同一列车如果连续发多个详细报文，程序会把它走过的位置连成折线。为了既不丢信息又不撑爆浏览器，
轨迹做了**抽稀**：

| 规则 | 数值 | 说明 |
|---|---|---|
| 记录条件 | 移动 > 6 m **或** 距上一点 > 3 s | 停站时不会堆一坨同心点 |
| 最多保留 | 240 点 | 超出后丢弃最早的（滑动窗口） |
| 折线样式 | 4 px、不透明度 72%，≥3 点才显示方向箭头 | 颜色跟随上/下行 |

信息卡片里那一行「`n 个点 · x.x km`」就是这条轨迹的点数与累计里程（按 111 km/度 估算，
只算平面距离，不含高程）。轨迹也可以关掉：「配置 → 地图与车次 → 显示轨迹」。

> 轨迹是从**本程序开始接收之后**画的，不是列车全程运行图。程序关掉再打开会从零开始。
> 同一个 `uid` 的记录被更优报文替换时，轨迹会接着画而不会重来。

### 6.5 夜间 / 日间模式

地图提供两套高德官方样式：

| 模式 | 高德样式 | 适合 |
|---|---|---|
| 夜间（默认） | `amap://styles/darkblue` 深蓝暗色 | 夜间值守、暗室、与程序整体深色主题一致 |
| 日间 | `amap://styles/normal` 标准浅色 | 白天强光下、投影演示、截图写文档 |

三种切换方式，效果一致：

1. 地图卡片左上角的「夜间 / 日间」按钮（按钮上写的是**目标**模式）；
2. 「视图 → 地图夜间模式」勾选框；
3. 配置窗口「地图与车次 → 地图夜间模式（深色底图）」。

切换是即时的——不重新加载页面，标记与轨迹原样保留。
选择会写进 `lbj_config.json` 的 `mapNight`，下次启动沿用。

> **v2.3.1 说明**：夜间配色优先调用高德的官方样式（`amap://styles/darkblue`）。
> 该样式的「个性化地图」权限**不是每个 Key 都有**，没开通时高德会**静默忽略**
> 这个请求（不报错、也不变色）。程序会读回当前样式做校验，一旦发现没生效，
> 就自动改为给**底图瓦片层**加一层反相滤镜——底图变深、道路与地名仍清晰，
> 而列车标签、轨迹、信息卡片不受影响。所以你换了 Key 也不会突然变回白底。

> 夜间模式下如果觉得标记不够醒目，可把 Windows 显示缩放降一档、或换 115% 界面缩放，
> 标签文字会更大一些。

### 6.6 坐标精度与纠偏

- LBJ 上报的是 **WGS-84** 经纬度，格式为「度 + 分」，程序换算为十进制度；
- 高德底图使用 **GCJ-02**（火星坐标），程序在落点前自动纠偏，
  不纠偏会偏 100~600 米，看起来像「列车跑到路外」；
- 详情窗口与历史库保存的始终是**原始 WGS-84**，方便与其它 GIS 工具对接；
- 定位精度取决于车载卫星定位，开阔地带一般十几米，隧道/站场内可能明显偏离。

## 7. 车次规则

2026 版《列车车次编排规定》改写了部分字母的含义（例如 `T` 从「特快旅客列车」
改为「特快动车组」，`K` 从「快速旅客列车」改为「快速动车组」，`X` 从「行包货物列车」
改为「新时速动车组」），新旧规则会同时存在一段时间。

「配置 → 地图与车次 → 车次规则」提供三种模式：

| 模式 | 行为 | 什么时候用 |
|---|---|---|
| **自动兼容**（默认） | `Z/N/V/B/DH/DJ/Y/G/D/C/S` 按新规则；`T/K/X` 用速度判定：≥200 km/h 按新动车组，<200 按旧特快/快速/行包 | 日常使用，过渡期首选 |
| **2026 新版** | 全部按 2026 规定解释 | 只想看新规则、或确认线路已切换 |
| **2014 旧版** | 全部按旧规定解释 | 研究历史数据、对照旧资料 |

速度也缺失时的兜底：2026-12-25 之前按旧规则，之后按新规则。

具体字母与数字区段的完整对照表见 [技术参考 · 车次分类](技术参考.md#5-车次分类规则)。

> 车次规则只影响「类别」这一列的显示文字，不影响车次号本身和其它字段，切换无需重启。

## 8. 当前列表与历史记录

### 8.1 当前解码

- 只保留最近 **10 分钟** 的记录，自动滚动清理；
- 列：时间、车次、方向、速度、公里标、线路、机车、类别、预计到达；
- 双击任意行打开记录详情；
- 同一列车在同一时刻只占一行：后来的详细报文会**原地替换**该行的内容
  （速度、机车、经纬度等随之更新），不会新增行，见 [5.4](#54-重复报文合并为什么同一次广播只留一条)。

### 8.2 历史记录

- 所有解码结果实时写入程序目录下的 `history.db`（SQLite）；
- 列：时间、车次、方向、速度、公里标、线路、机车、类别、报文、BCD；
- 界面最多显示 **1000** 行，更早的记录仍在库里，可用「导出 CSV」取全量；
- 库里每条记录带一个 `uid`（`车次-方向-时间戳`）。同一 `uid` 被更详细报文替换时，
  程序执行的是**更新**而不是插入，所以历史里不会出现「同一秒同一车次四行」的旧问题；
  收到这类更新后历史页签会在 1.2 秒内自动重载一次。

| 按钮 | 作用 |
|---|---|
| 刷新 | 重新从数据库加载 |
| 清空 | 清空数据库（**不可恢复**，建议先导出） |
| 导出 CSV... | 导出全部历史记录 |

> **升级提示**：从 2.0 升级上来时，程序会在首次启动对旧库做一次自动迁移——
> 补 `uid` 列、按「同车次 + 同一秒」用窗口函数排序去重（保留详细、有坐标、无 BCH 错、
> 信号强的那条），并把数据库版本号写入 `PRAGMA user_version`。
> 迁移只做一次，之后不再重复执行。原始数据未被删除的字段不会丢，但重复行会被清掉，
> 建议升级前先把 `history.db` 备份一份。

### 8.3 CSV 格式

文件为 **UTF-8 with BOM**，Excel 直接双击打开不乱码。共 18 列：

| 列 | 说明 |
|---|---|
| 时间 | `YYYY-MM-DD HH:MM:SS` |
| 车次 | 含前缀字母，如 `K19533` |
| 方向 | 上行 / 下行 / 未知 |
| 速度 | km/h |
| 公里标 | 如 `0123.4` |
| 机车 | 如 `HXD3C-0093` |
| 线路 | 如 `津山线` |
| 类别 | 按当前车次规则算出的中文类别 |
| 报文类型 | `详细`（长报文）/ `短报文` |
| 地址 | 18 位 RIC 地址码 |
| 功能码 | 1=下行，3=上行 |
| BCD | 原始 BCD 字符串 |
| 信号强度 | dB |
| AFC | 自动频率补偿（Hz） |
| FERR | 频偏估计（Hz） |
| 置信度 | 0~1 |
| 经度 | WGS-84 十进制度 |
| 纬度 | WGS-84 十进制度 |

## 10. 到达时间估算（ETA）

程序用「收到的公里标」与「本站公里标」的差值、列车速度与方向，估算到达本站的时间。

计算前提（缺一不可，缺了会显示对应的状态文字）：

| 前提 | 缺失时状态 |
|---|---|
| 记录必须是详细报文（有线路名） | `线路未知` / `线路名无效` |
| 已设置本站公里标（或该线路公里标） | `未设置线路位置` |
| 有车次号 | `等待车次` |
| 方向为上行或下行 | `方向未知` |
| 速度 > 0 | `速度无效` |
| 公里标可解析 | `公里标无效` |

配置项：

| 字段 | 说明 |
|---|---|
| 本站公里标 | 你所在位置的公里标（**关键参数，必须填**）。所有线路默认都用它 |
| 线路公里标 | 可选。多线交汇处按线路名分别设置，如 `津山线=123.4`；设置后优先于默认值 |
| 最大估算时间 | 默认 360 分钟；超过则不显示时间，只给 `ETA过大` |

距离算法（约定**下行公里标递增**）：

```
下行：距离 = 本站公里标 - 列车公里标
上行：距离 = 列车公里标 - 本站公里标
距离 < -0.02 km  →  "远离/已过"（车已经开过去了）
到达时间 = 现在 + 距离 / 速度 × 3600 秒
```

显示位置：列车信息面板的「到达时间」「距离」、当前列表的「预计到达」列、详情窗口。

常见状态：

| 状态 | 含义 |
|---|---|
| `接近` / `即将到达` | 正常估算中（≤10 秒显示「即将到达」） |
| `远离/已过` | 该车正在远离本站，或已经通过 |
| `ETA过大` | 估算超过最大估算时间，通常说明方向判断反了或公里标填错 |
| `错包忽略` | 该记录 BCH 校验失败，不参与估算 |

> 公里标不是 GPS 里程，需要你事先知道自己所在地的铁路公里标（可查线路里程表或问车站）。
> 填错会导致 ETA 完全不对，最典型的症状就是「所有车都在远离」；
> 不确定就留空，程序会显示 `--:--:--`，其它功能不受影响。

## 12. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 启动即提示未找到 `rtl_tcp.exe` | 源码运行且没装工具包 | 把 RTL-SDR 官方 Windows 工具包（或项目自带的 `tools/rtl`）放到程序目录 / `tools/rtl` / `RTL_TCP_Server` 子目录；或在配置里指定路径 |
| `rtl_tcp 启动失败（退出码 1）: No supported devices found.` | 没插棒子 / 驱动不对 | 插好设备；用 Zadig 装 WinUSB；点「检测设备」确认 |
| `rtl_tcp 启动超时（8 秒内端口未就绪）` | 端口被占 / 棒子被别的程序占用 | 关掉 SDR#、OWRX 等占用程序；换端口；重插 |
| ● 未连接，日志反复重连 | 地址端口不对 / 防火墙 | 确认 rtl_tcp 在跑（`telnet 主机 端口`）；放行防火墙 |
| 已连接但一直没有报文 | 频段本身没车 / 天线太差 | 换更好的天线、放到窗外；确认频率 821.2375 MHz |
| 报文时有时无、BCD 乱码 | 信号弱或频偏 | 提高增益、调 PPM、加高 RSSI 阈值 |
| 日志出现「干扰告警」 | BCH 错包率过高 | 属正常偶发；持续出现说明信号被压制或频偏过大 |
| 同一列车只看到一条记录，怀疑漏收 | 正常，已被合并 | 底栏点开仪表板，「解码与去重」里有合并丢弃数；想逐帧看就把「重复报文合并」设为 0 |
| 合并后仍想找回被丢弃的帧 | 合并发生在入库之前 | 关掉合并（0 秒）重启后重新接收；已丢弃的帧不会留档 |
| 界面字太小 / 太大 | 自动缩放不合适 | 「视图 → 界面缩放」选一个固定倍率（85%~150%），重启生效 |
| 界面太暗 / 想用浅色 | 主题是夜间 | 「视图 → 外观主题 → 日间」（或「跟随系统」），重启生效 |
| 切了主题但界面没变 | 主题启动时装载 | 关掉程序重开；「跟随系统」需要系统设置改变后再重启 |
| 看不到频谱 / 信息卡 | 被拖到边上了 | 拖回分隔线（三段都能拖），或「视图 → 显示/隐藏地图」后重排 |
| 底栏右侧标签看不清 | 该项有异常 | 变橙/红就是对应项出了问题，悬停看说明，点开看仪表板 |
| 底栏出现两行一样的话 | 旧版会重复显示告警 | v2.2 已改为日志显示原文、右侧只显示计数 |
| 想看 AFC、FERR、块大小等细节 | 主界面只留关键项 | 按 `Ctrl+D` 打开运行状态仪表板 |
| 地图标签挤成一团 | 车多、缩放太小 | 放大一级；程序会自动把次要标签缩成单行并变淡 |
| 来车后地图拖不动 / 一拖就被拉回 | v2.3.0 及以前的「跟随」实现缺陷 | 升到 v2.3.1：一拖动就自动暂停跟随，不再抢视野；也可手动点掉「跟随」 |
| 标记点位置偏了几十米 | 旧版把标签底边当坐标点 | v2.3.1 起标签下方有白色小球，球心就是报文坐标；仍有偏移请确认底图是否高德 |

## 13. 常见问题 FAQ

**Q：需要联网吗？**
解码不需要。只有「地图瓦片/脚本」「12306 时刻表」「机车图片」需要联网。

**Q：能收多远的车？**
取决于天线与地形。车载 LBJ 功率有限，通常几公里内；高架天线 + 好馈线可到十几公里。

**Q：为什么同一列车一会儿显示 `K19533`，一会儿显示 `19533`？**
基础帧只带纯数字车次，前缀要靠长报文/车次规则补齐。地图用纯数字做标识，
正是为了避免同一列车出现两个标记。

**Q：可以同时接两支 SDR 吗？**
可以，但本程序一次只用一个数据源。多支设备时可在数据源里用「设备序号」切换。

**Q：历史库会无限增长吗？**
会。数据量大时建议定期「导出 CSV → 清空」，或直接用 SQLite 工具归档。

**Q：能在 Linux / 树莓派上跑吗？**
源码可以（`pip install PySide6 PySide6-Addons pyqtgraph numpy scipy`），
但 QtWebEngine 在部分 ARM 发行版上需要额外依赖，缺它时地图会降级为提示面板。

**Q：地图能换百度/天地图吗？**
能。`map_panel.py` 的 HTML 模板是独立的，替换脚本与瓦片源即可，注意坐标系不同
（百度是 BD-09，需要再转一次）。

**Q：为什么 `X` 车的类别会变？**
`X` 在新旧规则里含义完全不同（行包货物列车 vs 新时速动车组），
自动模式按速度判定，所以同一车次在不同速度下可能显示不同类别。要固定就切模式。

**Q：为什么以前一秒出现四五行，现在只有一行？**
v2.1 起做了择优合并，见 [5.4](#54-重复报文合并为什么同一次广播只留一条)。
想回到逐帧显示，把「重复报文合并」设为 0 秒。

**Q：合并会不会丢信息？**
不会。留下的是同一批帧里内容最全的那条（详细报文 > 带坐标 > 无机车号但有线路名……），
而且更详细的帧后到时会替换掉先到的简版，并保留同一 `uid`，所以最终看到的是最优结果。

**Q：日志去哪了？以前底部有一大块日志。**
底部现在只显示最新一条，完整日志在「帮助 → 实时日志」（`Ctrl+L`）里，
自启动以来的输出都在，可以暂停、清空、另存为。

**Q：怎么全屏？**
`F11`、工具栏「全屏」按钮，或「视图 → 全屏」。`Esc` 退出。

**Q：高分辨率屏 / Surface 上字太小怎么办？**
「视图 → 界面缩放」选 115% 或 130%，重启生效。程序默认已按屏幕宽度自动选倍率。

**Q：界面为什么是红蓝配色？**
取自中国铁路视觉识别系统的标准色：CR 红 `#DA291C`（Pantone 485C）为主色，
CR 蓝 `#003DA5`（Pantone 286C）为辅色。想要浅色就切「日间」，
见 [3.7 外观主题](#37-外观主题中国铁路的红与蓝)。

**Q：换到小屏幕要不要手动改缩放？**
不用。启动时会按屏幕宽高自动选一个基准倍率，运行时窗口缩放也会自动调整
分栏比例、字段列数与标题显隐。「视图 → 界面缩放」只是给你一个手动覆盖的手段。

**Q：接收状态、系统状态去哪了？**
精要变成底栏「输出 2」里的四个方块（信号 / AFC / 干扰 / 链路），点一下就是完整的
运行状态仪表板（48 项，已改成分块卡片、异常自动标色）。
v2.3 取消了页签：列车信息在上段右下，车次信息 / 机车信息在中段右侧，频谱在中段左侧，
一屏全看得见。

**Q：仪表板里的数字看不懂？**
每个分组都标了单位，`链路` 怀疑断流、`射频与频谱` 看信号质量、`门控与 AFC` 看频偏、
`解码与去重` 看解出多少帧、`界面` 看当前布局参数。排查问题时点「复制全部」发给别人最省事。

## 14. 术语表

| 术语 | 含义 |
|---|---|
| LBJ | 列车防护报警设备，中国铁路机车车载安全设备 |
| POCSAG | 一种单向寻呼编码，1200 bps，带 BCH 纠错 |
| BCH(31,21) | 纠错码，可纠正 1 位错误 |
| RIC | 寻呼地址码，LBJ 用 1234000 等 |
| BCD | 二进制编码的十进制，LBJ 用特殊字符表示 A~F |
| 公里标 | 铁路线路里程标记，如 K123+400 |
| 上行 / 下行 | 干线通常为「向北京方向 / 背离北京方向」，具体以线路定义为准 |
| WGS-84 | GPS 原始坐标系 |
| GCJ-02 | 国测局加密坐标，高德/腾讯底图使用 |
| rtl_tcp | RTL-SDR 官方的 TCP 转发服务，把 IQ 数据通过网络发送 |
| OWRX | OpenWebRX，网页版 SDR 接收站，提供 rtl_tcp 兼容端口 |
| AFC | 自动频率控制，补偿晶振偏差 |
| ETA | 预计到达时间 |
| uid | v2.1 起每条记录的唯一标识（`车次-方向-时间戳`），用于就地更新同一条记录 |
| 去重窗口 | 同一车次同一方向的报文在这个时间窗内只保留最优一条，默认 2.5 秒 |
