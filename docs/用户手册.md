## 1. 这个程序能做什么

本程序用一支几十元的 RTL-SDR 接收棒，接收中国铁路列车 **LBJ 列车防护报警设备**
在 **821.2375 MHz** 发出的数传信号，实时解码出车次、机车号、线路、公里标、速度和
（部分车次）**经纬度**，并在地图上显示列车位置。

| 能力 | 说明 |
|---|---|
| 实时解码 | 1200 bps POCSAG 编码，BCH(31,21) 单比特纠错 |
| 全字段解析 | 车次、机车号/代号、线路、公里标、方向、速度、经纬度、报文类别 |
| 四种数据源 | 本机 USB 直连（无 TCP）、本机 USB 经 rtl_tcp 中转、局域网 RTL-TCP、OpenWebRX |
| 实时地图 | Leaflet 页面 + **OpenRailwayMap** 铁路图层，底图 11 种可选（免 Key），按方向着色、点击看时间/速度/公里标、支持夜间/日间 |
| 2026 车次规则 | X/G/T/K/D/C/S/Z/N/V/B/DH/DJ 新字头，自动兼容旧车次 |
| 历史留档 | SQLite 本地库（含经纬度），可导出 CSV |
| 车次查询 | RailGo 公开接口取等级 / 担当局 / 客运段 / 配属段 / 车型 / 时刻表 / 开行日 / 交路，失败自动退 12306 官方时刻表 |
| 机车配属查询 | 号段表按「型号 + 号段闭区间」匹配，给出配属单位、制造厂与车型参数；号段表可自动更新 |
| 辅助查询 | 12306 时刻表、机车详情、ETA 到达估算 |
| 择优合并 | 同一次广播的多帧只留最优一条，列表/地图/入库都不重复 |
| 一站式启动 | USB 直连（内附 rtlsdr.dll），装完驱动就能收；直连不通自动退回内附 rtl_tcp |

**它不是**：不是铁路官方设备，不能发报文，不能用于行车；只做被动接收与解码。

### 1.2 桌面端与安卓端的分工

两端共用同一份地图页、同一份号段表、同一套字段语义，但使用场景不同：

| 维度 | 桌面端（Windows） | 安卓端（手机） |
|---|---|---|
| 版本号 | `v3.0.0` | `v3.0.0`（同一个号；规则见 [更新记录](CHANGELOG.md)） |
| 典型场景 | 值班室长时间盯屏、大屏/双屏、历史归档 | 便携随车、现场临时接收 |
| 界面 | Fluent 全景式三段布局，一屏同显 | 六页（地图 / 解码 / 历史 / 状态 / 查询 / 设置）+ 悬浮胶囊导航 |
| 数据源 | 四种全支持 | USB OTG 直连 + 局域网 RTL-TCP / OWRX |
| 历史库 | SQLite（`history.db`），可在电脑上直接用工具查 | Room 数据库，支持按车次 / 按机车分组与多选删除 |
| 数据更新 | 启动后台检查 + 菜单手动触发 | 设置页「数据」组手动检查，启动后台检查 |
| 文档 | 本手册 + [技术参考](技术参考.md) | [安卓构建与环境](安卓构建与环境.md) |

> 两端**配置项同名同义**（如 `mapBase` / `mapRail` / `trainQuerySource`），
> 一套思路可以照搬到另一端；字段清单见 [12.2](#122-v30-新增与变更配置项)。

## 2. 三步开始使用

### 第 1 步：装驱动（一次性）

Windows 下 RTL2832U 默认是 DVB-T 电视棒驱动，必须换成 WinUSB：

1. 插上 RTL-SDR；
2. 打开 [Zadig](https://zadig.akeo.ie/)，`Options → List All Devices`；
3. 选中 `Bulk-In, Interface (Interface 0)`（VID `0BDA` / PID `2838`）；
4. 目标驱动选 **WinUSB**，点 `Replace Driver`。

> 已经用 SDR#、rtl_tcp、OpenWebRX 正常用过这支棒子的，驱动通常已经就绪，可跳过。

### 第 2 步：选数据源

打开程序 →「配置 → 数据源配置」（或 `Ctrl+,` 后切到「数据源配置」页）→ 顶部「数据源」组：

- 插的是本机 USB 棒 → 选 **本机 RTL-SDR (USB 直连)**（默认就是它，直连失败会自动退回中转）；
- 用局域网/本机的 rtl_tcp 服务 → 选 **局域网 / 本地 RTL-TCP** 并填地址端口；
- 连别人的 OpenWebRX → 选 **OWRX** 并填地址端口。

点「检测设备」可确认程序是否认到了棒子。没认到会给出具体原因。

### 第 3 步：开始接收

点菜单栏右侧的「接收」开关。状态栏显示「DSP 运行中」，「● 未连接」变成「● 已连接」，
底栏右侧的状态提示开始显示「信号 -63 dB · AFC 0.06 · 门控 ON」。收到报文后，上段右侧「当前解码」页签出现记录，
地图上出现第一个标记，右下的「列车信息」卡片同时被填满。

> 只发基础帧的车次不会出现在地图上，属正常现象，见 [6.1](#61-为什么有的车没有经纬度)。

> **用安卓端的话**，这三步不一样：不需要 Zadig（手机用 OTG，系统会弹授权），
> 装 APK → 授予 USB 权限 → 点开始。完整步骤（含 SDK/NDK 环境、模拟器验收）
> 见 [安卓构建与环境](安卓构建与环境.md)。

## 3. 界面总览

界面是**全景式三段布局**：上段回答「这一列车在哪、是谁」，
中段是频谱与两张查询卡，底栏两条输出。**没有页签，所有内容同屏可见**。

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ 视图   配置   工具   帮助                        ● 未连接   接收 ──○          │
├──────────────────────────────────────────┬────────────────────────────────────┤
│ [底图▾] [☑铁路] [夜间] [中心] [跟随]     │ [当前解码] [历史记录]              │
│                                          │ 时间 车次 方向 速度 公里标 …       │
│        实时位置（Leaflet 地图）          ├────────────────────────────────────┤
│        铁路图层 = OpenRailwayMap         │ 列车信息                           │
│              约六成宽度                  │ 车次 方向 速度 公里标 机车 线路 …  │
│ [清除] [网页]        右上角 ▾ 图层面板   │                                    │
├────────────────────┬─────────────────────┴──────────────┬─────────────────────┤
│ 接收频谱   [图形▾] │ 车次信息                           │ 机车信息            │
│  ~~~──~──~──       │ 12306 结果 / 查看时刻表            │ 机型 / 牵引参数/配属│
├────────────────────┴────────────────────────────────────┴─────────────────────┤
│ ● 16:04:35 [解码] G1234 下行 82 km/h │ ⚠ AFC 置信度偏低                  │
│                                  │ 信号 -63 dB · AFC 0.06 · 门控 ON        │
└──────────────────────────────────┴────────────────────────────────────────────┘
```

所有分隔线都可以拖动；窗口整体按屏幕大小自适应并居中。
`F11` 全屏、`Ctrl+L` 看完整日志、`Ctrl+D` 开运行状态仪表板、`Ctrl+T` 切换日/夜配色。

### 3.1 顶部：菜单栏即顶栏

顶部只有**一行菜单栏**：左边是菜单，右边是「● 连接状态」和「接收」开关；
不再有单独一行大标题和按钮。

| 元素 | 位置 | 说明 |
|---|---|---|
| 接收开关 | 菜单栏右侧 | 启动 / 停止 DSP 接收；菜单「视图 → 开始/停止接收」（`Ctrl+R`）与之联动 |
| ● 已连接 / ● 未连接 | 接收开关左边 | 数据源连接状态（USB 直连或 TCP 服务） |
| 视图 | 菜单 | 开始/停止接收、全屏（`F11`）、外观主题、切换日/夜（`Ctrl+T`）、地图夜间模式、**铁路图层**、**底图**子菜单、显示/隐藏地图、界面缩放 |
| 配置 | 菜单 | 7 个分页（`Ctrl+,`）：数据源 / 射频 / 到达估算 / 地图与车次 / 解码与界面 / 外观主题 / **数据更新** |
| 工具 | 菜单 | **车次查询**（`Ctrl+F`）、**机车配属查询**（`Ctrl+G`）、**检查数据更新** |
| 帮助 | 菜单 | 使用手册、运行状态仪表板（`Ctrl+D`）、实时日志（`Ctrl+L`）、关于、退出（`Ctrl+Q`） |

> 旧的「文件」菜单已并入：启动/停止归接收开关，「退出」在帮助菜单底部。
> 全屏会隐藏菜单栏，此时 `Ctrl+R` 仍可启停接收，`Esc` 退出全屏。
>
> 「视图 → 铁路图层」与「视图 → 底图」是 v3.0 新增的快捷入口，
> 与地图卡片工具栏、地图页右上角的图层面板**三处双向同步**——
> 在哪一处改都一样，改完立刻写回配置。

### 3.2 上段左：实时位置

Leaflet 地图卡片，约占上段宽度的六成。左上角是工具栏：

| 控件 | 作用 |
|---|---|
| **底图** 下拉 | 11 种底图里选一张（`osm` 默认 / CARTO 浅色·深色·路由 / Esri 卫星·街道 / OpenTopoMap / 天地图矢量·影像 / 高德街道·卫星） |
| **铁路** 勾选框 | 叠加 OpenRailwayMap 铁路图层（勾上 = 用配置里的样式） |
| **夜间 / 日间** | 地图配色切换（按钮上写的是**目标**模式） |
| **中心** | 视野挪回配置里的默认中心，只移动视图、不加任何标记 |
| **跟随** | 自动跟着最新列车走；手动拖动地图会自动取消勾选 |
| **清除** | 清掉地图上的标记与轨迹（不影响列表与历史） |
| **网页** | 用系统浏览器 / 高德 App 打开最近一列车的**位置页**（外部跳转，内部把 WGS-84 转成 GCJ-02，见 [6.6](#66-坐标系与偏移)） |

右上角还有一个**页面内图层面板**（点 ▾ 展开）：底图、铁路样式（standard / maxspeed /
signals / electrified / gauge）、透明度滑块，以及一行状态（当前底图、铁路、
坐标基准、瓦片失败数）。**在页面里改图层与用工具栏改完全等价，而且会写回配置**，
下次启动沿用。图源清单、坐标系与使用条款见 [地图与图源](地图与图源.md)。

「中心」用的是配置里的**默认中心**（预设城市名 + 一对 WGS-84 经纬度），
不再依赖在线地名解析，所以**离线也能居中**。

标记、信息卡片、轨迹的画法与避让规则详见 [第 6 节](#6-经纬度与实时地图)。

### 3.3 上段右：当前解码 / 历史记录 + 列车信息

右列上下两块，中间的分隔线可拖：

| 位置 | 内容 |
|---|---|
| 上（两张表的小页签） | **当前解码**：最近 10 分钟的记录，同一列车只保留最优的一条（就地更新，不刷屏）；**历史记录**：本地 SQLite 库中的全部记录（最多显示 1000 行） |
| 下（列车信息卡片） | 车次 / 方向 / 速度 / 公里标 / 机车 / 线路 / 类别 / 到达时间 / 距离 / 经纬度 / 本站，按可用宽度自动排 2~6 列 |

窗口很矮时，列车信息卡片会自动**收起字段名只留值**（鼠标停在值上仍能看到字段名），
保证 11 个字段不会被裁掉。

表格里**右键**任意一行有三个快捷入口：「记录详情…」「查该车次…」「查该机车配属…」；
后两个会带着该行的车次号 / 机车号直接打开查询对话框，不用手打。

### 3.4 中段：频谱 | 车次信息 | 机车信息

中段三块**并排同屏**，宽度比例约 5 : 3 : 3，分隔线可拖。

| 位置 | 显示什么 |
|---|---|
| 接收频谱（左） | 一条实时功率谱曲线 + RSSI 门限虚线 + 一行摘要（`±480 kHz · 门限 -55 dB · 峰值 -58 dB`），标题栏右侧带「图形 / 终端」下拉 |
| 车次信息（中） | 车次查询结论（RailGo / 12306）+ 「查看时刻表」按钮（左侧结论、右侧按钮） |
| 机车信息（右） | 机型、牵引参数、**配属单位**、简介 + 「机车详情」按钮 |

频谱页左上角那句结论会自动判定为三种之一：

- **有信号**：峰值高于门限且有解调余量，绿色；
- **弱信号**：接近门限，橙色（可微调增益或换天线位置）；
- **静噪**：峰值远低于门限，灰色（该频段暂时没车，属正常）。

> 曲线两端留了内边距、文字按可用宽度省略，所以**任何窗口宽度下频谱都不会撑出边框**；
> 高度随中段自动伸缩，不会出现半截图。
>
> 想看全部细节（AFC、FERR、采样率、块大小、接收字节、运行时长…）？
> 用下一节的**运行状态仪表板**，那里有 48 项。
>
> **频谱模式切换就在频谱卡片的标题栏右侧**（不再占工具栏）：下拉选「图形」或「终端」，
切完立即生效并记住选择。终端模式是字符画，省 CPU/GPU，适合老机器；
它的条形图行数会随卡片高度（2~8 行）、每格重复数随宽度自动伸缩，底部四行状态始终留在可视区。

### 3.5 底栏：输出 1 · 最新日志 ｜ 输出 2 · 一句话状态

底栏是一条**薄底栏**（约占窗口高度的 8%），左右各占一半——底栏就是个底栏，
省下来的高度全给地图。

| 位置 | 内容 | 点击行为 |
|---|---|---|
| 输出 1 · 最新日志（左） | **只显示最新一条**日志，字号比别处大一档，按级别着色（正常灰白 / 告警黄 / 错误红） | 打开实时日志窗口（同 `Ctrl+L`） |
| 输出 2 · 一句话状态（右） | 一句话说清当前状况 + 一行小字读数 | 打开运行状态仪表板（同 `Ctrl+D`） |

放不下时自动加省略号，鼠标悬停能看到完整原文——所以窄窗口也不会把底栏撑破。

**输出 2 说什么。** 它只挑最要紧的一件事讲，多个问题按严重程度取第一个：

| 提示 | 含义 | 建议 |
|---|---|---|
| 接收正常 | 链路通、信号够、AFC 稳、没有持续干扰 | 不用管 |
| 未连接 | 还没点「开始」，或链路断了 | 点「开始」或检查数据源 |
| 链路已断开 | 数据源断了，正在重连 | 看「运行状态仪表板」的重连次数 |
| 信号极弱 / 信号偏弱 | RSSI < -80 dB / < -65 dB | 调增益、换天线位置 |
| AFC 置信度偏低 | 置信度 < 0.10 且门控 ON，说明在硬撑 | 微调频率或 PPM |
| 频偏 +180 Hz | AFC 偏移绝对值 > 200 Hz | 修 PPM 或中心频率 |
| 干扰偏多 7 次 | 近 60 秒有 BCH 错包 | 可能是同频干扰，观察即可 |

下面那行小字固定是 `信号 -63 dB · AFC 0.06 · 门控 ON`，三方对照着看最快。

> **告警只显示一次。** 日志里会出现完整的 `[告警] ⚠ 探测到下行信号 干扰严重`，
> 底栏只留一句结论，不再重复刷屏。

### 3.11 分辨率自适应与界面缩放

**布局自己会调，不用手拖。** 窗口尺寸一变（拖边框、最大化、全屏、换显示器），程序会重算：

| 自适应项 | 规则 |
|---|---|
| 三段高度 | 底栏约 8%（56~88 px，压成一条）、中段约 34%（110~126 px 起）、上段吃掉剩余 |
| 地图最小宽度 | 窗口 < 1100 时降到 260 px，避免把窗口顶宽 |
| 字段列数 | 列车信息按可用宽度排 2~6 列，最后一行不会只剩一列；卡片太矮时自动收起字段名只留值 |
| 标题显隐 | 宽度 < 980 时收起左上角程序名，把空间让给频率与连接状态 |
| 频谱文字 | 图形频谱的说明文字按可用宽度省略，曲线两端留内边距，任何宽度下都不越界 |
| 终端频谱 | 条形图行数按面板高度取 2~8 行、每格横向重复数按宽度取 1~24，底部四行状态始终留在可视区，不出滚动条 |

只在**尺寸档位**变化时重算（宽度每 160 px 一档、高度每 120 px 一档），
同一档位内你拖过的分隔条不会被系统覆盖。

**缩放基准**在启动时按屏幕宽高综合判断（取更紧的一边，基准 1920×1040 ≈ 100%）：

| 屏幕（可用区） | 自动倍率 | 典型设备 |
|---|---|---|
| ≥ 2400×1300 | 1.25 | 2K / 4K 显示器、高分辨率笔记本 |
| ≥ 2110×1140 | 1.15 | 2560×1440 |
| ≥ 1880×1020 | 1.12 | 1920×1080 |
| ≥ 1540×830 | 1.00 | 1600×900 |
| 更小 | 0.92 | 1366×768、1024×600 老机器 |

底栏的「大字」另有一档：小屏 15 px、笔记本 17 px、中屏 19 px、大屏 21 px——
它比正文大一截，站着扫一眼就能看清最新那条。

不满意可在「视图 → 界面缩放」或「配置 → 解码与界面 → 界面缩放」里固定一个倍率
（85% ~ 150%，选「自动」则继续跟随屏幕）。缩放是整体等比缩放——字号、行高、按钮、
分隔条一起变，不只是把字放大。**修改后需重启程序生效。**

> **关于 100%**：老版本把「100%」当默认值写进配置，结果自动缩放等于被关掉，
> 大屏上一直是小字。现在选「100%」等同「自动」——想真的固定小字请选 85%。

另外程序向 Qt 申请了高 DPI 直通（`PassThrough`），Windows 显示缩放设成 125% / 150%
时不会出现界面被系统二次拉伸的模糊感。

## 4. 数据源配置

### 4.1 四种类型

| 类型 | 适用场景 | 需要额外准备 |
|---|---|---|
| **本机 RTL-SDR (USB 直连)** ← 推荐 | 棒子插在这台电脑上 | 只需驱动（Zadig）+ `rtlsdr.dll`（打包版已内附） |
| **本机 RTL-SDR (rtl_tcp 中转)** | 直连不可用时的兼容模式 | 驱动 + `rtl_tcp.exe` |
| **局域网 / 本地 RTL-TCP** | 同网段有 rtl_tcp 服务（树莓派、另一台电脑） | 对方已运行 rtl_tcp |
| **OWRX (OpenWebRX)** | 连公开或自建的 OpenWebRX | 对方开启 rtl_tcp 兼容端口（默认 8073），**DC 偏移设为 0** |

> **直连 vs 中转**：`rtl_tcp.exe` 只是 librtlsdr 的网络外壳，直连就是跳过它，
> 用 Python 直接调 `rtlsdr.dll`。少一个后台进程、少一层本地 TCP，
> 也少一次「端口被占用」的可能。选直连后如果因为 dll 缺失、位数不符、
> 设备被占用等原因打不开，程序会**自动回退**到 rtl_tcp 中转，并在日志里说明原因，
> 不需要你手工切换。

### 4.2 「检测设备」会做什么

点「检测设备」后程序：

1. 用 librtlsdr 枚举设备（`rtlsdr_get_device_count`），列出序号、型号、序列号；
2. 逐个打开读出 **tuner 型号**（R820T / R828D / FC0013 …）和该 tuner 支持的增益表；
3. 按型号给出推荐参数：**960 kS/s、手动增益（R820T 19.7 dB / R828D 15.7 dB）、
   AGC 关、DC 偏移 50 kHz**；
4. 弹窗里点「**应用推荐参数**」即填进当前数据源，并把类型切到 USB 直连。

枚举不到设备时自动改用 `rtl_test -t`，至少告诉你设备在不在。

### 4.3 「rtl_tcp 中转」是怎么工作的

只在选「本机 RTL-SDR (rtl_tcp 中转)」或直连回退时走这条路：

1. 按顺序查找 `rtl_tcp.exe`：程序目录 → `tools/rtl` 子目录 → `rtl` 子目录 →
   `RTL_TCP_Server` 子目录 → 逐级上级目录 → `PATH`；
2. 若配置里填了「rtl_tcp 路径」则优先用它；
3. 检查目标端口是否已有 rtl_tcp 在跑，有就直接复用；
4. 没有就用空闲端口启动：`rtl_tcp -a 127.0.0.1 -p <端口> -f <频率-DC偏移> -s <采样率> -g <增益> -P <ppm> [-d <设备序号>]`；
5. 最多等 8 秒端口就绪，失败会把 rtl_tcp 的原始报错贴到日志；
6. 停止接收时自动结束自己拉起的进程（复用别人起的服务则不动）。

> **一站式启动**：发布包把 `rtl_tcp.exe`、`rtl_test.exe`、`rtlsdr.dll`、
> `msvcr100.dll`、`pthreadVC2.dll` 一起打在 exe 里，运行时解压到临时目录的 `rtl/`，
> 所以装完驱动、插上棒子、点「开始」就能收，**不需要另外装 RTL-SDR 工具包**。
> 源码运行时这几个文件放在项目的 `tools/rtl/` 目录下即可，程序会优先去那里找。

### 4.4 多套数据源

「数据源」组顶部的下拉框是「已保存」列表，可保存任意多套，随时切换。
列表里的短标签：`[USB]` 直连、`[USB*]` rtl_tcp 中转、`[TCP]` 网络 RTL-TCP、`[OWRX]`。

| 按钮 | 作用 |
|---|---|
| 新增 | 新建一套（名称、类型、主机、端口、采样率、增益、PPM、DC 偏移） |
| 编辑 | 修改当前选中那套 |
| 删除 | 删除当前选中那套（至少保留一套） |
| 检测设备 | 枚举本机 RTL-SDR，读 tuner 型号并推荐参数（见 4.2） |

切换数据源属于「必须重连」的改动，点「确定」后程序会自动重启 DSP。

### 4.5 其他数据源相关参数

| 字段 | 默认 | 说明 |
|---|---|---|
| 主机 / 端口 | 127.0.0.1 / 1234 | RTL-TCP 地址；OWRX 一般是 8073。选「本机 USB (直连)」时这两行**自动隐藏**，换成提示文字——设备查找用「检测设备」，多支棒子用「设备序号」 |
| 设备序号 | 0 | 多支 SDR 时选第几支（0 = 第一支） |
| rtl_tcp 路径 | 空 | 留空自动查找；仅中转模式需要 |

## 5. 接收与解码

### 5.1 启动后应该看到什么

| 观察点 | 正常表现 |
|---|---|
| 菜单栏右侧连接指示 | ● 已连接（绿色） |
| 中段「接收频谱」卡片 | 一行结论是「有信号」，曲线有起伏 |
| 底栏右侧「信号」标签 | 有数值，随信号起伏；高于门限时变绿 |
| 底栏右侧「AFC」标签 | 显示 0.xx 的置信度；持续显示「低」说明没锁到信号 |
| 底栏右侧「干扰」标签 | 正常显示「无」；短时间内多次出现说明频段被压制 |
| 底栏右侧「链路」标签 | 「已连」（绿色） |
| 日志 | 无反复重连 |

列车经过时才会有报文。821.2375 MHz 是列车防护报警频段，**车少的路段可能十几分钟没有任何报文**，
这不是程序坏了。

### 5.2 读底栏的四个状态标签

主界面不再单独占一页显示接收状态：**精要都在底栏右侧**，细节在仪表板。

| 标签 | 含义 | 怎么判断 |
|---|---|---|
| 信号 | 当前 RSSI（dB） | 越接近 0 越强；低于 -80 dB 基本收不到 |
| AFC | AFC 锁定质量（0~1） | 低于 0.10 且正在放行时显示「低」；频偏 > ±200 Hz 会显示 Hz 值 |
| 干扰 | 近 60 秒 BCH 错包告警次数 | 偶发 1~2 次正常；持续增长说明信号被压制或频偏过大 |
| 链路 | 数据源连接 | 断开时变红 |

鼠标悬停会把这些合成一句话。需要看门限、RX 门控、AFC 偏移、FERR、采样率、块大小、
噪声底这些原始数值时，按 `Ctrl+D`（或点这四个标签）打开
[运行状态仪表板](#36-运行状态仪表板ctrld)。

### 5.3 调整接收效果

| 现象 | 调整方向 |
|---|---|
| 完全收不到 | 先确认天线、频率 821.2375 MHz、驱动；再看「检测设备」 |
| 偶尔能出报文但乱码多 | 提高「硬件增益」到 20~30 dB；把天线远离电脑 USB3 口 |
| 频偏大（FERR 长期偏） | 调「PPM 校正」（RTL-SDR 常见 0~60 ppm，先试 ±10） |
| 噪声太多、误报多 | 提高「RSSI 打开阈值」3~5 dB，增加「保持时间」 |
| 电脑卡顿 | 频谱切到「终端频谱」，或把采样率降到 960 kS/s / 480 kS/s |
| 长时间无报文 | 确认所在线路的列车是否真的经过；LBJ 功率小，几公里外就收不到 |

> 默认参数（960 kS/s、增益 15.7 dB、PPM 1.0、带宽 35 kHz）在多数城市环境可直接用，
> 非必要不用改。

### 5.4 重复报文合并（为什么同一次广播只留一条）

LBJ 的报文是**广播式**的：同一列车在几秒内往往连发 3~4 帧（甚至更多）内容几乎相同的
报文，以前每一帧都会进列表、进地图、进数据库，看起来像「同一秒同一车次刷了四行」。

v2.1 起在解码出口做了一次**择优合并**：

1. 按「纯数字车次 + 方向」建槽位，同一槽位在一个时间窗内只保留**一条**记录；
2. 每条报文按内容质量打分：详细报文 > 带坐标 > 无 BCH 错 > 线路有效 > 有机车号 >
   有线路名 > 有速度 > 有公里标，信号强度只做很小的加权；
3. 新报文分数**高出 3 分以上**才替换旧记录 —— 这样既能让「后到的详细报文」升级
   先前的短报文，又不会被 RSSI 抖动来回刷；
4. 替换是**就地更新**：同一条记录（同一个 `uid`）原地换内容，列表不新增行、地图不新增
   标记、数据库同一条记录被覆盖更新，不会留下重复历史。

相关的可调项：

| 位置 | 项目 | 默认 | 说明 |
|---|---|---|---|
| 配置 → 解码与界面 | 重复报文合并 | 2.5 秒 | 合并窗口；设为 0 关闭合并（回到 v2.0 的逐帧显示） |
| 运行状态仪表板（`Ctrl+D`） | 解码与去重 | — | `合并丢弃 / 择优升级 / 占用槽位` |

什么时候该改窗口：

| 情况 | 建议 |
|---|---|
| 车多、日志刷得太快 | 保持 2.5 秒，或加到 3~4 秒 |
| 想看清每一帧原始报文 | 设为 0 |
| 移动中的列车想更灵敏 | 降到 1.0~1.5 秒 |

> 合并只影响**展示与入库**，不影响解码本身：被合并的帧同样经过了 BCH 校验和字段解析，
> 只是内容不如留下的那条好，所以被丢弃。

## 6. 经纬度与实时地图

### 6.1 为什么有的车没有经纬度

LBJ 有两类报文：

| 报文 | 地址码 | 含经纬度 |
|---|---|---|
| 基础帧（车次、速度、公里标） | 1234000 / 1233999 | **否** |
| 时间广播 | 1234008 | 否 |
| 扩展长报文（机车、线路、经纬度） | 1234002 / 1234001 | **是** |

所以：

- 只有当列车发出长报文、且与基础帧配对成功（5 秒内），才会得到经纬度；
- 只发基础帧的车次，「经纬度」显示 `----`，也不会出现在地图上；
- 这不是解码错误，是报文本身没有这个信息。

### 6.2 打开地图

地图**不需要任何 Key**，装好就能用。第一次打开建议按三步确认：

1. 「配置 → 地图与车次 → 地图」：选**底图**（默认 `osm` 标准）与**铁路图层样式**
   （默认 `orm_standard`），透明度默认 85%；
2. 同一页的**默认中心**：从预设城市里选一个（列表来自 `shared/data/places.csv`，
   49 个），或者直接填**中心纬度 / 经度**（WGS-84）。预设只改标签，坐标才是真正的中心；
3. 确定后「实时位置」卡片立即重载页面，无需重启 DSP。

两个可选件：

| 可选项 | 什么时候需要 |
|---|---|
| **天地图 tk**（`tdtKey`） | 想用 `tdt_vec` / `tdt_img` 底图时。到 tianditu.gov.cn 申请「浏览器端」tk；没填时选这两张底图只会弹提示、不会加载 |
| 自建 / 离线铁路瓦片 | 国内网络访问不到 OpenRailwayMap 时，见 [地图与图源 · 自建与离线铁路图层](地图与图源.md#5-自建--离线铁路图层国内推荐) |

关于默认中心：

| 情况 | 开机时的地图 |
|---|---|
| 有中心坐标 | 居中到该坐标，缩放取「默认缩放」（默认 11） |
| 只选了预设城市 | 按预设名从 `places.csv` 取坐标；取不到就用全国概览 |
| 坐标与预设都空 | 全国概览，来车后自动跟随 |

> 想换中心点不用重开程序：改完配置点「确定」，视图会立刻挪过去；
> 平时也可以随时按地图卡片上的 **中心** 按钮回来。
> **v3.0 不再有「地名解析」这一步**——中心就是一对 WGS-84 经纬度，所以断网也能居中，
> 也不会出现「重名车站落到别的城市」的问题。

> 旧版高德 Key 配置项**已彻底移除**：v3.0 起地图不再需要任何 Key，配置页里也没有
> 这两行了。老配置文件里残留的 `amapKey` / `amapSecurity` 在加载时被忽略，不会再写回。

### 6.3 地图怎么读

| 元素 | 含义 |
|---|---|
| ▲ 蓝色标签 | 上行列车（车次号 + 速度/公里标）；夜间 `#4C8DFF`、日间 `#003DA5` |
| ▼ 红色标签 | 下行列车；夜间 `#F0604F`、日间 `#DA291C` |
| 黄色标签 | 方向未知（尚未解出方向） |
| 折线 | 该车的轨迹（见 [6.4](#64-轨迹是怎么画出来的)） |
| 标签下方的小球 | **真正的坐标点**：10 px 圆点，白色描边 + 方向色内芯，圆点中心严格落在报文经纬度上，标签浮在它上方 |
| 点击标签 | 弹出不透明信息卡片：时间、车次、方向、速度、公里标、线路、机车、类别、轨迹点数与里程、WGS-84 坐标 |
| 拖动/滚轮 | 手动缩放平移。**一动地图就自动暂停「跟随」**（按钮同时取消勾选），所以不会再被下一条报文拉回去 |

**标签会自己避让。** 一条线路上同时有多列车时，标签容易叠在一起看不清。程序每次
`zoomend` / `moveend` 会算一遍所有标记的屏幕坐标，互相冲突（52 px 内）或缩放级别太小
（< 11.6）时，把次要标签降级：

| 状态 | 表现 | 恢复 |
|---|---|---|
| 正常 | 两行：车次 + 速度/公里标 | — |
| 避让（`mini`） | 只留车次一行，字更小 | 放大或车散开后自动恢复 |
| 淡出（`dim`） | 透明度降到 62% | 同上 |

标签按「最后一次报文时间」排序，**最新报文的标签永远在最上层**，不会被旧的盖住。

**信息卡片是实体卡片**，不是半透明浮层压在底图上：白（或深色）底、圆角、阴影、
底部一个小三角指向标记，右侧有 ✕ 关闭。卡片里的时间截到 `HH:MM:SS`，
方向用箭头徽标，末尾标注当前坐标系状态：WGS-84 底图下写「WGS-84 原始坐标（底图同基准，
无偏移）」，高德底图下写「WGS-84 原始坐标 · 底图 GCJ-02 已加偏」。

卡片按钮：

| 按钮 | 作用 |
|---|---|
| 夜间 / 日间 | 切换地图配色（见 [6.5](#65-夜间--日间模式)） |
| 中心 | 把视野挪回配置里的默认中心（预设坐标，不加标记）；同时自动暂停「跟随」，免得刚看就被拉走 |
| 跟随 | 自动把视野移到最新报文位置；关掉后可自由查看 |
| 清除 | 清掉地图上所有标记与轨迹（不影响列表与历史） |
| 网页 | 在系统浏览器 / 高德 App 中打开最近一列车的位置（外部跳转，见 [6.6](#66-坐标系与偏移)） |

**为什么一拖动就暂停「跟随」**：

- 「跟随」开着时，程序只在**列车位置真的发生变化**（移动超过约 30 米）时才重新居中，
  不是每次刷新都强制把视野拉回去；
- 你一按下鼠标拖动、或用滚轮缩放，程序立刻判定为「手动查看」，
  自动取消「跟随」的勾选并写进配置，日志里会记一条
  `[地图] 检测到手动拖动地图，已暂停自动跟随`；
- 想恢复跟随，点一下 **跟随** 按钮即可，视野会马上回到最新列车。

> 这一行为是可观测的：桌面端每 1.2 秒向页面取一次状态，页面报告「已被用户接管」
> 就把勾选同步回来，所以按钮状态与实际行为不会打架。
> 同类「每帧强制拉回视野」的问题在早期版本出现过，实现细节见
> [技术参考 · 界面层](技术参考.md#9-界面层) 的地图小节。

### 6.4 轨迹是怎么画出来的

同一列车如果连续发多个详细报文，程序会把它走过的位置连成折线。为了既不丢信息又不撑爆浏览器，
轨迹做了**抽稀**：

| 规则 | 数值 | 说明 |
|---|---|---|
| 记录条件 | 移动 > 6 m **或** 距上一点 > 3 s | 停站时不会堆一坨同心点 |
| 最多保留 | 240 点 | 超出后丢弃最早的（滑动窗口） |
| 折线样式 | 4 px、不透明度 72%，≥3 点才显示方向箭头 | 颜色跟随上/下行 |

信息卡片里那一行「`n 个点 · x.x km`」就是这条轨迹的点数与累计里程（按 111 km/度 估算，
只算平面距离，不含高程）。轨迹也可以关掉：「配置 → 地图与车次 → 显示轨迹」。

> 轨迹是从**本程序开始接收之后**画的，不是列车全程运行图。程序关掉再打开会从零开始。
> 同一个 `uid` 的记录被更优报文替换时，轨迹会接着画而不会重来。

### 6.5 夜间 / 日间模式

夜间配色分两级处理，**不是靠某一家地图的私有样式**：

| 情况 | 做法 | 适合 |
|---|---|---|
| 当前底图有深色瓦片（如 `carto_dark`） | 直接换用深色瓦片，不加滤镜 | 夜间值守、暗室，最干净 |
| 当前底图只有浅色瓦片（如 `osm`） | 只给**瓦片层**加反相滤镜（`body.nightfall .lbj-tiles`） | 与程序深色主题一致 |
| 影像类底图（`esri_img` / `tdt_img`） | 标记为「不反相」，夜间只压暗标记与文字 | 卫星影像反相后不可读 |

三种切换方式，效果一致：

1. 地图卡片工具栏的「夜间 / 日间」按钮（按钮上写的是**目标**模式）；
2. 「视图 → 地图夜间模式」勾选框；
3. 配置窗口「地图与车次 → 地图夜间模式」。

切换是即时的——不重新加载页面，标记与轨迹原样保留。
选择会写进 `lbj_config.json` 的 `mapNight`，下次启动沿用；
**切换界面主题（`Ctrl+T`）时也会重新对齐**地图深浅色。

> 夜间模式下如果觉得标记不够醒目，可把 Windows 显示缩放降一档、或换 115% 界面缩放，
> 标签文字会更大一些。

### 6.6 坐标系与偏移

- LBJ 上报的是 **WGS-84** 经纬度，格式为「度 + 分」，程序换算为十进制度；
- 桌面端与安卓端**统一只传 WGS-84 原始坐标**，是否加偏由地图页按**底图基准**自己决定；
- WGS-84 系底图（OSM / CARTO / Esri / OpenTopoMap / 天地图）与铁路图层**零偏移**，
  不需要纠偏；
- 高德底图是 **GCJ-02**，相对 WGS-84 在中国境内典型偏移 **300~500 m**
  （zoom 16 时约 219 px）。所以：
  - 页面会给列车标记与轨迹**自动加偏**，与高德自身对齐；
  - **铁路图层会被自动关闭**——栅格瓦片没法逐块纠偏，硬叠会整体「漂」出去；
    换回 WGS 系底图后自动恢复；
- 详情窗口与历史库保存的始终是**原始 WGS-84**，方便与其它 GIS 工具对接；
- 「网页」按钮走的是高德 URI，那一步会内部把 WGS-84 转成 GCJ-02，**只是外部跳转**，
  与程序内地图无关；
- 定位精度取决于车载卫星定位，开阔地带一般十几米，隧道 / 站场内可能明显偏离。

### 6.7 换图源与二次开发

图源全部登记在 `shared/web/railmap.html` 顶部的 `BASE_SOURCES` / `RAIL_SOURCES` 两张表里，
**改这两张表就等于换图源，桌面端与安卓端同时生效**。做法（改 URL 模板、自建瓦片、
预生成 MBTiles/PMTiles、抽 Overpass 矢量）、坐标系注意点、OpenRailwayMap 的使用条款
都在 [地图与图源](地图与图源.md)：

## 7. 车次规则

2026 版《列车车次编排规定》改写了部分字母的含义（例如 `T` 从「特快旅客列车」
改为「特快动车组」，`K` 从「快速旅客列车」改为「快速动车组」，`X` 从「行包货物列车」
改为「新时速动车组」），新旧规则会同时存在一段时间。

「配置 → 地图与车次 → 车次规则」提供三种模式：

| 模式 | 行为 | 什么时候用 |
|---|---|---|
| **自动兼容**（默认） | `Z/N/V/B/DH/DJ/Y/G/D/C/S` 按新规则；`T/K/X` 用速度判定：≥200 km/h 按新动车组，<200 按旧特快/快速/行包 | 日常使用，过渡期首选 |
| **2026 新版** | 全部按 2026 规定解释 | 只想看新规则、或确认线路已切换 |
| **2014 旧版** | 全部按旧规定解释 | 研究历史数据、对照旧资料 |

速度也缺失时的兜底：2026-12-25 之前按旧规则，之后按新规则。

具体字母与数字区段的完整对照表见 [技术参考 · 车次分类](技术参考.md#5-车次分类规则)。

> 车次规则只影响「类别」这一列的显示文字，不影响车次号本身和其它字段，切换无需重启。

## 8. 当前列表与历史记录

### 8.1 当前解码

- 只保留最近 **10 分钟** 的记录，自动滚动清理；
- 列（10 列，与历史记录完全一致）：时间、车次、方向、速度、公里标、线路、机车、类别、预计到达、报文；
- 双击任意行打开记录详情；右键还有「查该车次…」「查该机车配属…」；
- 同一列车在同一时刻只占一行：后来的详细报文会**原地替换**该行的内容
  （速度、机车、经纬度等随之更新），不会新增行，见 [5.4](#54-重复报文合并为什么同一次广播只留一条)。

### 8.2 历史记录

- 所有解码结果实时写入程序目录下的 `history.db`（SQLite）；
- 列（10 列，与当前解码一致）：时间、车次、方向、速度、公里标、线路、机车、类别、预计到达、报文；
- 界面最多显示 **1000** 行，更早的记录仍在库里，可用「导出 CSV」取全量；
- 库里每条记录带一个 `uid`（`车次-方向-时间戳`）。同一 `uid` 被更详细报文替换时，
  程序执行的是**更新**而不是插入，所以历史里不会出现「同一秒同一车次四行」的旧问题；
  收到这类更新后历史页签会在 1.2 秒内自动重载一次。

| 按钮 | 作用 |
|---|---|
| 刷新 | 重新从数据库加载 |
| 清空 | 清空数据库（**不可恢复**，建议先导出） |
| 导出 CSV... | 导出全部历史记录 |

> **升级提示**：从 2.x 的旧库接着用时，程序会在首次启动对旧库做一次自动迁移——
> 补 `uid` 列、按「同车次 + 同一秒」用窗口函数排序去重（保留详细、有坐标、无 BCH 错、
> 信号强的那条），并把数据库版本号写入 `PRAGMA user_version`。
> 迁移只做一次，之后不再重复执行。原始数据未被删除的字段不会丢，但重复行会被清掉，
> 建议升级前先把 `history.db` 备份一份。

### 8.3 CSV 格式

文件为 **UTF-8 with BOM**，Excel 直接双击打开不乱码。共 18 列：

| 列 | 说明 |
|---|---|
| 时间 | `YYYY-MM-DD HH:MM:SS` |
| 车次 | 含前缀字母，如 `K19533` |
| 方向 | 上行 / 下行 / 未知 |
| 速度 | km/h |
| 公里标 | 如 `0123.4` |
| 机车 | 如 `HXD3C-0093` |
| 线路 | 如 `津山线` |
| 类别 | 按当前车次规则算出的中文类别 |
| 报文类型 | `详细`（长报文）/ `短报文` |
| 地址 | 18 位 RIC 地址码 |
| 功能码 | 1=下行，3=上行 |
| BCD | 原始 BCD 字符串 |
| 信号强度 | dB |
| AFC | 自动频率补偿（Hz） |
| FERR | 频偏估计（Hz） |
| 置信度 | 0~1 |
| 经度 | WGS-84 十进制度 |
| 纬度 | WGS-84 十进制度 |

## 9. 车次与机车配属查询

v3.0 新增。桌面端入口在**工具**菜单，安卓端在底部「查询」页的两个页签：

| 功能 | 桌面入口 | 快捷键 | 安卓 |
|---|---|---|---|
| 车次查询 | 工具 → 车次查询… | `Ctrl+F` | 查询页 · 车次页签 |
| 机车配属查询 | 工具 → 机车配属查询… | `Ctrl+G` | 查询页 · 机车配属页签 |
| 记录行快捷入口 | 表格右键 → 查该车次… / 查该机车配属… | — | 列表项菜单 |

> 两个对话框都是**非模态**的，接收过程中也能开；查询走后台线程，不会卡住解码与界面。

### 9.1 车次查询

输入车次号（如 `G7`、`K19533`、`1462`）回车或点「查询」。数据来源两级：

| 顺序 | 来源 | 能拿到什么 |
|---|---|---|
| 1 | **RailGo** | 列车等级、担当局、客运段、**配属段**、车型、时刻表、开行日、交路 |
| 2 | **12306**（RailGo 失败时自动退） | 官方口径时刻表、列车等级 |

配置项 `trainQuerySource` 可取 `auto`（默认，先 RailGo 再 12306）/ `railgo` / `12306`。
想固定用官方口径就选 `12306`。

结果分四块：

| 区块 | 字段 |
|---|---|
| 顶部 | 车次大字、列车等级、始发 → 终到、始发 / 终到时刻 |
| 信息网格 | 担当局、担当客运段、**配属段**、车型、开行日（数量 + 最近一日）、数据来源 |
| 交路 | 直通 / 管内，以及每段的区间与到发时刻（源没给就整块隐藏） |
| 时刻表 | 序号、站名、到点、发点、停站分钟、里程（`—` = 源未给） |

失败提示都是中文，直接可读：

| 提示 | 含义 | 处置 |
|---|---|---|
| `未查询到车次` | 车次号格式对，但库里没有 | 换车次或换日期；部分临客查不到属正常 |
| `车次号格式不对` | 不含合法车次号 | 去掉空格与中文后缀，字母在前（形如 `^[A-Za-z]{0,2}\d{1,5}$`） |
| `网络不可达` / `请求超时` | 断网、代理问题或对方服务不可用 | 检查网络；RailGo 是个人托管服务，可用性无保证 |
| `数据源返回异常` | 返回非 JSON 或 HTTP 错误 | 稍后重试，或把 `trainQuerySource` 改成 `12306` |

> 免费接口**没有配额保证**：程序只在**你手动点查询**时发请求，不预取、不轮询；
> 失败最多自动换源重试一次，不会循环打。

### 9.2 机车配属查询

输入机车号（`HXD1D-0123`、`HXD3C-0093`、`韶山4-0123`），或只填型号 + 号码，
点「查询」。也可以从**机车信息卡 / 记录详情 / 表格右键**直接带过来，不用手打。

匹配规则（桌面端与安卓端逐字一致）：

1. 先认型号——优先用报文里的 3 位**机车代号**查 `loco_types.csv`（最可靠），
   没有代号就从文本里拆型号，再按「中文名 / 短型号 → 短型号」归一；
2. 号码取数字部分并去前导零（`0123` → `123`）；
3. 在号段表 `loco_roster.csv`（16622 行 / 131 个型号）里找
   **型号精确相等 + 起号 ≤ 号 ≤ 止号（闭区间）**的**第一条**；
4. 别名只有两条：`DF4B`、`DF4R` 都归到 `DF4`（号段表把东风 4B/4R 并进 DF4 统计）。
   **不做前缀回退**：`HXD1D` 绝不会退成 `HXD1`，那是两种车、两个段。

结果里能看到的字段：

| 字段 | 说明 |
|---|---|
| 型号 / 号码 | 归一后的短型号与号码 |
| 配属单位 | 号段表原文（如 `上局沪段`），**不翻译成全称、不改写** |
| 号段 | 命中的区间（起号 ~ 止号） |
| 制造厂 | 号段表里带的备注（有则显示） |
| 车型参数 | 轴式、功率、构造速度、简介（来自 `loco_specs.json`，45 个车型） |
| 数据来源 | 号段表版本与更新日期（见 [12.5](#125-数据自动更新)） |

查不到时三种情况要区分开：

| 提示 | 含义 | 处置 |
|---|---|---|
| `配属未知（号段未收录）` | 型号认识，但这个号不在任何区间里 | 新造车或号段表滞后，属正常；可等数据更新 |
| `型号未收录` | 型号本身不在号段表的 131 个型号里 | 会给开头相同的相近型号提示（最多 4 个），**要你自己确认** |
| `原表未标注配属` | 号段命中但上游数据里配属为空（3 行） | 不猜，原样显示 |

> 号段可能重叠（同型号多条区间都含该号），程序取第一条，并在结果里提示「另有 N 条候选」。
> 配属只覆盖**机车**；动车组的配属看在 [9.1](#91-车次查询) 的「配属段」。

### 9.3 结果怎么用

- 车次结果里的「配属段 / 车型」可以和机车配属卡对照，判断本务机与车次是否匹配；
- 详情窗口的「配属 / 号段 / 车型参数」三行与这里是同一份数据（见 [第 10 章](#10-记录详情与二次查询)）；
- 完整字段语义、数据结构、与参考项目的差异见 [车次与配属查询](车次与配属查询.md)。

## 11. 到达时间估算（ETA）

程序用「收到的公里标」与「本站公里标」的差值、列车速度与方向，估算到达本站的时间。

计算前提（缺一不可，缺了会显示对应的状态文字）：

| 前提 | 缺失时状态 |
|---|---|
| 记录必须是详细报文（有线路名） | `线路未知` / `线路名无效` |
| 已设置本站公里标（或该线路公里标） | `未设置线路位置` |
| 有车次号 | `等待车次` |
| 方向为上行或下行 | `方向未知` |
| 速度 > 0 | `速度无效` |
| 公里标可解析 | `公里标无效` |

配置项：

| 字段 | 说明 |
|---|---|
| 本站公里标 | 你所在位置的公里标（**关键参数，必须填**）。所有线路默认都用它 |
| 线路公里标 | 可选。多线交汇处按线路名分别设置，如 `津山线=123.4`；设置后优先于默认值 |
| 最大估算时间 | 默认 360 分钟；超过则不显示时间，只给 `ETA过大` |

距离算法（约定**下行公里标递增**）：

```
下行：距离 = 本站公里标 - 列车公里标
上行：距离 = 列车公里标 - 本站公里标
距离 < -0.02 km  →  "远离/已过"（车已经开过去了）
到达时间 = 现在 + 距离 / 速度 × 3600 秒
```

显示位置：列车信息面板的「到达时间」「距离」、当前列表的「预计到达」列、详情窗口。

常见状态：

| 状态 | 含义 |
|---|---|
| `接近` / `即将到达` | 正常估算中（≤10 秒显示「即将到达」） |
| `远离/已过` | 该车正在远离本站，或已经通过 |
| `ETA过大` | 估算超过最大估算时间，通常说明方向判断反了或公里标填错 |
| `错包忽略` | 该记录 BCH 校验失败，不参与估算 |

> 公里标不是 GPS 里程，需要你事先知道自己所在地的铁路公里标（可查线路里程表或问车站）。
> 填错会导致 ETA 完全不对，最典型的症状就是「所有车都在远离」；
> 不确定就留空，程序会显示 `--:--:--`，其它功能不受影响。

### 12.5 数据自动更新

配属号段表是**人工维护的静态快照**，新造机车 / 新配属会滞后，所以 v3.0 给它加了自动更新。

**机制。** 内置快照只读，更新写到用户目录，读取时优先用覆盖层：

```
shared/data/loco_roster.csv（内置，随安装包，只读）
        ↑ 回退
%LOCALAPPDATA%\CR-LBJ-Receiver\data\loco_roster.csv（可写，更新写这里）
        ↑ 优先读取
        └─ 更新源：GitCode 镜像（GitHub 国内镜像）
           api.gitcode.com/api/v5/repos/CCCccc233/LBJ_Console/contents/loco_info.csv?ref=resources
```

写入前要过**严格校验**，过不了就丢弃、保留旧文件：

| 校验项 | 阈值 | 防什么 |
|---|---|---|
| 总行数 | ≥ 15000 | HTML 错误页 / 半截响应 |
| 型号数 | ≥ 120 | 字段错位 |
| 含中文的配属行 | ≥ 50 | 编码错乱 |
| 畸形行占比 | ≤ 2% | 字段不足、号段非数字、区间倒置 |

通过后**原子写入**（先写 `.tmp` 再改名），旧文件留 `.bak`，并更新
`data_manifest.json`（sha / 行数 / 型号数 / 抓取时间 / 来源 / 路径）。

**间隔。** 默认**每 7 天**检查一次（`dataUpdateIntervalDays`），
可关掉自动检查（`dataAutoUpdate`）。检查前先比 sha，内容没变就只记一次时间，
不会重复下载。

**手动触发。**

| 端 | 入口 |
|---|---|
| 桌面 | 工具 → **检查数据更新（机车配属表）**；配置窗口第 7 页「数据更新」也能看到当前行数 / 型号数 / 更新时间 / 来源并立即检查 |
| 安卓 | 设置页 →「数据」组 → 立即检查更新 |

**多久检查一次、要不要管它。** 桌面端**启动 20 秒后**在后台检查一次，
失败**只写一行日志、不弹窗**，接收一切照旧。所以正常情况下你不需要管它。

**怎么回退。**

1. 更新会留 `loco_roster.csv.bak`，删掉覆盖层的 `loco_roster.csv`（或把 `.bak` 改回来）
   即可回到上一版；
2. 想彻底回到出厂数据，把 `%LOCALAPPDATA%\CR-LBJ-Receiver\data\` 整个删掉——
   程序会重新读内置快照，功能完全正常，只是数据回退到随包版本。

**离线 / 内网。**

- 完全离线：自动检查失败 → 日志一行「检查更新失败：网络不可达」，其余功能不受影响；
- 内网自建镜像：设环境变量 `CRLBJ_DATA_SOURCE_URL` 指向自己的接口（返回同样的
  `{content: base64(csv), sha}` 结构）即可；
- 便携部署想让数据跟着 U 盘走：设 `CRLBJ_DATA_DIR` 指向 U 盘目录。

> 细节（归一化比对、原子写、manifest 字段、每步失败原因）见
> [车次与配属查询 · 数据自动更新](车次与配属查询.md#4-数据自动更新)。

## 13. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 日志提示「USB 直连不可用…改用 rtl_tcp 中转」 | dll 缺失 / 位数不符 / 设备被占用 | 先看括号里的原因：缺 dll 就补 `tools/rtl/rtlsdr.dll`；被占用就关掉 SDR#、rtl_tcp 等；中转能用就不影响接收 |
| 日志提示「rtlsdr_open(0) 失败，返回 -2」 | WinUSB 驱动没装 | 按 [第 1 步](#第-1-步装驱动一次性) 用 Zadig 装 WinUSB |
| 日志提示「设备已被其他程序占用（返回 -3）」 | 另一个程序正在用这支棒子 | 同一支棒子只能被一个程序独占；关掉占用方（含本程序开的另一个实例） |
| 检测设备能列出型号，但推荐增益不合适 | 不同板子增益表差异 | 弹窗里手改增益后保存；R820T 用 19.7 dB、R828D 用 15.7 dB 起调 |
| 启动即提示未找到 `rtl_tcp.exe` | 源码运行且没装工具包 | 把 RTL-SDR 官方 Windows 工具包（或项目自带的 `tools/rtl`）放到程序目录 / `tools/rtl` / `RTL_TCP_Server` 子目录；或在配置里指定路径 |
| `rtl_tcp 启动失败（退出码 1）: No supported devices found.` | 没插棒子 / 驱动不对 | 插好设备；用 Zadig 装 WinUSB；点「检测设备」确认 |
| `rtl_tcp 启动超时（8 秒内端口未就绪）` | 端口被占 / 棒子被别的程序占用 | 关掉 SDR#、OWRX 等占用程序；换端口；重插 |
| ● 未连接，日志反复重连 | 地址端口不对 / 防火墙 | 确认 rtl_tcp 在跑（`telnet 主机 端口`）；放行防火墙 |
| 已连接但一直没有报文 | 频段本身没车 / 天线太差 | 换更好的天线、放到窗外；确认频率 821.2375 MHz |
| 报文时有时无、BCD 乱码 | 信号弱或频偏 | 提高增益、调 PPM、加高 RSSI 阈值 |
| 日志出现「干扰告警」 | BCH 错包率过高 | 属正常偶发；持续出现说明信号被压制或频偏过大 |
| 同一列车只看到一条记录，怀疑漏收 | 正常，已被合并 | 底栏点开仪表板，「解码与去重」里有合并丢弃数；想逐帧看就把「重复报文合并」设为 0 |
| 合并后仍想找回被丢弃的帧 | 合并发生在入库之前 | 关掉合并（0 秒）重启后重新接收；已丢弃的帧不会留档 |
| 界面字太小 / 太大 | 自动缩放不合适，或配置里锁了 100% | 「视图 → 界面缩放」选一档（85%~150%），重启生效；选「自动」按屏幕定 |
| 界面太暗 / 想用浅色 | 主题是夜间 | 「视图 → 外观主题 → 日间」（或「跟随系统」），重启生效 |
| 切了主题但界面没变 | 主题启动时装载 | 关掉程序重开；「跟随系统」需要系统设置改变后再重启 |
| 看不到频谱 / 信息卡 | 被拖到边上了 | 拖回分隔线（三段都能拖），或「视图 → 显示/隐藏地图」后重排 |
| 底栏右侧标签看不清 | 该项有异常 | 变橙/红就是对应项出了问题，悬停看说明，点开看仪表板 |
| 底栏出现两行一样的话 | 旧版会重复显示告警 | v2.2 已改为日志显示原文、右侧只显示计数 |
| 想看 AFC、FERR、块大小等细节 | 主界面只留关键项 | 按 `Ctrl+D` 打开运行状态仪表板 |
| 地图标签挤成一团 | 车多、缩放太小 | 放大一级；程序会自动把次要标签缩成单行并变淡 |
| 拖动地图后「跟随」自己取消了 | 设计如此：手动查看优先 | 点「跟随」恢复；这样才不会每帧被拉回列车位置 |
| **地图一片灰** | 底图域名不可达（国内访问 OSM 常见）。坐标栏会写「底图不可达，换一张」并变红，不弹窗 | 换 `tdt_vec` / `tdt_img`（先在配置里填天地图 tk）或 `amap`；可达性实测见 [地图与图源](地图与图源.md) 的「中国大陆可达性」一节 |
| **铁路图层开了但没内容** | ① 该地区 OSM 无铁路数据；② 当前是高德底图、图层已被自动关闭；③ 该样式本身稀疏（`signals` / `maxspeed` 在中国普遍缺标注） | 看地图页状态行的「铁路」一项；换 OSM 系底图、换 `orm_standard` 样式再试；`maxspeed` / `signals` 缺数据属正常，不是 bug |
| **切到高德后铁路图层自己关了** | 设计如此：GCJ-02 与 WGS-84 不能混叠（栅格无法逐块纠偏） | 要铁路图层就换回 OSM / CARTO / Esri / 天地图底图，会自动恢复 |
| 标记位置比铁路线偏几百米 | 当前底图是高德（GCJ-02），你在拿它跟 OSM / 卫星影像对比 | 换成 WGS 系底图再对比；高德底图下标记已加偏，与高德自身是对齐的 |
| 想要固定中心 | 默认中心为空或不是你要的位置 | 「配置 → 地图与车次 → 默认中心」选预设城市，或直接填中心纬度 / 经度；也可点地图「中心」按钮 |
| 地图信息窗挡住底图 | — | 右上角 ✕ 关闭；点空白处也会关 |
| 轨迹只有两三个点 | 该车长报文少 | 只有详细报文才更新位置，基础帧不带坐标 |
| 普速车次显示「不提供 12306 时刻表」 | 类别判定 | 看卡片给出的类别：货运 / 单机 / 回送 / 检测等本就没有时刻表；旅客列车类可查 |
| 高分辨率屏上界面发虚 | 系统缩放与程序缩放叠加 | 本版已用高 DPI 直通；若仍发虚，把 Windows 显示缩放改回 100% 或固定界面缩放 |
| 全屏后地图白屏 | 显卡 / WebEngine 重绘慢 | 切换一次「显示/隐藏地图」，或退出全屏再进；必要时切终端频谱降负载 |
| 触屏上滚动条拖不动 / 误选中 | 用的是老版本 | 本版已启用惯性滚动并加宽滚动条与分隔条 |
| 地图配色不合适 | 默认深色 | 点地图卡片「夜间 / 日间」按钮，或「视图 → 地图夜间模式」 |
| 地图页白屏 / 提示缺少地图页面文件 | 打包漏了 `shared/web/`，或 `vendor/leaflet/` 不完整 | 重新打包（spec 已带 `shared` datas）；源码运行时确认 `shared/web/railmap.html` 存在 |
| 日志窗口内容为空 | 刚启动还没输出 | 正常；点开始接收后即有内容 |
| 地图能开但没有标记 | 只收到基础帧 | 正常，等长报文或该车不发长报文 |
| **配属查不到** | ① 号段未收录；② 型号未收录；③ 上游配属为空 | 按提示文字区分：`配属未知（号段未收录）` 等数据更新；`型号未收录` 按给出的相近型号自己确认；`原表未标注配属` 就是原表没写。见 [9.2](#92-机车配属查询) |
| **车次查询失败** | 断网 / 代理 / RailGo 不可用 / 车次不存在 | 按提示处置：`未查询到车次` 换个车次；`数据源返回异常` 稍后重试或把 `trainQuerySource` 改成 `12306`。见 [9.1](#91-车次查询) |
| **数据更新失败** | 网络不可达 / 上游改版 / 校验不通过 | 只影响覆盖层，内置快照照常可用；看日志里的失败原因，或删掉 `%LOCALAPPDATA%\CR-LBJ-Receiver\data\` 回退。见 [12.5](#125-数据自动更新) |
| 经纬度显示 `----` | 该记录没有长报文 | 正常 |
| 导出 CSV 中文乱码 | 用记事本等非 UTF-8 工具打开 | 用 Excel 直接打开（已带 BOM） |
| 首次运行被杀毒软件拦截 | 单文件 EXE 自解压行为 | 加入信任；或改用源码运行 |
| 程序启动要等十几秒 | 单文件 EXE 需解压 Qt 运行库 | 正常；对启动速度敏感可用源码运行 |

## 14. 常见问题 FAQ

**Q：需要联网吗？**
解码不需要。联网只用于四件事：**地图瓦片**、**车次查询**（RailGo / 12306）、
**配属号段表自动更新**，以及 12306 时刻表。机车参数、配属匹配、ETA、历史库全部离线。
断网时地图会停在已缓存的瓦片并提示「底图不可达，换一张」，其它功能照常。

**Q：能收多远的车？**
取决于天线与地形。车载 LBJ 功率有限，通常几公里内；高架天线 + 好馈线可到十几公里。

**Q：为什么同一列车一会儿显示 `K19533`，一会儿显示 `19533`？**
基础帧只带纯数字车次，前缀要靠长报文/车次规则补齐。地图用纯数字做标识，
正是为了避免同一列车出现两个标记。

**Q：可以同时接两支 SDR 吗？**
可以，但本程序一次只用一个数据源。多支设备时可在数据源里用「设备序号」切换。

**Q：历史库会无限增长吗？**
会。数据量大时建议定期「导出 CSV → 清空」，或直接用 SQLite 工具归档。

**Q：能在 Linux / 树莓派上跑吗？**
源码可以（`pip install PySide6 PySide6-Addons pyqtgraph numpy scipy`），
但 QtWebEngine 在部分 ARM 发行版上需要额外依赖，缺它时地图会降级为提示面板。

**Q：地图能换百度 / 天地图吗？**
天地图已经内置（`tdt_vec` / `tdt_img`，填 tk 即可）。想加百度，改
`shared/web/railmap.html` 的 `BASE_SOURCES` 加一条即可——注意百度是 **BD-09**，
要在 `toMap()` 里多转一次，且它同样不能叠 OpenRailwayMap。做法见
[地图与图源](地图与图源.md)。

**Q：为什么地图不再需要高德 Key 了？**
底图换成了免 Key 的 OSM / CARTO / Esri / 天地图（天地图可自愿填 tk），
铁路图层是 OpenRailwayMap。高德只保留两种用法：一种是把 `amap` 当**应急底图**，
一种是「网页」按钮跳转到高德 App / 网页——那一步是外部跳转，程序内部不会加载任何
高德 JS。

**Q：车次查询和配属查询要不要钱？会不会被限流？**
不要钱。车次查询走 RailGo 的公开接口（失败退 12306），配属查询**完全离线**
（读内置号段表）。程序只在**你手动点查询**时发请求，不预取、不轮询，
所以不会被当成抓取流量。

**Q：配属显示「上局沪段」，能翻成「上海铁路局上海机务段」吗？**
不翻。号段表原文就是简称式，翻成全称一旦对不上反而更难查，而且两个端要保持一致。
想要全称可以自己在 `shared/data/loco_roster.csv` 的备注列里加。

**Q：为什么 `X` 车的类别会变？**
`X` 在新旧规则里含义完全不同（行包货物列车 vs 新时速动车组），
自动模式按速度判定，所以同一车次在不同速度下可能显示不同类别。要固定就切模式。

**Q：为什么以前一秒出现四五行，现在只有一行？**
v2.1 起做了择优合并，见 [5.4](#54-重复报文合并为什么同一次广播只留一条)。
想回到逐帧显示，把「重复报文合并」设为 0 秒。

**Q：合并会不会丢信息？**
不会。留下的是同一批帧里内容最全的那条（详细报文 > 带坐标 > 无机车号但有线路名……），
而且更详细的帧后到时会替换掉先到的简版，并保留同一 `uid`，所以最终看到的是最优结果。

**Q：日志去哪了？以前底部有一大块日志。**
底部现在只显示最新一条，完整日志在「帮助 → 实时日志」（`Ctrl+L`）里，
自启动以来的输出都在，可以暂停、清空、另存为。

**Q：怎么全屏？**
`F11` 或「视图 → 全屏」。`Esc` 退出。

**Q：高分辨率屏 / Surface 上字太小怎么办？**
自动倍率按屏幕给（4K 给 1.25、1080p 给 1.12），底栏大字 15~21 px 分档。
若你的配置里 `uiScale` 被老版本写成了 1.0，现在也按「自动」处理，不会再锁死小字。
仍不满意就在「视图 → 界面缩放」里固定一档（85%~150%），重启生效。

**Q：界面为什么是红蓝配色？**
取自中国铁路视觉识别系统的标准色：CR 红 `#DA291C`（Pantone 485C）为主色，
CR 蓝 `#003DA5`（Pantone 286C）为辅色。想要浅色就切「日间」，
见 [3.7 外观主题](#37-外观主题中国铁路的红与蓝)。

**Q：换到小屏幕要不要手动改缩放？**
不用。启动时会按屏幕宽高自动选一个基准倍率，运行时窗口缩放也会自动调整
分栏比例、字段列数与标题显隐。「视图 → 界面缩放」只是给你一个手动覆盖的手段。

**Q：接收状态、系统状态去哪了？**
精要变成底栏「输出 2」里的一句提示（「接收正常」或「AFC 置信度偏低」这种），
点一下就是完整的运行状态仪表板（48 项，已改成分块卡片、异常自动标色）。
界面取消了页签：列车信息在上段右下，车次信息 / 机车信息在中段右侧，频谱在中段左侧，
一屏全看得见。

**Q：桌面端和安卓端的数据会不一样吗？**
不会。两端读的是同一个 `shared/` 目录：同一份地图页、同一份号段表、同一份车型参数、
同一份预设城市。唯一的差别是**自动更新落盘的位置**（桌面在
`%LOCALAPPDATA%\CR-LBJ-Receiver\data\`，安卓在 App 私有目录），
但读取逻辑都是「覆盖层优先、内置快照兜底」，所以数据内容一致。
两端的版本号也一致（本版都是 `v3.0.0`）。

**Q：仪表板里的数字看不懂？**
每个分组都标了单位，`链路` 怀疑断流、`射频与频谱` 看信号质量、`门控与 AFC` 看频偏、
`解码与去重` 看解出多少帧、`界面` 看当前布局参数。排查问题时点「复制全部」发给别人最省事。

## 15. 术语表

| 术语 | 含义 |
|---|---|
| LBJ | 列车防护报警设备，中国铁路机车车载安全设备 |
| POCSAG | 一种单向寻呼编码，1200 bps，带 BCH 纠错 |
| BCH(31,21) | 纠错码，可纠正 1 位错误 |
| RIC | 寻呼地址码，LBJ 用 1234000 等 |
| BCD | 二进制编码的十进制，LBJ 用特殊字符表示 A~F |
| 公里标 | 铁路线路里程标记，如 K123+400 |
| 上行 / 下行 | 干线通常为「向北京方向 / 背离北京方向」，具体以线路定义为准 |
| WGS-84 | GPS 原始坐标系；本程序解码、存储、地图推送全链路都用它 |
| GCJ-02 | 国测局加密坐标，高德 / 腾讯底图使用；高德底图下由地图页自动加偏 |
| rtl_tcp | RTL-SDR 官方的 TCP 转发服务，把 IQ 数据通过网络发送 |
| OWRX | OpenWebRX，网页版 SDR 接收站，提供 rtl_tcp 兼容端口 |
| OpenRailwayMap（ORM） | 基于 OpenStreetMap 的铁路专题瓦片服务，本项目默认铁路图层来源 |
| Leaflet | 开源 JS 地图库（1.9.4），两端共用的地图页基于它，已本地化可离线 |
| 号段表 | 机车配属号段表（`loco_roster.csv`）：型号 + 起止号段 → 配属单位 |
| 配属 | 机车归属的机务段 / 动车所（如 `上局沪段`），按号段表原文显示 |
| 覆盖层 | 自动更新写进用户目录的数据文件；读取时优先于内置快照，可删除回退 |
| RailGo | 第三方公开的车次数据接口，提供等级 / 担当 / 配属段 / 时刻表等 |
| AFC | 自动频率控制，补偿晶振偏差 |
| ETA | 预计到达时间 |
| uid | 每条记录的唯一标识（`车次-方向-时间戳`），用于就地更新同一条记录 |
| 去重窗口 | 同一车次同一方向的报文在这个时间窗内只保留最优一条，默认 2.5 秒 |
