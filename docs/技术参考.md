### 1.2 线程模型

```
┌─────────────────────────────────────────────────────────┐
│ GUI 主线程 (Qt event loop)                              │
│   SpectrumPanel / TrainInfoPanel / MapPanel / 表格       │
└───────────▲─────────────────────────────────────────────┘
            │ Qt Signal（跨线程排队投递）
┌───────────┴─────────────────────────────────────────────┐
│ DspBridge(QThread)  —— cr_lbj/core/bridge.py             │
│   包装 LbjCore，把回调转成 trainDecoded / statusUpdated  │
│   / spectrumUpdated / logMessage / connectionChanged 等  │
└───────────▲─────────────────────────────────────────────┘
            │ 回调（onDecode / onLog / onConnectionChange）
┌───────────┴─────────────────────────────────────────────┐
│ LbjCore —— cr_lbj/core/decoder.py                        │
│   ├─ Source：RtlSdrDirectSource（USB 直连，libusb 回调）  │
│   │        或 RtlTcpSource（TCP 读流线程）               │
│   ├─ FrontendChain：DDC → 抽取 → 鉴频 → AFC → RSSI 门控 │
│   └─ LbjDecoder：比特恢复 → 帧同步 → BCH → 解析         │
└─────────────────────────────────────────────────────────┘
       │ USB 直连：libusb bulk 传输        │ TCP：rtl_tcp 协议
┌──────┴──────────────┐        ┌──────────┴──────────────────┐
│ rtlsdr.dll (librtlsdr)│        │ rtl_tcp.exe（可选中转模式） │
│  ctypes 直调，无子进程│        │ 由程序自动拉起并结束后台   │
└──────────────────────┘        └─────────────────────────────┘
```

要点：

- 解码全部在 `DspBridge` 线程内完成，GUI 只负责渲染；
- 去重发生在 `LbjCore._onDecode()` 里、信号发出**之前**，所以 GUI 与数据库永远不会看到重复帧；
- 地图分两层：`MapHost` 只管"把页面装进来 + 调 JS"，`MapPanel` 管工具栏与数据。
  推送走 `MapHost.update(payload)` → `runJavaScript`，**节流 0.25 秒**；
  反向（页面 → Python）**只有一条路**：`MapPanel` 每 **1200 ms** 轮询一次
  `LBJ.status()`（`JSON.stringify` + `json.loads`），拿回当前底图/铁路/坐标基准/
  跟随锁/瓦片失败数。**不做逐帧回调**，所以页面卡顿不会拖慢解码；
- **坐标一律 WGS-84**：`MapPanel.updateTrain()` 不转换，页面按**当前底图基准**决定如何
  加偏（WGS-84 原样 / GCJ-02 或 BD-09 自动加偏，见 [9.6](#96-地图页与宿主桥)）；
- **v3.2 起车次信息异步查**：`TrainInfoService`（`ui/info_lookup.py`）用
  `TrainInfoWorker(QThread)` 在后台调 `data.train_info.query()`，结果经
  `infoReady(train, info)` 信号回 GUI 线程，再补进地图标记与「车次信息」面板；
  机车配属走本地号段表 `loco_roster.lookup_loco()`（同步、毫秒级）。查询失败静默，
  只少几行信息，不影响解码与地图；
- 日志统一走 `LogBus(QObject)`：保存全量到内存（默认 20000 行），同时用 `lineAdded` 信号
  驱动「底部单条日志」与「日志窗口」，两者互不影响；
- 配置热更新走 `applyHotConfig()`，只更新门控/AFC/ETA/去重窗口等无需重连的参数；
  地图/图层类配置走 `MapPanel.setConfig()` → `MapHost.apply_config()`，同样不重建页面。

### 1.3 一次解码的数据流

```
IQ 块 (blockSize × u8)
  → DC 去除 + IQ 不平衡校正
  → 数字下变频 (DDC，偏移 dcOffsetHz)
  → 半带滤波抽取 960k→240k → 240k→48k
  → 信道 FIR（带宽 bwKhz）
  → FM 鉴频 → 基带 48 kHz
  → 高斯平滑 → DPLL 位同步 → 1200 bps 比特流
  → 帧同步（同步字容错 ≤2 bit）
  → 按 8 码字/批 取 BCH(31,21) 纠错 + 偶校验
  → 地址码 + 功能码 + BCD 字符
  → 报文分类（短帧 / 合并帧 / 独立长帧）→ 会话配对（5 秒窗口）
  → DecodeResult
  → 打上 rssi / afcHz / afcErrHz / afcScore
  → RecordDeduplicator.apply()  ← v2.1：按 (车次,方向) 择优合并，必要时分配 uid
  → onDecode 回调 → GUI（列表就地更新 + 地图 + 卡片）/ history.db（uid upsert）
  → MapPanel.updateTrain()：坐标**原样**（WGS-84）推给页面
  → MapHost.update() → runJavaScript（0.25 s 节流）
  → railmap.html：按底图基准决定是否 wgs2gcj / wgs2bd，再落 marker / trail
```

## 2. 信号处理链

### 2.1 关键常量

| 常量 | 值 | 说明 |
|---|---|---|
| `BAUD_RATE` | 1200 | LBJ 波特率（bps） |
| `BASEBAND_RATE` | 48000 | 基带采样率（Hz），即每比特 40 个采样点 |
| `MID_RATE` | 240000 | 半带滤波后的中间速率 |
| `HW_GAIN_DB` | 15.7 | 默认硬件增益 |
| `PPM` | 1 | 默认晶振校正 |
| `DEFAULT_DC_OFFSET_HZ` | 50000.0 | DDC 偏移，避开零频直流 |
| `DEFAULT_BW_KHZ` | 35.0 | 信道带宽 |
| `DEFAULT_AFC_MAX_HZ` | 8000.0 | AFC 最大修正范围 |
| `DEFAULT_RSSI_THRESHOLD_DB` | -55.0 | 门控打开阈值 |
| `DEFAULT_RSSI_HYST_DB` | 4.0 | 释放迟滞 |
| `DEFAULT_RSSI_HOLD_MS` | 700.0 | 保持时间 |
| `DEFAULT_ETA_MAX_SECONDS` | 21600 | ETA 上限（6 小时） |

### 2.2 频率规划

- 中心频率 821.2375 MHz；
- DDC 把目标信道搬到 `dcOffsetHz`（默认 +50 kHz），避免落在 0 Hz 处被直流与
  1/f 噪声污染；
- 因为整块 IQ 一起抽到 48 kHz 基带，可用带宽约 ±24 kHz，覆盖 35 kHz 信道带宽
  内的主要能量。

> 连 OWRX 时必须把 `dcOffsetHz` 设为 **0**：OWRX 已经把目标信道搬到零频，
> 再偏移会直接把信号推出带宽。

### 2.3 门控与 AFC 的相互作用

1. RSSI 高于 `rssiThresholdDb` 时打开门控，开始喂解码器；
2. 低于 `threshold - hyst` 且持续 `holdMs` 后关闭（迟滞 + 保持，避免抖动丢包）；
3. AFC 在门控打开期间跟踪频偏，补偿上限 `afcMaxHz`；
4. `keepAfcAfterPacket=False` 时，一次报文结束后 AFC 复位，下次重新捕获——
   对间歇性 LBJ 信号更稳。

## 3. POCSAG 帧与 LBJ 报文

### 3.1 POCSAG 基本结构

| 项 | 值 |
|---|---|
| 调制 | 2FSK，1200 bps |
| 同步字 | `0x7CD215D8`（反相 `0x832DEA27`，两者都接受） |
| 空闲字 | `0x7A89C197` |
| 批结构 | 1 个同步字 + 8 个码字（每码字 32 bit） |
| 码字 | 1 bit 标志 + 20 bit 数据 + 10 bit BCH 校验 + 1 bit 偶校验 |
| 地址码容量 | 每帧 8 个地址，按地址低 3 位选帧 |

代码里对应 `LbjDecoder.SYNC_STD / SYNC_INV / IDLE_WORD`，帧同步允许 ≤2 bit 误差
（`popcount32(shiftReg ^ SYNC_STD) <= 2`）。

### 3.2 LBJ 报文类型

| 类型 | 地址码（RIC） | 内容 | 是否含经纬度 |
|---|---|---|---|
| 基础帧 | 1234000、1233999 | 车次、速度、公里标、方向 | 否 |
| 时间广播 | 1234008 | 时间同步 | 否 |
| 扩展长报文 | 1234002、1234001 | 机车、线路、经纬度、尾字段 | **是** |
| 合并报文 | 同上，BCD 长度 ≥65 | 基础帧 + 长报文字段拼接在一帧内 | 是（若含长段） |

判定结果写入 `DecodeResult` 的 `rawIsShort` / `rawIsMerged` / `rawIsStandalone`。

功能码 `rawFunc`：**1 = 下行，3 = 上行**，其它值视为未知方向。

### 3.3 BCD 字符映射

LBJ 的 BCD 段除 0~9 外，用特殊字符表示 10~15。程序内部统一按下列映射换回 hex：

| BCD 字符 | hex |
|---|---|
| `*` | A |
| `U` | B |
| 空格 | C |
| `-` | D |
| `)` | E |
| `(` | F |

（即 `{'*': 'A', 'U': 'B', ' ': 'C', '-': 'D', ')': 'E', '(': 'F'}`）

反过来，写测试数据时用 hex→字符即可。原始字符串保存在 `rawBcd`，详情窗口
「BCD 原始数据」直接显示。

## 4. 长报文与经纬度

### 4.1 字段布局

长报文按 BCD 字符序列（`ih`，0 基）解析，总长 50：

| 切片 | 长度 | 含义 |
|---|---|---|
| `[0:2]` | 2 | 车次前缀（承载 2 个 ASCII 字符，字母前缀 + 补位） |
| `[4:8]` | 4 | 机车型号代号 |
| `[8:12]` | 4 | 机车号 |
| `[12:14]` | 2 | 端位（A/B 端） |
| `[14:30]` | 16 | 线路名（8 字节 GBK 的 hex 展开） |
| `[30:33]` | 3 | 经度：度（3 位） |
| `[33:39]` | 6 | 经度：分（6 位，需 /10000） |
| `[39:41]` | 2 | 纬度：度（2 位） |
| `[41:47]` | 6 | 纬度：分（6 位，需 /10000） |
| `[47:50]` | 3 | 未知尾字段 |

### 4.2 换算与校验

```python
from cr_lbj.core.decoder import parseDmCoordinate

lon = parseDmCoordinate(ih[30:33], ih[33:39], isLatitude=False)
lat = parseDmCoordinate(ih[39:41], ih[41:47], isLatitude=True)
```

`parseDmCoordinate(degText, minText, isLatitude=False)` 的行为：

```python
deg    = int(degText)
minute = int(minText) / 10000.0        # 6 位整数分 → 真实分值
if minute >= 60.0: return None         # 非法分
value  = deg + minute / 60.0           # 度 + 分/60
# 纬度：0 < value <= 60；经度：70 <= value <= 140
return round(value, 6)                 # WGS-84 十进制度
```

范围校验（`70~140°E`、`0~60°N`）同时起到过滤乱码的作用：BCD 误码拼出的
“坐标”几乎必然越界，直接丢弃。

### 4.3 实测样例

输入长报文字符串：

```
204U2390093130U-(2 9U- (-(202011720927939053465000
```

解析结果：

| 字段 | 值 |
|---|---|
| 车次 | `K19533` |
| 机车 | `HXD3C-0093` |
| 线路 | `津山线` |
| 经度 | `117.348798`（117° + 20.9279′ / 60） |
| 纬度 | `39.089108`（39° + 5.3465′ / 60） |

手算校验：`20.9279 / 60 = 0.348798`，`117 + 0.348798 = 117.348798` ✓。

### 4.4 会话配对

长报文本身不含速度、公里标，需要与同一车次的基础帧配对：

- `LbjDecoder.sessions[trainId]` 保存会话，长报文到达时补写 `latitude/longitude`；
- 配对窗口 5 秒，超时则长报文单独成一条记录（`rawIsStandalone=True`，
  `isDetailed=True`，速度/公里标为空）；
- 只有配对成功或独立长帧的记录才有经纬度，`DecodeResult.latitude/longitude`
  为 `None` 时 UI 显示 `----`，地图跳过。

## 5. 车次分类规则

入口（**纯自动、纯日期驱动**，无手动方案选择）：

```python
classifyTrainCategory(trainNo, isDetailed, speed=None, now=None) -> str
```

`now` 为可注入的当前时间（本地时间语义，默认 `datetime.now()`），便于测试拨钟。
分类只由日期决定：

- `now >= 2027-01-01`（`TRAIN_NEW_SCHEME_DATE`）：所有车次（高铁+普速）一律按
  新版编排分类，**不再看速度**；
- `now < 2027-01-01`：过渡期——含义稳定的前缀已按新版；T/K/X 新旧含义冲突
  按速度判定（≥200 km/h 视为新版动车组），速度缺失/无效时一律按旧版兜底。

安卓侧 `TrainClassifier.classify(trainNo, isDetailed, speed, nowMs)` 逐条对应；
切换阈值为**设备本地时区** 2027-01-01 00:00 的 epoch 毫秒
（`LocalDate.of(2027,1,1).atStartOfDay(ZoneId.systemDefault())`，类加载时求值一次）。
旧版「UTC 午夜毫秒常量」近似（时区差 ≤8h）已修正，与桌面本地午夜语义在任何时区严格一致。

### 5.3 判定顺序（纯自动）

```python
# 0) 2027-01-01 起：全量新版（高铁+普速，不看速度）

    return _category2026(prefix, numText) or _categoryNumeric(...)

# ---- 以下为过渡期（2027-01-01 前） ----
# 1) 含义稳定的前缀直接按新版
if prefix in ('Z','N','V','B','DH','DJ','Y','G','D','C','S'):
    return _category2026(prefix, numText)

# 2) 新旧冲突的前缀看速度
if prefix in ('T','K','X'):
    if speed 有效:
        return _category2026(...) if speed >= 200 else _categoryLegacy(...)
    # 速度缺失/无效：过渡期内一律按旧版兜底
    return _categoryLegacy(...)

# 3) 其余按数字车次区段（新版区段表）
return _categoryNumeric(...)
```

`TRAIN_NEW_SCHEME_DATE = datetime(2027, 1, 1)`（本地时间语义）。速度有效范围
0~500 km/h（`_speedValue()`），超出视为无效（等同缺失）。

## 6. 数据源：USB 直连与 rtl_tcp

### 6.1 类关系

```
RtlSdrDirectSource   USB 直连：ctypes 调 librtlsdr（无 TCP、无子进程）
RtlTcpSource         经典 rtl_tcp 客户端（TCP 连接 / 握手 / 命令 / 读流）
  └─ RtlUsbSource    额外负责「自动拉起 rtl_tcp.exe」，其余复用父类实现
RtlUsbAutoSource     门面：先试直连，失败自动换 RtlUsbSource
```

三者对外接口完全一致——`open()` / `read(timeout)` / `close()` / `getDiagnostics()`，
`LbjCore` 的 DSP 主循环对具体实现无感知。诊断统计由
`cr_lbj/core/source_stats.py` 统一计算（`recordBlock()` / `buildDiagnostics()`），
所以仪表板不必按数据源分支。

OWRX 与普通 rtl_tcp 都用 `RtlTcpSource`，`owrxMode` 只影响驱动启动分支与 DC 偏移约定。

`LbjCore._buildChain()` 按 `config.sourceType` 分发：

| `sourceType` | 数据源类 | 说明 |
|---|---|---|
| `rtl_usb` | `RtlUsbAutoSource(RtlSdrDirectSource → RtlUsbSource)` | 默认；直连失败自动回退 |
| `rtl_usb_tcp` | `RtlUsbSource` | 显式使用中转（兼容模式） |
| `rtl_tcp` | `RtlTcpSource` | 局域网/本地 rtl_tcp |
| `owrx` | `RtlTcpSource(owrxMode=True)` | OpenWebRX |

### 6.2 USB 直连要点（v2.6）

**为什么可以直接调 dll**：`rtl_tcp.exe` 是 librtlsdr 的网络前端，而 librtlsdr
自己就是用 libusb 访问 RTL2832U 的。程序随包的 `tools/rtl/rtlsdr.dll` 已经是
完整实现（libusb 静态链接，不需要额外 DLL），用 ctypes 直接调即可，零新增依赖。

**绑定方式**：`ctypes.CDLL` + 显式声明 `argtypes/restype`，只绑 33 个导出函数中
用到的部分：

| 用途 | 函数 |
|---|---|
| 枚举 | `rtlsdr_get_device_count` / `get_device_name` / `get_device_usb_strings` |
| 生命周期 | `rtlsdr_open` / `rtlsdr_close` |
| 射频 | `rtlsdr_set_sample_rate` / `set_center_freq` / `set_freq_correction` / `set_tuner_gain_mode` / `set_tuner_gain` / `set_agc_mode` |
| 探测 | `rtlsdr_get_tuner_type` / `rtlsdr_get_tuner_gains` |
| 取数 | `rtlsdr_reset_buffer` / `rtlsdr_read_async` / `rtlsdr_cancel_async` |

**读取链路**：`rtlsdr_read_async(dev, cb, ctx, buf_num=15, buf_len=blockSize*2)`
在独立线程里阻塞；libusb 每凑满一块就回调 `_onSamples`，回调里只做
`uint8 → complex64` 与 `queue.put_nowait`（队列满计入 `droppedBlocks` 直接丢）。
回调对象必须存成 `self._cb`，否则被 GC 后就是野指针。

**打开即配置**：`open()` 同步完成 `rtlsdr_open` + 全部参数下发，失败立刻抛
`RtlSdrError`，这样 `RtlUsbAutoSource` 能在几百毫秒内决定是否回退。增益会
按设备真实增益表就近取值（先 `get_tuner_gains` 读表，再取最近档）。

**断流恢复**：`read_async` 返回后计一次 `reconnectCount`，关闭设备、等 1 秒、
重开并重新下发参数，循环直到 `close()`。`close()` 先 `cancel_async` 让
`read_async` 返回，再 `join(3s)`，最后才 `rtlsdr_close`（顺序不能反）。

**参数推荐**：`recommendProfile(tunerType)` 按 tuner 型号给值，依据见
[调研报告](调研-USB直连与设备自适应连接.md) §4：

| tuner | 采样率 | 增益 | 备注 |
|---|---|---|---|
| R820T / R820T2 | 960 kS/s | 19.7 dB 手动 | 最常见，实测最稳 |
| R828D | 960 kS/s | 15.7 dB 手动 | 多为 Blog V4，需 Blog fork 版 dll |
| E4000 / FC0012 / FC0013 | 960 kS/s | 19.7 dB（按表就近） | 增益表不同 |
| 未知 | 960 kS/s | 15.7 dB | 保守值 |

全部统一：AGC 关、DC 偏移 50 kHz、块 65536。

### 6.3 rtl_tcp 协议要点

**握手**（服务端 → 客户端，12 字节）：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 4 | `RTL0` |
| 4 | 4 | tuner type（大端 u32） |
| 8 | 4 | tuner gain 个数（大端 u32） |

**命令**（客户端 → 服务端，5 字节）：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 1 | 命令码 |
| 1 | 4 | 参数（大端 u32） |

常用命令码：`1 = SET_FREQ`、`2 = SET_SAMPLE_RATE`、`3 = SET_GAIN_MODE`、
`4 = SET_GAIN`、`5 = SET_FREQ_CORRECTION`、`8 = SET_AGC_MODE`。
数据流是 `u8` 的 I/Q 交织（I、Q 各一字节，无符号，中心 127.5）。

### 6.4 自动拉起 rtl_tcp（中转模式）

`find_rtl_tool(name)` 搜索顺序（v2.1 调整为优先项目内 `tools/rtl`）：

1. 打包态：EXE 所在目录、`_MEIPASS/rtl`（随包内附，由 spec 的 `_RTL_DATAS` 收集）；
2. 源码态：`cr_lbj/core/rtl_paths.py` 所在目录、当前工作目录，以及它们下面的
   `tools/rtl`、`rtl`、`RTL_TCP_Server` 子目录；
3. 上述每个目录的父级最多 6 层，同样检查每层的 `tools/rtl` / `rtl` / `RTL_TCP_Server`；
4. 都没找到则回退 `shutil.which()` 查 `PATH`。

`runtime_dirs()`（`cr_lbj/core/rtl_paths.py`）就是这套顺序的唯一实现：
`rtl_tcp` / `rtl_test` 用 `find_rtl_tool()`，`rtlsdr.dll` 用 `findRtlsdrDll()`，
三者共用同一套目录回溯，所以源码运行时只要把官方工具包解压到项目根的
`tools/rtl/` 即可，无需配置路径。

`RtlUsbSource.open()` 流程：

```python
if not _port_open(host, port):        # 已有服务就复用
    port = _free_port(port)           # 否则找空闲端口
    _spawn(port)                      # 启动 rtl_tcp，最多等 8 秒
```

实际命令行：

```
rtl_tcp.exe -a 127.0.0.1 -p <port> -f <频率Hz - dcOffsetHz> -s <采样率> \
            -g <增益> [-P <ppm>] [-d <设备序号>]
```

注意 `-g` 传入的是**浮点 dB 值**（rtl_tcp 内部 `atof(x)*10`，等于 0.1 dB 单位），
`-f` 传的是 `目标频率 - DDC 偏移` 的整数 Hz。

`close()` 只结束自己拉起的进程（`_spawned` 标志），复用别人的服务时不动它。

设备检测 `detect_rtl_devices()` 跑 `rtl_test -t`（直连枚举失败时的兜底），判定逻辑：

```python
ok = re.search(r'found\s+\d+\s+device', low) or 'sn:' in low
if 'no supported devices' in low or 'no devices found' in low:
    ok = False
```

（早期版本用 `'found' in low and 'device' in low` 判断，
被 `No supported devices found.` 骗过，已修正。）

### 7.4 历史库

表结构与 `DecodeResult` 一一对应，共 33 列（v2.1 新增 `uid TEXT`）。

写入改为 **`INSERT ... ON CONFLICT(uid) DO UPDATE`** 语义（由 `_values()` 与
`_INSERT_COLS` 统一维护列顺序）：

| 返回值 | 触发条件 | GUI 行为 |
|---|---|---|
| `inserted` | 新 `uid` | 列表新增一行；历史页签标记待刷新 |
| `updated` | 已存在同 `uid` | 列表就地替换该行；历史页签 1.2 秒后自动重载 |
| `failed` | 异常/空记录 | 写入日志 |

`uid` 为空的历史行（2.0 遗留）不会参与冲突更新，只按普通插入处理。

**v2.1 迁移**（`HistoryDb._migrateV21()`，只在 `PRAGMA user_version < 1` 时执行一次）：

1. `ALTER TABLE history ADD COLUMN uid TEXT`（`PRAGMA table_info` 判重，幂等）；
2. 建索引 `idx_uid`；
3. 用窗口函数删除历史重复行：

```sql
DELETE FROM history WHERE id IN (
  SELECT id FROM (
    SELECT id,
           ROW_NUMBER() OVER (
             PARTITION BY train, substr(timeStr, 1, 19)
             ORDER BY isDetailed DESC, (latitude IS NOT NULL) DESC,
                      msgTypeError ASC, rssi DESC, id ASC
           ) AS rn
    FROM history
  ) WHERE rn > 1
)
```

4. `PRAGMA user_version = 1`，并在 `lastMigrated` 记录本次清理的行数（写进日志）。

排序键与 `RecordDeduplicator.quality()` 保持同序，保证「在线合并」与「离线补迁移」
留下的是同一条最优记录。实测一个 274 行的 2.0 库迁移后剩 175 行（清理 99 行），
同车次同秒重复组从 60 组降为 0。

CSV 导出 18 列，UTF-8 with BOM，导出的是迁移后的干净数据。

## 8. 重复报文合并

### 8.1 为什么需要

LBJ 是广播式数传：同一列车在 2~3 秒内常连发 3~4 帧，内容高度重叠（只有 RSSI 不同），
偶尔夹一帧信息更全的长报文。逐帧入库会造成三个问题：

1. 列表刷屏，看不清「最新一列车在哪」；
2. 地图上同一标记被反复重建；
3. 历史库膨胀且难以人工阅读。

### 8.2 `RecordDeduplicator`

```python
class RecordDeduplicator:
    def __init__(self, window=2.5, maxSlots=256): ...
    @staticmethod
    def keyOf(d) -> str:      # f'{baseTrain}|{direction}'
    @staticmethod
    def quality(d) -> float:  # 内容质量打分
    def apply(self, d) -> Optional[DecodeResult]   # None = 被丢弃
```

`quality()` 的权重（同一量纲，越大越好）：

| 项 | 分值 | 理由 |
|---|---|---|
| `isDetailed`（长报文） | +100 | 信息量最大，必须优先 |
| `latitude` 非空 | +40 | 有坐标才能上地图 |
| `not msgTypeError` | +20 | BCH/格式无误 |
| `routeValid` | +10 | 线路名可信 |
| `loco` 非空 | +15 | 能显示机车 |
| `route` 非空 | +10 | 能算 ETA |
| `speed` 非空 | +5 | |
| `position` 非空 | +5 | |
| `rssi` 归一化 | 0~1 | 只做微调，防止信号抖动主导 |

### 8.3 合并规则

```python
now  = d.timestamp
slot = self._slots.get(key)                     # 过期槽位直接丢弃
if slot is None:                                # 首帧：分配新 uid
    d.uid = f'{key.replace("|", "-")}-{now:.3f}'
else:
    if quality(d) > slot['score'] + 3.0:        # 明显更优才替换
        d.uid = slot['uid']                     # 复用 uid → 就地更新
        slot['score'] = quality(d); upgraded += 1
    else:
        return None                             # 合并掉
```

三个关键设计：

- **+3.0 门限**：单纯 RSSI 抖动（0~1 分）不会触发替换，避免同一行反复刷新；
- **uid 复用**：替帧沿用首帧的 `uid`，于是列表「原地换内容」、SQLite「更新同一行」、
  地图「同一标记刷新」，三处都不产生重复；
- **`window <= 0` 关闭**：此时每帧都分配新 `uid`，行为退化为 v2.0 的逐帧记录。

槽位用 `maxSlots` 限制（默认 256），`_prune()` 按时间戳清理过期项，长时间运行不会积累。

### 8.4 观测与调参

- 运行状态仪表板（`Ctrl+D`）的「解码与去重」组显示 `dropped / upgraded / slots`；
- 配置窗口「解码与界面 → 重复报文合并」调整窗口（0~10 秒）；
- 窗口调大对高频重复更有效，但列车快速移动时可能把不同位置的两帧误合并；
  2.5 秒是实测 1200 bps 广播节奏下的折中值。

### 9.2 全局缩放：`UI_SCALE` / `spx()` / `scale_qss()`

```python
UI_SCALE = 1.0
def spx(v):            return max(1, int(round(float(v) * UI_SCALE)))
def scale_qss(text):   # 正则替换 QSS 中的 (\d+)px → spx(n)
def autoUiScale(app):  # min(宽/1920, 高/1040) → 0.92 / 1.00 / 1.12 / 1.15 / 1.25

```

- 代码里所有像素值都写 `spx(N)`，不再出现裸数字；
- 样式表在 `main()` 里一次性 `scale_qss(TH.styleSheet()) + scale_qss(TOUCH_STYLE)`
  （v2.2 起 `DARK_STYLE` 常量已删除，配色全部来自 `cr_lbj/ui/theme.py`）；
- `autoUiScale()` 取**宽高两个比例的较小值**（基准 1920×1040），且不乘系统 DPI ——
  否则会与 Qt6 的高 DPI 缩放叠加，在高分屏上放大两次；
- 布局自适应（分栏比例、字段列数）另由 `_applyResponsive()` + `FieldGrid` 负责，
  与这里的字号缩放解耦：小屏不一定缩小字号，但一定会重排布局；
- 「视图 → 界面缩放」写入 `config.uiScale` 并提示重启（样式表和 `spx` 在启动时定型，
  运行时改动会半新半旧，不如重启干净）；
- `resolveUiScale()`（v2.4）把 `uiScale <= 0` **和 `== 1.0`** 都当成「自动」：
  老版本把 100% 当默认值写进配置，等于永久关掉自动缩放，大屏上一直是小字。

### 9.2.1 外观层 `cr_lbj/ui/widgets.py`（Fluent Design）

**不自造轮子。** 控件全部来自现成库 [qfluentwidgets](https://github.com/zhiyiYo/PyQt-Fluent-Widgets)
（PyPI 包名 `PySide6-Fluent-Widgets`，导入名 `qfluentwidgets`，作者 zhiyiYo，GPLv3，与本项目同许可）。
`cr_lbj/ui/widgets.py` 只做四件事：

| 职责 | 做法 |
|---|---|
| 初始化 | `setThemeColor(CR 红)`、`setFontFamilies(微软雅黑 → Segoe UI)`、基础字号 |
| 短名字 | `button() / combo() / line_edit() / check() / spin() / table() / label()`，换库只改这一个文件 |
| 签名兼容 | 见下表的两个薄子类，让 5000 行旧界面代码零改动 |
| 缺库降级 | `import qfluentwidgets` 失败时全部退回原生 Qt，程序照常运行 |

**签名兼容（关键）。** qfluentwidgets 的构造函数比 Qt 窄，项目里又有大量老写法，
所以用两个极薄的子类补齐签名，**不改任何调用点**，样式仍全部来自库：

```python
class ComboBox(qfluentwidgets.ComboBox):
    def addItem(self, text, userData=None, icon=None):      # 老写法 addItem('自动', 'auto')
        super().addItem(str(text), icon=icon, userData=userData)

class TableWidget(qfluentwidgets.TableWidget):
    def __init__(self, rows=0, cols=0, parent=None):        # 老写法 QTableWidget(0, 9)
        super().__init__(parent)
        if rows: self.setRowCount(rows)
        if cols: self.setColumnCount(cols)
        applyTablePalette(self)
```

主程序里用名字别名一次性接管：`QPushButton = K.PushButton`、`QComboBox = K.ComboBox`、
`QTableWidget = K.TableWidget` …… 31 个按钮、9 个下拉、3 张表零改动迁完。

**三个必须知道的坑。**

1. **Fluent 的字号不吃应用级 QSS。** 它在构造时用 `QWidget.setFont()` 定 14 px，
   之后 `scale_qss()` 改不到它。`ui_kit.installFontScaler(app)` 挂了个应用级事件过滤器，
   在控件第一次 `Show` 时按 `_SCALE` 放大一次，原值记在 `_uiBasePx` 属性里，
   重复触发不会叠加。dialogs 在运行时新建也能覆盖到。
2. **表格会变白。** 库给表格自己的样式是 `QTableView { background: transparent; }`，
   想让卡片色透上来；但 `QAbstractScrollArea` 的 viewport 会退回 `QPalette.Base`，
   浅色系统调色板下就是纯白，深色界面上白得刺眼。而且这条在**控件自带的**样式表里，
   优先级高于应用 QSS，光改 `cr_lbj/ui/theme.py` 覆盖不掉。`applyTablePalette()` 的解法是：
   设 `QPalette.Base/AlternateBase` 兜底 + 在控件样式表**末尾追加**一条规则（后者优先）。
3. **卡片会变白。** `SimpleCardWidget` 只画「白色 + 13/170 透明度」，深浅靠父层透上来。
   `CardBox.paintEvent()` 先用主题色铺实，再让 Fluent 的描边叠上去。

**降级验证**（模拟没装库）：

```python

```

### 9.5 主题系统（`cr_lbj/ui/theme.py`）

关键设计：

| 决策 | 理由 |
|---|---|
| 调色板是 `dict` + `string.Template` 的 `$name` 占位 | 不用 `str.format`，避免 QSS 里的 `{}` 要写双大括号 |
| `applyMode()` 可在运行期反复调用（v2.3） | 见下面「即时换肤」：全局 QSS 重设 + 内联颜色按映射表替换，pyqtgraph 与地图各自 refresh |
| `auto` 走 `QGuiApplication.styleHints().colorScheme()` | Qt6.5+ 才有；取不到时退回 `dark` |
| `mapColors()` 单独出口 | 地图页面是 HTML/JS，需要的是具体 hex，而不是 QSS |
| `c()` 一律带 fallback | 某键缺失时不会抛异常，界面不至于整块变黑 |

调用方两种写法：

```python
from theme import c as CLR
label.setStyleSheet(f'color: {CLR("accent")};')      # f-string 内
label.setStyleSheet('color: {};'.format(CLR('dim')))  # 普通字符串（注意转义）
```

**即时换肤（v2.3）** —— 点「日间 / 夜间」不再需要重启，`MainWindow._applyThemeLive()` 干四件事：

1. 换全局样式表：`QApplication.setStyleSheet(theme.styleSheet())`；
2. **内联颜色按映射表替换**：界面里几百处 `setStyleSheet(f'color: {CLR("accent")}')`
   在创建时就把 hex 写死了，光换全局 QSS 改不到。这里用两套调色板的同名键
   生成 `{旧 hex: 新 hex}`，再对每个控件（`QApplication.allWidgets()`，含独立对话框）
   做**一次正则扫描**替换：

   ```python
   pat = re.compile('|'.join(re.escape(k) for k in pairs), re.I)   # 单次扫描
   new = pat.sub(lambda m: pairs[m.group(0).lower()], old_style)
   ```

   必须是单次扫描：分多次 `str.replace` 会出现 A→B、B→C 的连环替换，
   换一次主题颜色就“串”了；
3. 重设 pyqtgraph：`applyPgTheme()` + `SpectrumPanel.applyTheme()`（画笔、填充、门限线）
   + `TerminalSpectrumPanel.applyTheme()`（字符画颜色是类属性，要重新赋值并重画）；
4. 地图与日志页重建：`MapPanel.applyTheme()` 重建 `setHtml`（颜色注入在 HTML 里），
   `LogTail.relayout()` 重拼 HTML。

实测一次切换约 30 ms（1440×900，含 pyqtgraph 重绘），界面无闪烁。

> `theme` 字段存在 `CoreConfig` 里（`dark` / `light` / `auto`），
> 改完提示重启——`main()` 里 `TH.applyMode(config.theme)` → `applyPgTheme()` →
> `app.setStyleSheet(scale_qss(TH.styleSheet()) + scale_qss(TOUCH_STYLE))` 三步定型。

### 9.6 地图页与宿主桥

v3.1 把地图拆成三层，**页面本身两端共用**（渲染引擎 Leaflet 1.9.4，底图 7 张）；
v3.2 在此基础上给页面加了**分层瓦片统计**、**ORM Referer 适配**与**车次/机车信息展示**：

```
shared/web/railmap.html     纯前端，Leaflet + 图源登记表 + LBJ.* JS API + 离线缓存
        ▲ setHtml(html, baseUrl=shared/web/)          │ runJavaScript
        │                                             ▼
cr_lbj/ui/map_host.py  MapHost：装载 / 配置注入 / JS 桥 / Referer 拦截 / JSON 状态查询
```

#### 1. 页面结构（`shared/web/railmap.html`）

单文件、零构建，脚本只引用同目录 `vendor/leaflet/leaflet.js`（**已本地化，无 CDN**）。

| 段落 | 内容 |
|---|---|
| `BASE_SOURCES` | 底图登记表（**7 张**）：`{name, coord: 'wgs'\|'gcj'\|'bd', maxNativeZoom, url, subdomains?, noInvert?}`；默认 `amap` |
| `RAIL_SOURCES` | 铁路图层登记表：`off` + 5 个 OpenRailwayMap 样式，坐标恒为 WGS-84 |
| `DEFAULT_CONFIG` / `INJECTED` | 页面缺省配置 / 宿主注入点；含 `cacheEnabled` / `cacheZoomDelta` / `tdtKey` |
| pane 分层 | 底图（默认 pane）< `railPane` z=**300** < `trailPane` z=**410** < `markerPane` z=**620** |
| `wgs2gcj()` / `gcj2bd()` / `wgs2bd()` | GCJ-02 / BD-09 偏移算法（含 `outOfChina()` / `tLat()` / `tLng()`） |
| `ll2mc()` / `mc2ll()` + `L_BAIDU_CRS` | 百度自有墨卡托投影（官方换算系数），`BaiduTileLayer` 做百度瓦片编号换算 |
| `toMap(lat, lng)` | **唯一的坐标出口**：按 `coordMode()` 返回 `wgs` / `gcj` / `bd` 对应坐标 |
| `fromMap(lat, lng)` | 反算回 WGS-84（`LBJ.center()` / `status().center` 用） |
| `tileHooks(layer, kind)` / `warnRailFail()` | **v3.2**：瓦片事件按 `'base'` / `'rail'` 分别累计；铁路失败 ≥ 4 张只 toast 一次，不影响底图判定 |
| `infoRows(d)` / `markerSub(d)` | **v3.2**：从 `d.info` 生成点击弹窗四行（车次信息 / 车底 / 区间 / 机车配属）与标记副标题里的车次等级 |
| `#panel` | 页面右上角图层面板（`z-index: 500`）：底图 / 铁路样式 / 透明度 / 缓存按钮 / 状态行 |

几个必须记住的点：

- **底图分三类坐标系**：`wgs`（OSM / 天地图，零偏移）、`gcj`（高德，标准墨卡托 + `wgs2gcj`）、
  `bd`（百度，`L_BAIDU_CRS` 自定义 CRS + `BaiduTileLayer`）。高德 ↔ OSM 只换瓦片层；
  **标准墨卡托 ↔ 百度墨卡托要重建地图实例**（`createMap()`，保存 WGS-84 中心与 zoom 后重画标记）；
- **底图与铁路图层的坐标系必须一致**。`setBase()` 切到 `coord != 'wgs'` 的底图时，
  会把 `railId` 置 `'off'`、记住用户想要的样式（`railWanted`）、置 `railAutoOff = true`
  并弹提示「铁路图层已暂停」。`notifyHost()` 此时上报 `railWanted` 而不是 `off`，
  避免宿主把「自动暂停」误当成用户选择关闭。切回 WGS 底图时若 `railAutoOff` 为真则恢复
  `railWanted`，否则沿用 `railUserOff` / `CONFIG.rail` 的原有恢复逻辑；
- `applyConfig()` 的顺序是「**先定底图，再定铁路**」，否则「先开 ORM 再切高德」
  会弹两次「无法叠加」；
- 夜间兜底是 CSS 滤镜，作用域限定瓦片层；`noInvert: true` 的底图
  （高德卫星 `amap_img` / 百度卫星 `baidu_sat` / 天地图影像 `tdt_img`）跳过反相；
- **瓦片计数分图层（v3.2）**：`tileHooks(layer, kind)` 把 `tileload` / `tileerror` 分别记到
  `baseTileOk` / `baseTileFail`（底图）与 `railTileOk` / `railTileFail`（铁路）。旧名
  `tilesTotal()` / `tilesFailed()` 保留但**只返回底图**计数，`LBJ.status()` 里
  `tilesTotal` / `tilesFailed` 只含底图，另带 `railTilesTotal` / `railTilesFailed`；
- **底图不可达判定（v3.2）**：页面全屏提示条件是 `baseTileFail >= 6` 且
  （`baseTileOk === 0` 或 `baseTileFail >= baseTileOk * 19`，即失败率 ≥ 95%）；
  铁路瓦片失败只走 `warnRailFail()` 的一行 toast 与状态行「铁路 N/失败 M」，
  **绝不参与底图判定**。桌面坐标栏的红色提示仍在 `MapPanel._onStatusPoll()` 里按
  `failed > 8` 且（`total == 0` 或 `failed >= total * 0.9`）判定（`_TILE_FAIL_HINT = 8`），
  但输入已是纯底图统计；
- **ORM Referer（v3.2）**：ORM 官方瓦片要求 `Referer: https://www.openrailwaymap.org/`
  （只带 UA 仍 403），由**宿主**在请求层补，页面只设 `crossOrigin: false`、不改 Referer；
  桌面见 `MapHost._TdtRefererInterceptor.ORM_REFERER`，安卓见
  `TileCache.refererFor()`（细节见 [地图与图源 · §3.5](地图与图源.md#35-为什么必须带-refererv32-关键修复)）；
- 天地图 tk 用 `{key}` 占位，由 `buildBase()` / `tileUrlFor()` 用 `CONFIG.tdtKey` 替换；
  **页面不硬编码任何 tk**。

#### 1.5 离线缓存（页面侧）

- `cacheArea()`：取当前视野 z0=当前级、z1=min(z0+`cacheZoomDelta`, 18)，逐级算瓦片 URL
  （百度做编号换算、天地图替换 tk）；单级超过 40×40 张时跳过该级。
  宿主实现了 `LBJHost.cacheArea` → 交宿主代拉落盘；否则 `prefetchLocal()` 用 `new Image()`
  4 路并发预取（进浏览器 HTTP 缓存）。
- `LBJ.onCacheProgress(done,total)` / `LBJ.cacheStats(json)`：宿主回传进度与 `{count,bytes}`，
  页面写到面板状态行。
- 安卓 `TileCache`（DiskLruCache，`cacheDir/tile_cache`，上限 300 MB）：`shouldInterceptRequest`
  拦截瓦片主机 → 命中直接返回 → 未命中 `HttpURLConnection` 代拉（浏览器 UA；天地图按
  `tdtReferer` 加 Referer，百度固定 `map.baidu.com`；10 s/20 s 超时）→ 成功落盘；
  失败返回 `null` 走 WebView 原路。

#### 3. 踩坑：QtWebEngine 不能序列化 JS 对象

```python
def _json_call(self, expr, cb):
    def _wrap(raw):
        data = json.loads(raw) if isinstance(raw, str) and raw else raw
        cb(data)
    self.js('JSON.stringify(%s);' % expr, _wrap)      # ← 关键：先在 JS 侧串行化
```

`runJavaScript` 的返回值要经 Qt 的 `QVariant` 转换：**标量与数组可以，对象会变成空串**。
所以状态查询一律「JS 侧 `JSON.stringify` → Python 侧 `json.loads`」。

> 症状极其隐蔽：`_onStatusPoll(st)` 永远收到 `None` 就静默返回，于是工具栏不同步、
> 跟随锁检测失效、瓦片失败提示不出现——**全都不报错，只是"看起来没反应"**。
> 写地图相关代码时，先把「状态能不能取回来」验证掉，再调逻辑。

#### 4. 轮询、跟随锁与图层写回

```python
self._viewTimer.setInterval(1200)      # MapPanel._pollStatus → host.status(self._onStatusPoll)
```

| 轮询字段 | 用途 |
|---|---|
| `base` / `rail` / `coord` | 同步工具栏下拉、铁路勾选框、「视图」菜单的勾选状态 |
| `night` | 与界面主题对齐（以配置为准，避免来回跳） |
| `locked` | 页面报告「用户拖动/缩放过」→ 取消「跟随」勾选、写回 `cfg.mapFollow`、发 `followChanged`、日志留痕 |
| `zoom` / `center` | 缓存回 `CoreConfig.mapZoom` / `mapCenterLng` / `mapCenterLat`，随 `config.save()` 落盘 |
| `tilesTotal` / `tilesFailed` | 只含**底图**；`failed > 8` 且 `total == 0`（或 `failed ≥ total × 0.9`）→ 坐标栏显示「底图不可达，换一张」（红字），**不弹窗**；铁路层计数 `railTilesTotal` / `railTilesFailed` 只展示、不参与该判定 |

**页面内改图层会写回配置**（`_syncLayersFromPage()`）：

1. 页面里`base` 变了 → 写 `config.mapBase`、同步下拉、发 `layersChanged`；
2. `rail` 变了：用户**手动**关/换的，写 `config.mapRail`。页面因 GCJ/BD 偏移底图
   **自动暂停**时会置 `railAutoOff`，并用 `notifyHost()` 上报 `railWanted`——安卓 `onLayers`
   收到的是「用户想要的图层」，不会把自动暂停误写成「不显示」；桌面端不注入 `LBJHost`，
   靠 1200 ms `status()` 轮询同步勾选框；
3. 有变化就 `_saveConfig()` 并存盘。

所以在工具栏、「视图」菜单、页面面板三处怎么改，最终状态都一致。

#### 5. 标记、轨迹与信息卡片

| 机制 | 实现 |
|---|---|
| 标记 | `L.marker` + `L.divIcon`（HTML 车次标签 + 9 px 坐标圆点），`pane: markerPane`、`riseOnHover`、`zIndexOffset:100`；点击弹信息卡片 |
| 轨迹 | **页面侧**抽稀（位移 > 6e-5 度 **或** 距上一点 > 3 s 才记一点，滑动窗口 `trailMax=240`），`L.polyline` 画在 `trailPane`（3 px / 0.85 不透明度） |
| 信息卡片 | `L.popup`（`closeButton`，不自动平移）：车次/方向/速度/公里标/线路/机车/类别，**v3.2 追加**车次信息（等级·担当局·担当段）、车底（配属段·车型）、区间（始发→终到）、机车配属（配属单位·制造厂），再跟收到时间/轨迹里程/坐标 |
| 坐标 | 标记与轨迹都先经 `toMap()` 换到当前底图基准，`updated` 时按新基准重画 |
| 跟随 | 只有列车移动 > 30 m 才重新居中；用户一按鼠标/滚轮/触摸即置 `userTouched`，由 Python 侧轮询发现并同步按钮 |
| 换底图 | 标准墨卡托 ↔ 百度墨卡托重建地图实例（`createMap`），其余只换瓦片层；标记/轨迹由 `rebuildMarkers()` 按新基准重画 |

> **历史教训（保留，别再犯）**：早期每帧无条件 `setZoomAndCenter`，用户一拖就被拉回，
> 表现为「来车之后地图动不了」。现在用户一操作就置 `userTouched` 并停止自动跟随，
> 纯视觉逻辑失败绝不能影响定位。

#### 6. 车次/机车信息（v3.2）

页面的 `state[id].data.info` 是**唯一落点**，两种写入方式等价：

```js
// ① 随批量推送带进来
LBJ.update({ trains: [{ id, train, lat, lon, info: { grade, bureau, section, owner,
              model, from, to, locoDepot, locoMaker, locoModel } }] });
// ② 查询结果晚到：补进已有标记（不改变位置），返回命中数
LBJ.setTrainInfo('G1234', { grade: '高速动车组', bureau: '南昌局', section: '南昌客运段' });
```

- 合并规则：`upsertTrain()` 对 `info` 做**浅合并**（后到的非空字段覆盖旧值，
  空值不覆盖），所以位置帧先到、车次查询后到也不会把已有信息冲掉；
- 展示位置：标记副标题（`markerSub()` 追加 `info.grade`）与点击弹窗（`infoRows()`：
  `grade/bureau/section` → 「车次信息」、`owner/model` → 「车底」、`from/to` → 「区间」、

### 9.11 自适应布局：`FieldGrid` / `RxStatusStrip` / `_applyResponsive`

**`FieldGrid`** —— 一批 label/value，按可用尺寸自动换列：

```python
class FieldGrid(QWidget):
    MIN_CELL_W = 150      # 单列最小宽度
    MAX_COLS   = 6        # 最多 6 列（再多经纬度那种长值就挤了）
    TARGET_CELL_W = 210   # 理想列宽
    MIN_ROW_H  = 36       # 一行至少占的高度（字段名 14px + 值 19px）

    def _colsForWidth(self, width, height=0) -> int:
        maxCols = min(n, MAX_COLS, width // spx(MIN_CELL_W))
        best = maxCols
        for c in range(2, maxCols + 1):
            rows = ceil(n / c)
            if height and rows * spx(MIN_ROW_H) > height and c < maxCols:
                continue                       # 行放不下 → 加列
            last = n - (rows - 1) * c          # 最后一行几项
            penalty = (c // 2 - last) * 80 if last < max(1, c // 2) else 0
            score = abs(width / c - spx(TARGET_CELL_W)) + penalty
            best = min(best, c, key=…)
        return best
```

打分同时考虑三件事：**格子宽度接近 210 px**、**最后一行别只剩一两个**、
**行数别超出可用高度**。全景布局下「列车信息」只有右列 38% 宽，
所以常见结果是 2~4 列；窗口很矮时还会切紧凑模式（见下）。

**紧凑模式（v2.3）**：`_applyDensity()` 用真实控件量出行高
（`value.minimumSizeHint().height() + caption… + spacing`），
`rows × 行高 > 可用高度` 就把字段名 `setVisible(False)`、值上挂 tooltip。
v2.3 的全景布局里右列卡片只有 150~200 px 高，11 个字段硬塞 6 行必被裁，
藏起字段名后 6 行只需 120 px，值全部可见。

两个坑（都已修）：

1. **`QSizePolicy.Ignored` 会把标签压成 0 宽**——频谱那行摘要曾经因为这个直接不显示，
   正确做法是保留默认策略、自己用 `QFontMetrics.elidedText()` 控制文本长度；
2. **重新 `addWidget` 后空行还留着 stretch**，多出来的高度被空行吃掉，
   表现为“内容挤在上半截”。每次 reflow 要先把所有行列 stretch 清零再重设。

### 9.13 多屏混合 DPI 适配（v2.5）

**现象**：本机两块显示器，程序在 1920×1080@100% 上正常，拖到笔记本屏（200% 缩放）
后窗口右下整片被裁、卡片挤成一团，两屏看起来完全不像同一个程序。

`QGuiApplication.screens()` 实测：

```
screen[0] P24FBA-RA   1920x1080 @(0,0)      logicalDPI=96  dpr=1.00   (主屏)
screen[1] EF25QBA63.E 1280x800  @(1920,-242) logicalDPI=96  dpr=2.00   (笔记本)
```

Qt6 在 Windows 上默认按显示器分别处理 DPI（per-monitor v2），`QWidget` 的
坐标/尺寸/`setPixelSize()` 字号都是**逻辑像素**，平台层渲染时再乘所在屏的 dpr。
也就是说 dpr=2.0 的屏会把同样的逻辑窗口画成 2 倍物理像素。

**四个叠加的根因**：

1. `autoUiScale()` 与 `_applyWindowGeometry()` 一律取 `app.primaryScreen()`。
   窗口按主屏算出 1792×949 逻辑像素，拖到 dpr=2.0 的副屏 → 物理 3584×1898，
   而副屏物理只有 2560×1600，必然溢出。
2. 窗口尺寸下限写死 `w = max(w, spx(1000))`、`h = max(h, spx(660))`，
   再加上 `setMinimumSize(spx(880), spx(560))`。高 DPI 屏的**逻辑**可用区可能只有
   640×400（甚至 400×400），这些下限会把窗口顶出屏幕，布局再自适应也救不回来。
3. `_applyResponsive()` 开头 `w = max(640, self.width())` / `h = max(480, ...)`。
   用户把窗口拖小、或屏幕逻辑区本来就小时，代码却按 640 宽去分配 `band1`
   左右两列（`setSizes([int(w*0.62), ...])`），子控件被顶出父窗口。
4. 标题 `setMaximumWidth()` 用 `fontMetrics()` 量宽度，但此时 QSS 还没 polish，
   量到的是应用默认字体（156 px），而实际 `spx(15)` 的字需要 192 px → 标题被截断。

**修复**（全在 `cr_lbj/gui.py` 等 `cr_lbj/ui/` 模块）：

```python
def _currentScreen(self):        # windowHandle().screen() → 鼠标所在屏 → primaryScreen()
def _applyMinSizeForScreen(scr)  # 下限 min(spx(880), 该屏逻辑可用宽-8)，高同理
def _applyWindowGeometry(scr)   # w/h 一律 min(..., avail.width()/height())，绝不超屏
def _onScreenChanged(scr)       # 换屏：收紧尺寸 + 重排三段 + 地图 JS resize
def showEvent / moveEvent      # 首次显示、拖动换屏时触发上面这条
```

- `_applyResponsive()` 改用**真实** `self.width()/height()`（只留 320×240 兜底），
  三段高度与所有 `setMinimumWidth/Height` 都跟着窗口尺寸收紧；
  极小逻辑窗（< `spx(620)` 或高 < `spx(500)`）直接收起中段，把高度全给地图与解码。
- 标题宽度改用显式 `QFont` + `QFontMetrics`（按 `spx(15)` 构造）计算。
- `main()` 保持 `PassThrough` 高 DPI 策略；启动日志打印当前屏名与 dpr。

**设计取舍 —— UI_SCALE 故意不随屏变**：所有 `spx()` 尺寸在构造时已烘焙进控件，
运行时改倍率只有一部分控件会跟着变，反而更乱。两屏共用同一套逻辑布局，
物理大小交给 Qt 按各自 dpr 渲染，这才是系统级正确做法；换屏只调整窗口几何与
三段比例，字号不跳变。实测两屏字号分布完全一致。

**验证**（`_dpi_probe.py`，临时脚本，用完即删）：离屏渲染 100%/125%/150%/200%
四档 + 本机两块真实屏各截一张，统计 `offScreen`、文字裁切数、子控件溢出数：

### 9.16 配属 / 制造厂全称化（v3.2.1，`data/depot_names.py`）

号段表 `loco_roster.csv` 的配属是简称式（`上局沪段`、`南局南段`），

`南昌局南昌机务段`），制造厂同理（`中车株洲` → `中车株洲电力机车有限公司`）：

```python
full_depot('南局南段')      # '南昌局南昌机务段'
full_depot('京局丰段（京铁运输）')  # '北京局丰台机务段（京铁运输）'

format_duty('南昌局', '南昌客运段')  # '南昌局南昌客运段'
```

约定：

- 只翻译**核对过的标准机务段**；没收录的地方铁路 / 企业自备 / 非标写法原样返回，
  宁可显示简称也不编造全称；
- 带括号备注的只翻主名，备注原样保留；
- 该模块是纯数据 + 纯函数，不依赖 Qt；回归用例见

- 使用位置：`LocoInfoPanel`（机车信息卡，配属/制造厂分两行）、`RecordDetailDialog`
  与 `LocoDetailDialog` 的配属/制造厂字段；车次卡/记录详情的担当单位用 `format_duty()`。

## 10. 数据层：路径、配属、车次、更新

v3.0 新增的四个模块都在 `cr_lbj/data/`，**不依赖 Qt**，桌面端与安卓端共用同一份
`shared/data/`。字段语义对照见 [车次与配属查询](车次与配属查询.md)。

### 10.1 数据目录分层（`paths.py`）

安装目录可能只读（Program Files / `_MEIPASS` 临时目录 / 只读的绿色版解压目录），
而自动更新必须能写，所以引入"用户可写覆盖层"，读取顺序**先命中先用**：

| 优先级 | 位置 | 用途 |
|---|---|---|
| 1 | `%CRLBJ_DATA_DIR%` | 便携部署 / 自动化测试指定的目录 |
| 2 | `%LOCALAPPDATA%\CR-LBJ-Receiver\data\`（Linux: `~/.local/share/…`） | **自动更新写这里** |
| 3 | exe 同级的 `shared/data/` | 绿色版（exe 与 shared 并排） |
| 4 | `_MEIPASS/shared/data/` | PyInstaller 内置快照 |
| 5 | 仓库根 `shared/data/` | 源码运行 |

`loco_roster.data_path(name)` 返回实际生效路径，`loco_roster.source_info()` 给出
每份文件是否来自覆盖层（界面据此显示"内置快照 / 已更新"），
`loco_roster.invalidate()` 在更新后清缓存，下次读取即新数据。

> 源码运行 / 自动化测试请设 `CRLBJ_WORK_DIR`（`runtime.py` 会把它当成配置与历史库目录，
> 并把仓库模板种进去），否则离屏冒烟会把受版本控制的 `lbj_config.json` 模板写脏。
> 打包后的 exe 不需要它：配置与 `history.db` 本来就落在 exe 同级目录。

### 10.2 机车配属（`loco_roster.py`）

```
locoCode(3 位) ──loco_types.csv──► 短型号 DF4/SS4/HXD1D
号码(去前导零) ─┐
                ├─► loco_roster.csv：型号精确相等 && 起号 <= 号 <= 止号 → 第一条命中
型号文本(兜底) ─┘
```

- 别名只有 `DF4B→DF4`、`DF4R→DF4`（号段表把东风 4B/4R 并入 DF4），
  **不做泛化前缀回退**：`HXD1D` 不能退成 `HXD1`（两种车、两个段）。
- 返回结构里 `ok`（认出型号）与 `exact`（号段命中）分开，界面据此区分
  "配属未知（号段未收录）"与"型号未收录"；型号未收录时 `suggest` 给出开头相同的候选。
- 号段重叠时取第一条，其余进 `alternatives`。
- 号段表有 3 行配属为空（上游即缺），显示"原表未标注配属"，不猜。

```python
from cr_lbj.data import loco_roster as R
R.lookup_loco('HXD1D-0123', '240')   # → depot='上局沪段', range='106-137'
R.specs_for('HXD3CA')                # → 前缀兜底到 HXD3C 的参数
```

### 10.3 车次查询（`train_info.py`）

两个来源，统一成同一套字段：

| | RailGo | 12306 |
|---|---|---|
| 接口 | `data.railgo.zenglingkun.cn/api/train/query?train=G7` | `search.12306.cn` → `kyfw.12306.cn/otn/queryTrainInfo/query` |
| 鉴权 | 无（CORS `*`） | 无（需浏览器 UA / Referer） |
| 有 | 等级、担当局、客运段、**配属段**、车型、时刻表、开行日、交路 | 时刻表、等级 |
| 无 | —— | 担当/配属/车型 |

`query(train, prefer)`：`auto` 默认先 RailGo，失败自动退 12306；也可以强制指定。
**任何失败都不抛异常**，返回 `ok=False` + 中文原因（网络不可达 / HTTP 4xx / 非 JSON /
未查询到车次）。12306 的停站分钟数由到发时刻相减，跨日不臆测（记 0）。
频率约束：只在用户手动查询时发请求，不做预取与轮询。

### 10.4 数据自动更新（`updater.py`）

```
GitCode contents API（GitHub 国内镜像）
  GET .../repos/CCCccc233/LBJ_Console/contents/loco_info.csv?ref=resources
  → {content: base64(csv), sha}
        │
        ├─ 归一化比对（去行尾空白/末尾空行）→ 与本地一致：只记 sha，不写盘
        ├─ 严格校验：行数≥15000、型号≥120、中文配属≥50、畸形行≤2%
        │     不通过 → 丢弃，保留旧文件（绝不覆盖能用的数据）
        └─ 通过 → 原子写（.tmp → rename）+ 旧文件留 .bak + 写 data_manifest.json
```

- `check_and_update(force=False, interval_days=7)`：非强制时先看 manifest 的
  `lastCheck`，未到期直接跳过（避免每次启动都打上游）。
- `status()` / `last_check_text()` 给界面用；`restore_backup()` 回退到 `.bak`。
- 网络层只依赖 `urllib`；`CRLBJ_DATA_SOURCE_URL` 可换成自建镜像（返回同样的 JSON 结构）。
- 失败一律返回 `{ok: False, message}`，界面只记日志，不弹窗、不影响启动。

## 11. 扩展点

### 11.1 新增一种数据源

数据源只要满足四个方法就能接进来：`open()` / `read(timeout)` / `close()` /
`getDiagnostics()`，外加一组统计属性（`queue`、`blockCount`、`blockSizes`…）。

1. 新建类，读数据时调 `recordBlock(self, 样本数, 字节数)` 记账，
   队列满就 `droppedBlocks += 1` 并把块丢掉（绝不阻塞读取线程）；
2. `getDiagnostics()` 直接 `return buildDiagnostics(self, 'usb' 或 'net')`，
   仪表板就自动有块率/抖动/丢块指标；
3. 在 `LbjCore._buildChain()` 的 `sourceType` 分支里注册；
4. 在 `SOURCE_TYPE_LABELS` 与 `default_sources()` 里加一项，
   并在 `SOURCE_TYPE_TAGS` / `SOURCE_TYPE_NAMES` 里补短标签与显示名；
5. `normalize_sources()` 无需改动（它只保证列表里有 USB 选项）。

### 11.2 新增解码字段

1. 在 `DecodeResult` 加字段，并写进 `toDict()`；
2. 在 `LbjDecoder.decodeLbj()` 相应切片处赋值；
3. 历史库：`_CREATE_SQL` 加列 + `_initDb()` 加迁移（若需兼容旧库）；
4. `HistoryDb.insert()` 的列数与占位符必须同步（当前 33，列序由 `_INSERT_COLS` 统一维护）；
   若是「同 uid 就地更新」的字段，还要同步 `_values()`；
5. 详情窗口 `result_items`、`TrainInfoPanel.fields` 按需补显示。

### 11.3 换地图或换底图

地图是两端共用的单文件 `shared/web/railmap.html`（Leaflet 1.9.4，本地化在
`shared/web/vendor/leaflet/`），宿主只依赖 `window.LBJ.*` 这组方法。
换服务商时保持这些方法签名，桌面 `MapHost` / 安卓 `MapPage` 两端都不用改。

- 换底图：改 `BASE_SOURCES`，新增条目必须同时写 `name`（与 `config_ext.BASE_LAYERS`、
  安卓 `MAP_BASES` 逐字一致）、`coord`（`wgs` / `gcj` / `bd`）、`url` 模板与 `maxNativeZoom`；
  需要 tk 的用 `{key}` 占位。
- 坐标系：高德是 GCJ-02（`wgs2gcj`），百度是 BD-09（`gcj2bd` 再转一次，
  且瓦片编号/投影要用 `L_BAIDU_CRS` + `BaiduTileLayer`），天地图是 CGCS2000（工程上等同 WGS-84）。
  偏移坐标系底图与 WGS-84 铁路图层不能混叠。
- 换渲染引擎属于破坏性变更：`tests/test_shared_web.py` 会校验 Leaflet 本地化、
  7 张底图 id/名字、百度 CRS、缓存契约与 API 表面，换引擎必须同步重写该测试。

## 12. 构建与打包

### 12.1 一键构建

```bash
python desktop/build.py                 # 清理 → 打包 → 清历史库 → 校验 → 汇总（配置保留）
python desktop/build.py --no-clean      # 跳过前置清理（增量构建，快）
python desktop/build.py --keep-data     # 连历史库也保留
python desktop/build.py --reset-config   # 连 dist/lbj_config.json 一起清掉
```

`desktop/build.py` 的六个步骤：

| 函数 | 作用 |
|---|---|
| `cleanProcessFiles()` | 删 `build/`、所有 `__pycache__/`、根目录 `*.pyc`；遍历时跳过 `.git` / `dist` / `docs` / `tools` / `android` |
| `runPyInstaller()` | `python -m PyInstaller desktop/SDR_LBJ.spec --clean --noconfirm`（cwd 为仓库根，产物仍在根 `dist/`），打印退出码与耗时 |
| `cleanDistRunData(keepConfig=True)` | 默认只删 `history.db`（含 `-journal` / `-wal`）；**`lbj_config.json` 保留**（用户的 Key / 数据源 / 主题都在里面），只有 `--reset-config` 才删 |
| `cleanProcessFiles()` | 打包后再清一次，保证交付目录只剩源码 / 文档 / dist |
| `verify()` | 校验 exe 存在、`dist/README.md` 存在、`dist/docs/` 八份文档齐全、**CArchive 里 `shared/` 资源是否真的入包**，并警告残留运行时文件 |
| `summary()` | 打印源码清单、`tools/rtl` 文件数、文档清单、`dist/` 内容 |

构建后目录约定（v3.0）：

```
CR_LBJ_Receiver/
├── 桌面工程 desktop/
│   ├── 入口     main.py
│   ├── 应用包   cr_lbj/  （core / data / ui / utils + runtime / gui / app）
│   ├── 构建     build.py  SDR_LBJ.spec
│   └── 资源     lbj_config.json  国铁.ico（运行期配置/历史库也在这里）
├── 工具     tools/rtl/
├── 文档     docs/（含 架构说明.md）
├── 共享     shared/（两端共用）
└── 产物     dist/  →  CR-LBJ-Receiver.exe + README.md + docs/（仓库根）
```

`dist/` 里**不应**出现 `build/`、`__pycache__`、`*.pyc`、`history.db`；
`lbj_config.json` 是**允许且有意保留**的——重打包不应该让用户重填数据源/地图等配置。

### 12.2 `SDR_LBJ.spec`

| `_RTL_DATAS` | 把 `rtl_tcp.exe` / `rtl_test.exe` / `rtlsdr.dll` / `msvcr100.dll` / `pthreadVC2.dll` / `README.txt` 收进 `rtl/`；优先取项目 `tools/rtl`，回退旧路径 `../../RTL_TCP_Server`，并打印实际取用的目录 |
| `_PY_EXCLUDES` | 排除 torch / pandas / pyarrow / h5py / sklearn / numba / shapely / pyproj / pyspark 等无关重型包 |
| `_keep_qt()` | 过滤未用到的 Qt 二进制（3D、Charts、Multimedia、Pdf、VirtualKeyboard…），实测剔除 109 个 |
| `lbj_config.json` 作为 `datas` | 首次运行时解压到 exe 同级，作为默认配置模板 |
| 打包后处理（`EXE()` 之后） | `shutil.copytree` 把 `docs/` 复制到 `dist/docs`，`shutil.copy2` 复制 `README.md`，于是发布包自带文档 |

> spec 里的后处理是「构建即交付」的关键：exe 与文档一次成型，不需要手工拷贝，
> 也就不会出现「程序更新了、文档还是上一版」的情况。

### 12.3 体积

| 配置 | 单文件大小 |
|---|---|
| 未做排除 | 575 MB |
| 排除 Python 重型包 + 过滤 Qt | **282 MB** |

体积主要构成：QtWebEngine（`Qt6WebEngineCore.dll` + `icudtl.dat` + resources，约
130 MB）、PySide6 基础模块、numpy/scipy。想再小只能放弃内嵌地图（去掉

## 14. 已知限制

| 限制 | 说明 |
|---|---|
| 经纬度依赖长报文 | 只发基础帧的车次永远没有坐标，无法反推 |
| 长报文属实测逆向 | 不在 TB/T 3504 明文范围内，字段含义可能随厂商固件变化 |
| 尾 3 位未知 | `ih[47:50]` 含义未确认，程序保留但不解释 |
| 无位置时地图无点 | 无法用公里标代替经纬度上地图（缺线路几何数据） |
| 单数据源 | 一次只能用一个 `sources` 条目，不支持同时收多路 |
| OWRX 必须 DC=0 | 否则目标信道被推出带宽 |
| 地图瓦片需联网 | 无网时只有已缓存瓦片能显示，解码不受影响；离线缓存按底图/缩放分别存 |
| 默认中心是坐标 | 不再做在线地名解析（v3.0 起），断网也能居中；重名地点不会再落到别的城市 |
| 偏移坐标系底图不能叠铁路 | 高德（GCJ-02）/百度（BD-09）与 WGS-84 铁路栅格无法逐块纠偏，页面自动暂停铁路图层 |
| 天地图需自带 tk | 浏览器端 tk + Referer 白名单域名，两者缺一都可能 418/403 |
| 百度只覆盖国内 | 百度瓦片在中国境外基本无图，境外/远海请用 OSM |
| 过渡期分类是启发式 | 2027-01-01 前 T/K/X 按速度判定、速度缺失按旧版兜底，仍可能误判；2027-01-01 起全量新版，此限制消失 |
| 去重按 (车次, 方向) 建槽 | 同一车次上下行交替极快时（几乎不出现）可能把两帧并到一条 |
| 去重窗口是时间近似 | 2.5 秒内位置大幅变化的两帧会被判为重复，只保留更优的那条 |
| 被合并的帧不落库 | 想留全量原始帧就把 `dedupeWindow` 设为 0 |
| 界面缩放需重启 | `spx()` 与样式表在 `main()` 定型，不支持运行时热切换 |
