## 1. 一句话结论

- **渲染引擎** = Leaflet 1.9.4（BSD-2-Clause，`shared/web/vendor/leaflet/` 本地化，
  离线可用、零构建、无 CDN 依赖）。
- **底图** = 7 张：高德街道/卫星（免 Key）、百度街道/卫星（免 Key）、OSM 标准、
  天地图矢量/影像（CGCS2000，需 tk）。**默认 `amap` 高德街道**。
- **铁路图层** = OpenRailwayMap 5 种样式（WGS-84 栅格），可在页面图层面板切换样式与不透明度。
- **坐标系分三类**：`wgs`（OSM/天地图，零偏移）、`gcj`（高德，标记自动加偏）、
  `bd`（百度，自定义墨卡托 CRS，标记自动加偏；切百度时重建地图实例）。
  列车点/轨迹/铁路图层对外**一律 WGS-84**，偏移由页面按当前底图基准统一处理。
- **偏移坐标系底图与 WGS-84 铁路图层不能混叠**：切到高德/百度时页面自动暂停铁路图层并提示，
  换回 OSM/天地图后自动恢复（用户手动关过的不恢复）。
- **离线缓存**：页面图层面板「缓存本区域」；安卓宿主用 DiskLruCache 落盘（300 MB 上限，
  可查占用/清除），桌面宿主无磁盘缓存接口时降级为图片预取（进浏览器 HTTP 缓存）。

  **页面不硬编码任何 tk**，tk 为空时选中天地图只弹申请提示、不发瓦片请求（见 §6）。

  其余底图在夜间给瓦片层加 CSS 反相（`body.nightfall .lbj-tiles`，
  `invert(1) hue-rotate(180deg) brightness(.86) contrast(.92) saturate(.72)`）。
  标记、轨迹、信息卡片在独立 pane，不受滤镜影响。

### 2.1 默认底图为什么是高德街道（`amap`）

| 理由 | 说明 |
|---|---|
| **实测最快最稳** | 2026-11-26 本机复测 HTTP 200、238 ms（同日上午另一次实测 63~130 ms），是全部图源里响应最快的；OSM 本机 15 s 超时、ORM 403、天地图无 tk 返回 418。 |
| **免 Key** | 直接按瓦片 URL 取图，无任何注册/配额门槛，开箱即用。 |
| **国内网络可达** | 高德瓦片域名在国内通常直连可达；OSM/ORM 的可达性随网络环境波动。 |
| **偏移可自动处理** | 高德是 GCJ-02，页面用标准 `wgs2gcj()` 自动给标记/轨迹加偏，与高德底图对齐；代价是铁路图层（WGS-84）自动暂停，可随时切回 OSM/天地图看铁路。 |

> 可达性会随网络（代理/线路/运营商）变化，**不要当固定事实**；换设备/换网络请按 §2.2 现场复测。
> 底图全挂时页面会整屏提示，并提供「换成高德街道 / 换成 OSM」一键按钮。

### 2.2 可达性实测（2026-11-26，本机）

测试环境：Windows 11 10.0.26300、Python 3.14.5、浏览器 UA、
`urllib` 直连（无代理）、连接/读取超时 15 s、取 z6 中国范围瓦片；
百度两个域名带 `Referer: https://map.baidu.com/`。
**结论只代表当时、当地、该网络**，用户设备请自行复测。

| 图源 | 实测结果 | 判定 | 说明 |
|---|---|---|---|
| 高德街道 `amap` | **HTTP 200 · 238 ms** | ✅ 可用 | 返回真实 PNG 瓦片（同日上午另一次 63 ms） |
| 高德卫星 `amap_img` | **HTTP 200 · 279 ms** | ✅ 可用 | 返回 JPEG 影像瓦片 |
| 百度街道 `baidu` | **HTTP 200 · 656 ms** | ✅ 可用 | 带 Referer 后正常返回 PNG |
| 百度卫星 `baidu_sat` | **HTTP 200 · 372 ms** | ✅ 可用 | 同上 |
| OSM `osm` | **超时（> 15 s）** | ⚠️ 随网络 | 本机不可达，不代表用户设备；失败自动降级 |
| 天地图矢量 `tdt_vec` | **HTTP 418** | ⚠️ 需 tk | 无 tk 被服务端拒绝，属预期（见 §6） |
| 天地图影像 `tdt_img` | **HTTP 418** | ⚠️ 需 tk | 同上 |
| OpenRailwayMap | **HTTP 403（v3.2 当时，无 Referer）** | ⚠️ 需合规 UA | v3.2.2 整改后改用可识别应用 UA、**不伪造 Referer**，实测 200（见 §3.5）；桌面 OSM 底图 + ORM 标准图层实测 **16/16 瓦片成功** |

现场复测脚本（20 秒内出结果；直接改 `urls` 即可）：

```python
import concurrent.futures as cf
import urllib.request

UA = {'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) '
                    'AppleWebKit/537.36 (KHTML, like Gecko) Chrome/128.0.0.0 Safari/537.36'}
BAIDU_REF = {'Referer': 'https://map.baidu.com/'}

urls = {
    'amap':     'https://webrd01.is.autonavi.com/appmaptile?lang=zh_cn&size=1&scale=1&style=8&x=52&y=24&z=6',
    'amap_img': 'https://webst01.is.autonavi.com/appmaptile?style=6&x=52&y=24&z=6',
    'baidu':    'https://maponline0.bdimg.com/tile/?qt=vtile&x=20&y=7&z=6&styles=pl&scaler=1&udt=20200818&from=jsapi',
    'osm':      'https://tile.openstreetmap.org/6/52/24.png',
    'tdt_vec':  'https://t0.tianditu.gov.cn/vec_w/wmts?SERVICE=WMTS&REQUEST=GetTile&VERSION=1.0.0'
                '&LAYER=vec&STYLE=default&TILEMATRIXSET=w&FORMAT=tiles'
                '&TILEMATRIX=6&TILEROW=24&TILECOL=52&tk=',
    'orm':      'https://a.tiles.openrailwaymap.org/standard/6/52/24.png',
}

def probe(kv):
    k, u = kv
    h = dict(UA)
    if 'bdimg.com' in u:
        h.update(BAIDU_REF)
    try:
        r = urllib.request.urlopen(urllib.request.Request(u, headers=h), timeout=9)
        return k, 'OK %d' % r.status
    except Exception as e:
        return k, 'FAIL %s' % type(e).__name__

with cf.ThreadPoolExecutor(max_workers=8) as ex:
    for k, v in sorted(ex.map(probe, urls.items())):
        print('%-9s %s' % (k, v))
```

> 本机网络下 Python 侧「百度不带 Referer」也能 200，但**部分时段/节点会 403**，
> 且 `file://` 页面发出的请求 Referer 与浏览器上下文不同——所以两端宿主**固定**给
> `*.bdimg.com` 加 `Referer: https://map.baidu.com/`，不依赖运气（实现位置见 §6.4）。

> **ORM 的 403 与整改**：v3.2 时观察到 OpenRailwayMap 官方瓦片「不带 Referer 返回 403」，
> 一度在宿主补官方站点 Referer。v3.2.2 复核发现**真正的判定依据是 User-Agent**：
> 用可识别的应用 UA、不加任何 Referer 即可 200；用浏览器 UA 才会被拒。
> 因此现行为「合规 UA + 不伪造 Referer」，既符合政策又能正常取图（见 §3.5）。

### 2.3 底图全挂时应用自己的表现

- **地图页**：只有当**底图**瓦片失败数 ≥ 6 且一张都没成功（或失败率 ≥ 95%）时，
  才整屏提示「底图瓦片加载失败」，列一张可点的备用底图按钮（高德街道 / OSM），
  点一下直接换（`LBJ.setBase`），不离开页面；状态行会分别显示底图与铁路的瓦片成功/失败张数。
  **铁路瓦片失败不再触发这个全屏提示**（见 §3.5）。
- **桌面端**：地图卡片左侧坐标栏显示红色「底图不可达，换一张」，不弹窗；
  底图下拉是救急入口。
- **安卓端**：地图页底部出现「换底图 ›」横幅，点开图层底部面板换。
- 换完的底图会**写回配置**（`mapBase`），下次启动沿用。

### 2.4 与 LBJ_Console 的图源对照（调研结论）

对 [LBJ_Console](https://github.com/undef-i/LBJ_Console)（Flutter）的调研结论：

| 项 | LBJ_Console | 本项目 v3.2 |
|---|---|---|
| 渲染 | Flutter 地图插件（栅格瓦片） | Leaflet 1.9.4（本地化，共用页） |
| OSM | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` 直连 | 同地址直连 |
| 高德 | `webrd` / `webst`，自带 WGS84→GCJ02 转换 | 同源直连，页面自动加偏 |
| 腾讯 | TMS + GCJ 转换 | 不接入 |
| ORM | `{s}.tiles.openrailwaymap.org` + 自建 PMTiles | 官方直连 5 样式（无自建 PMTiles） |
| 代理/加速 | **无任何代理/加速** | 无代理；瓦片请求由原生栈代拉并落盘缓存（安卓） |

结论：LBJ_Console 地图「顺畅」与否**完全取决于用户网络环境**，并没有隐藏的加速链路；
本项目对齐同样的直连策略，并额外把安卓端瓦片请求改由原生 HTTP 栈代拉 + DiskLruCache 缓存
（§7），落盘后离线可复用。

## 3. OpenRailwayMap 铁路图层

### 3.1 样式

| id | 名称（逐字） | 瓦片路径 |
|---|---|---|
| `off` | 不显示 | — |
| `orm_standard`（默认） | ORM 标准（线路+信号） | `https://{s}.tiles.openrailwaymap.org/standard/{z}/{x}/{y}.png` |
| `orm_maxspeed` | ORM 限速 | `.../maxspeed/{z}/{x}/{y}.png` |
| `orm_signals` | ORM 信号 | `.../signals/{z}/{x}/{y}.png` |
| `orm_electrified` | ORM 电气化 | `.../electrified/{z}/{x}/{y}.png` |
| `orm_gauge` | ORM 轨距 | `.../gauge/{z}/{x}/{y}.png` |

- 子域 `a/b/c`，`maxNativeZoom` 19；页面上限 z19。
- 铁路图层固定 `coord: wgs`（WGS-84 标准墨卡托）；叠加顺序（自下而上）：
  **底图 → 铁路（`railPane` z=300）→ 轨迹（`trailPane` z=410）→ 标记（`markerPane` z=620）**。
- 不透明度默认 **0.85**（配置项 `mapRailOpacity`，0.2~1.0），面板滑块实时生效。
- 页面右上角图层面板可切样式；桌面工具栏「铁路」勾选框 = 开/关（关时记住原样式，
  再勾回来用的是配置里的 `mapRail`）。

### 3.2 混叠规则（重要）

| 当前底图坐标系 | 能否叠 ORM | 页面行为 |
|---|---|---|
| `wgs`（OSM / 天地图） | ✅ 可以 | 正常叠加 |
| `gcj`（高德） | ❌ 不能 | 切过去时自动把铁路设为 `off`，弹提示「铁路图层已暂停」；页面用 `railAutoOff` / `railWanted` 记住用户想要的样式，换回 WGS 底图时自动恢复 |
| `bd`（百度） | ❌ 不能 | 同上（提示里写 BD-09）；此时在铁路下拉里选任何样式都会被拒绝并提示先换底图 |

原因：ORM 瓦片是 WGS-84，高德/百度是偏移坐标系；栅格瓦片无法按块纠偏，硬叠会整体平移
300~500 m，看起来像「铁路线漂到旁边」。**要铁路图层就切回 OSM / 天地图**。

### 3.3 使用条款（重要）

OpenRailwayMap 官方瓦片是**非商业公益服务**，其 API 文档要求：

- 只允许"小规模、少量请求"的应用免费使用；
- 应用必须**对公众免费开放**（不得是内部/商用系统）；
- 必须发送**唯一的 User-Agent**（含应用名/版本/联系方式），且**不得伪造 Referer** 等来源标识；
  禁止预取与批量抓取；
- 官方可**无预警封禁**超量或商用使用者。

本项目是 GPL-3.0 开源、非商业软件，符合其定位；但**如果你想内部部署或商用**，
请自建瓦片（§5）或改用本地 GeoJSON，不要长期直连官方服务器。
安卓端代拉对 OSM/ORM 发应用 UA（`TileCache.UA_APP`），高德/百度/天地图沿用浏览器 UA；
桌面端由 QtWebEngine 发正常浏览器 UA，`_TdtRefererInterceptor` 只对 OSM/ORM 改写应用 UA。

### 3.4 中国境内覆盖

ORM 的中国数据完全来自 OSM，覆盖不均衡：主要干线通常有线路/车站，`signals`、`maxspeed`
这类需要人工标注的图层在中国境内**普遍稀疏**，缺数据时该图层就是透明的，属正常现象。
需要准确的信号/限速信息请自建（§5.2），别把「没画出来」当 bug。

### 3.5 OSM / ORM 使用政策与合规要求（v3.2.2 关键整改）

> OpenStreetMap 官方瓦片与 OpenRailwayMap 都是**志愿者运营的公益服务**，不是可以随便
> 抓取的开源 CDN。其使用政策（[OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)、
> [ORM 条款](https://www.openrailwaymap.org/)）明确要求：
>
> 1. **必须提供可识别的 User-Agent**（含应用名 / 版本 / 联系方式），**不得伪装成浏览器**；
> 2. **禁止批量预取/下载瓦片**（bulk download、prefetch、离线整片抓取）；
> 3. **不得伪造 Referer** 等来源标识；不得绕过限流。
>
> 违规会被直接封禁：OSM 返回 **HTTP 418**，正文为
> `Access blocked / App is not following the tile usage policy ...`（`http://osm.wiki/Blocked`）。

**v3.2.2 之前我们踩过的两个坑（真机实测 418 的根因）**：

| 问题 | 当时做法 | 后果 |
|---|---|---|
| UA 伪装 | 代拉瓦片用 `Mozilla/5.0 ... Chrome/128` 浏览器 UA | 被判「未识别客户端」，违规 |
| 批量预取 | 「缓存本区域」一次拉当前视野 z~z+3 的**几百上千张**瓦片 | 明确违反「禁止 bulk download」 |
| 伪造 Referer | ORM 请求固定带 `Referer: https://www.openrailwaymap.org/` | 违反「不得伪造来源」 |

**v3.2.2 整改（两端一致）**：

| 项 | 做法 | 实现位置 |
|---|---|---|
| 合规 UA | `CR-LBJ-Receiver/3.2.2 (+https://github.com/liujitong/CR_LBJ_Receiver; ...)` | 桌面 `ui/map_host.py` 的 `APP_UA`（拦截器对 `*.openstreetmap.org` / `*.openrailwaymap.org` 注入 `b'User-Agent'`）；安卓 `core/TileCache.kt` 的 `UA_APP` + `userAgentFor()` |
| 不伪造 Referer | ORM 请求不带 Referer（带合规 UA 实测 **200**） | 桌面 `APP_UA` 分支直接 return；安卓 `refererFor()` 对 ORM 返回 `null` |
| 禁止批量预取 | 「缓存本区域」对 OSM/ORM 直接拒绝并解释；浏览时的**被动缓存保留** | 页面 `isPolicyStrictSource()` + `LBJ.onCacheBlocked()`；安卓 `MapPage.runCacheArea()` 用 `TileCache.isPolicyStrictHost()` 二次过滤 |
| 高德/百度/天地图 | 仍用浏览器 UA（无此类政策要求；天地图另按 tk + `tdtReferer` 白名单） | 同上 |

> **被封之后怎么办**：OSM 的封禁通常是**按 IP 的临时封禁**（数小时自动解除）。
> 本程序已合规，解封后直接恢复。期间请换「高德 / 天地图」底图——页面在 OSM 不可达时
> 会明确解释原因并给出一键换图按钮。
>
> **想离线看整片地图**：用「天地图 / 高德 / 百度」底图再做「缓存本区域」（这几个图源没有
> 禁止预取的条款）；OSM/ORM 只做浏览级缓存，或自建瓦片（§5）。

**补充：ORM 之前的 403 与 Referer 的历史说明**

v3.2 时曾观察到「ORM 不带 Referer 返回 403、只带浏览器 UA 也 403」，于是补了官方站点
Referer。后来实测发现：**真正的判定依据是 User-Agent**——用可识别的应用 UA、不加任何
Referer 即可 200；用浏览器 UA 才会 403。所以 v3.2.2 改为「合规 UA + 不伪造 Referer」，
既满足政策又能正常取图。

**铁路图层失败降级**（页面侧，`shared/web/railmap.html`）：

- 铁路瓦片统计走独立的 `railTileOk` / `railTileFail`，失败 ≥ 4 张只弹**一次**小字 toast
  （`warnRailFail()`），**不影响底图判定**；
- 状态行显示「铁路 成功数/失败数」；全部失败（`railTileFail > 4 && railTileOk === 0`）时
  提示「铁路图层不可用」，并建议改用本地铁路线（GeoJSON）；
- 想完全离线看铁路，用 §5 的本地 `rail_local.geojson` 或自建瓦片，不再依赖官方 HTTP 服务。

**实测**：桌面 OSM 底图 + ORM 标准图层（`orm_standard`）**16/16 瓦片全部成功**；
本机验证 OSM（合规 UA）200、ORM（合规 UA、**无 Referer**）200。

## 4. 坐标系与偏移

### 4.1 三类底图基准

| `coord` | 基准 | 出现在 | 页面处理 | 标记偏移 |
|---|---|---|---|---|
| `wgs` | WGS-84 / 标准 Web 墨卡托（EPSG:3857） | OSM、天地图（CGCS2000，工程上等同 WGS-84） | 原样使用 | 零偏移 |
| `gcj` | GCJ-02（火星坐标） | 高德街道/卫星 | 标准墨卡托瓦片；`toMap()` 调 `wgs2gcj()` 给标记/轨迹加偏 | 自动纠偏 |
| `bd` | BD-09 + 百度自有墨卡托投影 | 百度街道/卫星 | 自定义 `L_BAIDU_CRS` + 专用瓦片编号换算；`toMap()` 调 `wgs2bd()`（= `wgs2gcj` → `gcj2bd`） | 自动纠偏 |

- **全链路只传 WGS-84**：桌面 `MapHost.update()` / 安卓 `MapPage` 下发列车点、轨迹、
  `centerLatLng` / `setCenter` / `centerTo` 的入参都是报文原始 WGS-84；
  是否加偏由页面按**当前底图基准**统一决定，宿主不做坐标转换。
- 反向读取：`LBJ.center()` / `LBJ.status().center` 返回的也是 WGS-84（`fromMap()` 反算），
  宿主可直接存配置或与其它 GIS 工具对接。
- 切换坐标系：标准墨卡托 ↔ 百度墨卡托必须**重建地图实例**（`createMap()`），
  页面会保存当前 WGS-84 中心与 zoom，重建后把中心/标记/轨迹按新基准重画（`rebuildMarkers()`）。
  高德与 OSM/天地图之间只换瓦片层，不重建实例。
- 高德 GCJ-02 相对 WGS-84 在中国境内典型偏移 **300~500 m**（z16 约 200 px）；
  百度 BD-09 在高德基础上再叠一层偏移。两者坐标**不能互相替代**，跨系统 Exchange 时
  一律以 WGS-84 为准。
- 页面内的坐标函数（`shared/web/railmap.html` §3）：
  `wgs2gcj` / `gcj2wgs`（一阶近似反算，误差 < 1 m，仅供地图跟随） /
  `gcj2bd` / `bd2gcj` / `wgs2bd`，以及百度墨卡托的 `ll2mc` / `mc2ll`。

### 4.2 百度自定义 CRS（页面纯 JS 实现，不引百度 JS API）

实现位置：`shared/web/railmap.html` 的 `L_BAIDU_CRS` 与 `BaiduTileLayer`：

| 组件 | 作用 |
|---|---|
| `LLBAND` / `LL2MC` | 纬度分带的经纬度 → 百度墨卡托系数（百度官方公开值） |
| `MCBAND` / `MC2LL` | 反向换算系数 |
| `ll2mc(lng, lat)` / `mc2ll(x, y)` | 经纬度 ↔ 百度平面坐标 |
| `L_BAIDU_CRS` | `L.extend({}, L.CRS, …)`：`project`/`unproject` 走 `ll2mc`/`mc2ll`，`transformation` 取 `2^-26, 0.5, -2^-26, 0.5`，`scale(zoom)=256*2^zoom`，`infinite: true` |
| `BaiduTileLayer` | 继承 `L.TileLayer`，重写 `getTileUrl()`：百度瓦片以世界中心为原点，`offset=2^(z-1)`，`bx=x-offset`、`by=offset-y-1`，再拼回模板 |

要点：

- 百度瓦片编号与 Leaflet 标准 XYZ 索引不同，**必须**用 `BaiduTileLayer`，
  否则切百度后整张图错位/错瓦片；
- 该实现与社区常见的百度 CRS 插件等价，但**不依赖百度 JS API、不引外部脚本**；
- 缓存预取（§7）里同样做了百度编号换算（`tileUrlFor()`），缓存下来的 URL 与页面实际请求一致。

## 5. 自建 / 离线铁路图层（国内推荐）

### 5.1 本地铁路线 `rail_local.geojson`

> **当前版本实现状态（v3.2）**：页面 `RAIL_SOURCES` 已登记 `rail_local`
> （`{name:'本地铁路线（GeoJSON）', file:'rail_local.geojson'}`），`buildRail()` 见到
> `src.file` 会走 `buildLocalRail()`：用 XHR 读取同目录的 `rail_local.geojson`，
> 以 `L.geoJSON` 画到 `railPane`（紫色 `#8B5CF6`，线宽 2.2，透明度跟随铁路滑块）。
> 桌面配置页的 `config_ext.RAIL_LAYERS` 也列出该 id；安卓设置页的铁路下拉仍只列
> ORM 5 样式，但安卓地图页的「图层」面板读的是页面 `LBJ.layers()`，会包含
> 「本地铁路线（GeoJSON）」，可在那里选。**文件不存在/为空/JSON 解析失败**时页面会
> toast 原因并自动退回「不显示」。

自建本地铁路线（准备好 GeoJSON 后，两端共用同一份文件）：

1. 生成 `rail_local.geojson`（见下面的命令），WGS-84 经纬度、`FeatureCollection`；
2. 放到 **`shared/web/rail_local.geojson`**（与 `railmap.html` 同目录）：
   桌面随 `shared/` 分发，安卓构建时把 `shared/web/` 复制进 assets；
3. 页面用 XHR 读取（`file://` 下 `fetch` 不可用；桌面 QWebEngine 的
   `LocalContentCanAccessFileUrls` 与安卓 `allowFileAccessFromFileURLs` 均已放行）；
4. 页面已内置上述 `rail_local` 条目，**不需要再改代码**；若想改文件名或新增其它本地图层，
   照 `RAIL_SOURCES` 里 `{file: 'xxx.geojson'}` 的格式登记，并同步三处 id/名字清单
   （页面 `RAIL_SOURCES`、桌面 `config_ext.RAIL_LAYERS`、安卓设置页/兜底图层清单）。

**自建命令**（Geofabrik 中国 OSM 提取 → 过滤 `railway=rail` → 转 GeoJSON）：

```bash
# 1. 下载中国提取（Geofabrik，数据 ODbL，约 1 GB；建议在境外机器/CI 上做）
curl -O https://download.geofabrik.de/asia/china-latest.osm.pbf

# 2. 只保留 railway=rail 的 way（osmium-tool，https://osmcode.org/osmium-tool/）
osmium tags-filter china-latest.osm.pbf w/railway=rail -o rail.osm.pbf

# 3.（可选）只裁一条走廊，体积可从几十 MB 降到几百 KB
#    范围格式：minLon,minLat,maxLon,maxLat
osmium extract -b 115.7,28.4,116.1,28.9 rail.osm.pbf -o rail_corridor.osm.pbf

# 4. 导出 GeoJSON（WGS-84 经纬度）
osmium export rail_corridor.osm.pbf -f geojson -o rail_local.geojson

# 5. 放到 shared/web/rail_local.geojson（两端同时生效）
```

全国 `railway=rail` 的 GeoJSON 约几十 MB，页面一次性加载渲染，低配机器建议先裁剪。

### 5.2 自建 ORM 瓦片服务（能直接出图）

| 做法 | 步骤 | 适用 |
|---|---|---|
| Docker 自建 ORM | 用社区 [hiddewie/openrailwaymap](https://github.com/hiddewie/openrailwaymap) 镜像渲染中国范围，放境内 VPS + CDN；把页面 `RAIL_SOURCES` 的 `url` 改成自己的模板 | 多用户长期使用、内部部署 |

## 6. 天地图：tk 申请与 tdtReferer 白名单机制

### 6.1 tk 怎么申请

1. 打开 <https://www.tianditu.gov.cn/> → 注册（需实名）→ 进入「控制台」→「应用管理」→「创建应用」；
2. 应用类型选 **浏览器端**；填**域名白名单**（不支持通配符），例如 `example.com`。
   本地 `file://` 页面没有合法 Referer，靠 §6.3 两端的附加机制把白名单域名「借」给请求；
3. 审核通过后拿到 32 位 `tk`，填到 **设置 → 地图 → 天地图 tk**（配置字段 `tdtKey`，
   安卓为 `mapTdtKey`）；
4. 把第 2 步登记的白名单域名填到 **天地图 Referer 域名**（配置字段 `tdtReferer`，
   只填域名、不带 `http://` 前缀；**留空则不附加 Referer**）。
5. 没填 tk 时选中 `tdt_vec` / `tdt_img` 只会弹提示、不加载（避免满屏 418 失败瓦片）。

> tk 有配额与有效期（以控制台说明为准）；安卓端代拉会带 `Referer: https://<tdtReferer>/`，
> 若填的域名与申请时不符，天地图仍会拒绝（418/403）。

### 6.2 为什么 file:// 页面需要宿主附加 Referer

天地图「浏览器端」tk 会校验请求的 `Referer` 是否命中白名单域名。本程序两端地图页都以
`file://` 方式加载（桌面 `QWebEngineView.setHtml(html, baseUrl=file://<shared/web>/)`、
安卓 `file:///android_asset/web/railmap.html`），页面自己发出的请求没有合法 Referer
→ 被拒。因此**两端约定同一机制**：宿主在网络层给 `*.tianditu.gov.cn` 的请求附加
`Referer: https://<tdtReferer>/`。页面本身不感知 Referer（纯宿主网络层行为），
配置字段两端同名：`tdtKey` / `tdtReferer`。

### 6.3 两端实现位置

| 端 | 实现 | 触发时机 |
|---|---|---|
| **桌面** | `desktop/cr_lbj/ui/map_host.py` 的 `_TdtRefererInterceptor`（`QWebEngineUrlRequestInterceptor`，装在页面 profile 上）；`_tdt_referer()` 负责把用户输入规整成 `https://<域名>/`（容错粘贴了 `https://example.com/xxx`） | `load()` 装拦截器；`_sync_referer()` 在加载与每次 `apply_config()` 时把最新 `tdtReferer` 同步给拦截器 |
| **安卓** | `android/.../core/TileCache.kt` 的 `refererFor(host, tdtReferer)`（原生代拉时加头）+ `MapPage.kt` 的 `WebViewClient.shouldInterceptRequest`（瓦片主机查缓存/代拉） | 每次代拉瓦片时按当前设置取 `tdtReferer` |

请求头规则（两端一致）：

| 主机 | 附加 Referer | 原因 |
|---|---|---|
| `*.tianditu.gov.cn` | `https://<tdtReferer>/`（**仅当 tdtReferer 非空**） | 天地图浏览器端 tk 的域名白名单校验 |
| `*.bdimg.com` | 固定 `https://map.baidu.com/` | 百度瓦片无 Referer 会 403（部分时段/节点），固定站点 Referer 可稳定取图 |
| `*.openstreetmap.org` / `*.openrailwaymap.org` | **不附加 Referer**，只改写应用 UA | 两家政策要求可识别 UA、禁止伪造来源；带合规 UA 实测 200（§3.5） |
| 其它 | 不改动 | — |

### 6.4 天地图瓦片 URL（官方 WMTS 栅格接口）

页面用天地图官方 **WMTS** 接口拼 XYZ（`_w` = 球面墨卡托，与 Leaflet 的 EPSG:3857 匹配）：

```
https://t{0-7}.tianditu.gov.cn/vec_w/wmts?SERVICE=WMTS&REQUEST=GetTile&VERSION=1.0.0
  &LAYER=vec&STYLE=default&TILEMATRIXSET=w&FORMAT=tiles
  &TILEMATRIX={z}&TILEROW={y}&TILECOL={x}&tk=<tdtKey>
```

影像为 `img_w`（`LAYER=img`），最大 18 级，子域 t0–t7。当前版本**不叠加注记层**
（`cva`/`cia`），只做纯底图；需要中文注记可自行在 `BASE_SOURCES` 里加一层注记瓦片。
格式依据：天地图官方服务文档 <https://lbs.tianditu.gov.cn/server/MapService.html>。

## 7. 离线瓦片缓存

### 7.1 用户怎么用

1. 在「实时位置」地图页右上角点 **图层 ▾** 打开面板；
2. 先选好底图（缓存的是**当前底图 + 当前视野**）；
3. 点 **缓存本区域**：缓存范围 = 当前 zoom ~ zoom+3（页面配置 `cacheZoomDelta=3`，
   最高到 z18；单级瓦片超过 40×40 时跳过该级，避免误点缓存整省）；
4. 面板状态行显示 **缓存进度 done/total**，完成后再显示 **已存 N 张 / X MB**
   （安卓宿主支持统计时）；
5. 离线后直接打开地图，命中缓存的瓦片照常显示，未命中的显示灰块并计数失败。

**安卓端**额外提供管理入口：设置 → 地图 → 显示「地图瓦片缓存：N 张 / X MB（上限 300 MB）」，
下面是 **清除地图缓存** 按钮。

| 端 | 缓存落到哪 | 上限 | 占用/清除 |
|---|---|---|---|
| **安卓** | 应用私有缓存目录 `cacheDir/tile_cache/`（DiskLruCache，按 URL 的 SHA-256 建键） | **300 MB**，LRU 自动淘汰 | 设置页显示张数/大小，可一键清除 |
| **桌面** | 宿主未实现 `LBJHost.cacheArea` → 页面降级为**图片预取**，瓦片进入 QtWebEngine 的磁盘 HTTP 缓存（由 Chromium 管理） | 由 Chromium 缓存策略决定 | 页面不提供统计/清除；需要清理时删程序数据目录下的 WebEngine 缓存 |

### 7.2 页面侧实现（`shared/web/railmap.html` §8.5）

- `cacheArea()`：算当前视野 z0~z1 的瓦片 URL（含百度编号换算、天地图 tk 替换），
  若 `window.LBJHost.cacheArea` 是函数 → `LBJHost.cacheArea(JSON.stringify(urls))` 交给宿主；
  否则 `prefetchLocal()` 用 `new Image()` 4 路并发预取（进浏览器 HTTP 缓存）。
- `LBJ.onCacheProgress(done, total)`：宿主每缓存若干张回调一次 → 更新面板进度；
  完成时 toast「瓦片缓存完成：N 张」并调 `host.cacheStats()` 刷新占用。
- `LBJ.cacheStats(json)`：宿主回传 `{"count": 张数, "bytes": 字节数}` → 面板显示占用。
- 配置项 `cacheEnabled`（默认 `true`）可在注入配置里关掉；关掉后点按钮只弹提示。
- 安卓实现：`TileCache` 拦截瓦片主机（天地图/百度/高德/OSM/ORM），命中直接返回，
  未命中用 `HttpURLConnection` 代拉（OSM/ORM 发应用 UA、其余图源发浏览器 UA；
  天地图按 `tdtReferer` 加 Referer，百度固定 `map.baidu.com`；10 s 连接 / 20 s 读取超时），
  成功落盘并返回；非 2xx/超时/异常返回 `null`，回退 WebView 原路请求。进度每 8 张或完成时回传。

> 注意：缓存的是**瓦片 URL**，不是地图引擎数据。同一个位置换底图 / 换缩放会缺瓦片，
> 想覆盖离线范围就多缓存几个缩放级别（在不同 zoom 下各点一次）。

## 9. 两端契约（宿主与页面）

### 9.1 页面暴露给宿主的 `window.LBJ`

|---|---|
| `update(payload)` | 批量推送：`{trains:[{id,train,direction,lat,lon,speed,km,ts,info?,...}], focus, night, follow, showTrail}`，坐标 **WGS-84**；`info` 为车次/机车信息对象（键见下），可缺省 |
| `setTrainInfo(idOrTrain, info)` | **v3.2**：宿主异步查询到车次/机车信息后补进标记（**不改变位置**），显示在标记副标题与点击弹窗；`idOrTrain` 是标记 id 或车次号，`info` 可传对象或 JSON 字符串，返回命中的标记数。`info` 字段：`grade` 等级 / `bureau` 担当局 / `section` 担当段 / `owner` 配属段 / `model` 车型 / `from`·`to` 始发终到 / `locoDepot` 机车配属单位 / `locoMaker` 制造厂 / `locoModel` 机车型号 |
| `pushTrain(lat,lng,name,id,opts)` | 单车上报（安卓早期接口，保留） |
| `focus(id)` / `clear()` | 聚焦某车 / 清空标记与轨迹 |
| `setFollow(b)` / `follow()` / `locked()` / `unlock()` | 跟随开关 / 状态 / 是否被用户手动接管 |
| `setNight(b)` / `isNight()` | 夜间配色 |
| `centerTo(addr)` / `center()` | 回默认中心 / 读当前视图中心（`[lng,lat]`，WGS-84） |
| `setBase(id)` / `base()` | 切底图 / 读底图 id |
| `setRailway(on)` / `setRailStyle(id)` / `rail()` / `railOpacity(v)` | 铁路图层开关 / 样式 / 不透明度 |
| `coordMode()` | 当前底图基准：`wgs` / `gcj` / `bd` |
| `status()` | `{base, rail, coord, night, follow, locked, zoom, center:[lng,lat], tilesTotal, tilesFailed, railTilesTotal, railTilesFailed}`。**v3.2 起统计分图层**：`tilesTotal`/`tilesFailed` 只统计**底图**（`tilesTotal` 是成功的 `tileload` 数），铁路层看 `railTilesTotal`/`railTilesFailed` |
| `layers()` | `[{id, name, coord, kind:'base'|'rail'}]` |
| `applyConfig(cfg)` / `resize()` | 推配置 / 容器尺寸变化后 `invalidateSize(false)` |
| `centerLatLng(lat, lng[, zoom])` | **转到本机位置**：居中 + 停止自动跟随 + toast「已转到本机位置」；入参 WGS-84；参数非法返回 `false`（安卓「转到自己位置」按钮调用） |
| `setCenter(lat, lng[, zoom])` | 显式把视图挪到某坐标（WGS-84），会重新开启跟随 |
| `onCacheProgress(done, total)` / `cacheStats(json)` / `refreshCacheStats()` | 缓存进度回调 / 统计回传 / 主动查统计（§7） |
| `ready` | 页面 API 就绪标志（恒 `true`） |

另保留旧名 `window.updateTrain(lat,lng,name,follow)` 兼容安卓早期调用。

### 9.2 宿主暴露给页面的 `window.LBJHost`（可选）

| 方法 | 参数 | 说明 |
|---|---|---|
| `onLayers(json)` | `{"base","rail","railOpacity","night"}` | 用户在**页面内**改了图层组合时回调宿主；宿主据此写回配置/同步工具栏。只在组合真的变化时触发 |
| `cacheArea(urlsJson)` | JSON 数组字符串（瓦片 URL 列表） | 请求宿主代拉并落盘缓存；宿主不存在/不实现时页面自动降级为预取 |
| `cacheStats()` | 无 | 请求宿主回传 `LBJ.cacheStats({count,bytes})` |

> 桌面端**不注入 `LBJHost`**：图层变化靠 `MapHost` 每 1200 ms 轮询 `LBJ.status()` 发现，
> 少一个 QWebChannel 依赖；缓存走页面预取。
> 安卓端用 `addJavascriptInterface(HostBridge, "LBJHost")` 注入（`MapPage.kt`）。

### 9.3 装载方式（桌面宿主）

```python
html = open(os.path.join(web_dir, 'railmap.html'), encoding='utf-8').read()
html = _CONFIG_MARK.sub(lambda _m: 'INJECTED = %s;' % json.dumps(cfg), html, count=1)
view.setHtml(html, QUrl.fromLocalFile(web_dir + os.sep))   # baseUrl 必须是目录且以 / 结尾
```

- 配置注入点：页面里那行 `/*__LBJ_CONFIG_START__*//*__LBJ_CONFIG_END__*/`；替换 0 次也照样加载，
  `loadFinished` 后 `LBJ.applyConfig(cfg)` 兜底。
- `baseUrl` 指向 `shared/web/` 目录，`vendor/leaflet/leaflet.js|css` 才能按相对路径解析；
  指向文件或漏掉结尾分隔符会整页白屏。
- **关键修复（v3.1）**：QtWebEngine 默认禁止 `file://` 页面访问远程 URL
  （`WebAttribute.LocalContentCanAccessRemoteUrls = False`），表现为页面能开、Leaflet 也加载了，
  但**所有瓦片请求被静默拦截，地图一片灰**——这是 v3.0 桌面端「地图不显示」的真实原因。
  `map_host.py` 现在显式打开：

  ```python
  st = self._page.settings()
  st.setAttribute(st.WebAttribute.LocalContentCanAccessRemoteUrls, True)
  st.setAttribute(st.WebAttribute.LocalContentCanAccessFileUrls, True)
  ```

  安卓 `file:///android_asset/` 页面由 WebView 原生代拉/`setAllowFileAccessFromFileURLs` 放行，
  没有这个开关。

## 10. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| **桌面端地图一片灰、页面能开、状态瓦片 0 成功** | QtWebEngine 默认拦 `file://` 页面的远程请求（v3.0 遗留问题） | 确认 `map_host.py` 里已设 `LocalContentCanAccessRemoteUrls = True`（§9.3）；用最新构建 |
| 地图一片灰、状态写「瓦片失败 N」 | 当前底图域名不可达（网络/代理/地区） | 换高德街道（默认、免 Key、实测最快）；或 OSM/天地图（天地图先填 tk） |
| **ORM 铁路图层全部失败（403/418）** | ① 旧版（≤ v3.2.1）用浏览器 UA 且伪造 Referer，被 OSM/ORM 判定违规；② 本机到 ORM 官方瓦片的 TLS 常被阻断 | 用 **v3.2.2 及以后**版本（合规 UA、不伪造 Referer）；仍失败多为网络阻断，可先用本地铁路线（§5.1）或自建瓦片（§5.2） |
| **地图提示「底图不可达」但底图其实能显示** | 旧版（≤ v3.1）把铁路瓦片失败也算进底图统计：ORM 缺 Referer 403 后连累底图判定 | v3.2 已修：统计按图层分离（`baseTileOk/baseTileFail` 与 `railTileOk/railTileFail`），全屏提示只由**底图**触发，条件是失败 ≥ 6 且（无成功瓦片或失败率 ≥ 95%，即 `baseTileFail >= baseTileOk * 19`）；铁路失败最多一行小字提示。仍误报就确认没在用旧页面文件 |
| `status()` 里 `railTilesTotal/railTilesFailed` 是什么 | 铁路图层的瓦片成功/失败计数；`tilesTotal/tilesFailed` 自 v3.2 起**只统计底图** | 桌面 `MapPanel` 只用 `tilesTotal/tilesFailed` 判底图可达，不受铁路层影响；铁路层看 `railTilesTotal`/`railTilesFailed`，页面状态行显示「铁路 成功/失败」 |
| 选天地图提示「需要天地图 Key」 | `tdtKey` 为空 | 按 §6.1 申请并填「天地图 tk」；不填就别选天地图 |
| 天地图填了 tk 仍失败（418/403/满屏灰） | Referer 白名单不匹配，或没填 Referer 域名 | 把申请 tk 时登记的白名单域名填到「天地图 Referer 域名」；确认两端宿主版本带拦截/代拉机制（§6.3） |
| **百度底图 403 / 满屏灰** | 请求缺 `Referer`（部分时段/节点） | 两端宿主已固定给 `*.bdimg.com` 加 `Referer: https://map.baidu.com/`；确认用的是 v3.1 及以后宿主，别用旧版页面 |
| 切百度后地图错位/花屏 | 用了普通 `L.tileLayer` 而非 `BaiduTileLayer` | 检查页面是否被改坏（百度瓦片编号换算见 §4.2）；恢复 `shared/web/railmap.html` |
| OSM 一直转圈/超时 | 本机网络到 OSM 不可达（实测 15 s 超时） | 换高德街道（免 Key）；要铁路图层就换天地图（先配 tk） |
| 铁路图层开了却什么都没有 | ①当前是偏移坐标系底图（高德/百度），图层已被自动暂停；②该地区 OSM 无铁路数据；③样式本身稀疏 | 看状态行「铁路」一行；换 OSM/天地图；`signals`/`maxspeed` 在中国缺数据属正常 |
| 切到高德/百度后铁路图层自己关了 | 设计如此（WGS-84 无法与偏移栅格混叠），页面提示「铁路图层已暂停」 | 要铁路就切回 OSM/天地图，页面会自动恢复原样式（`railWanted`） |
| 铁路线整体漂 300~500 m | 在偏移坐标系底图上硬叠了 WGS-84 图层 | 换 OSM/天地图；或改自建 WGS-84 瓦片 |
| 「缓存本区域」没反应/只弹预取进度 | 桌面宿主没有磁盘缓存接口，页面降级为图片预取 | 桌面属预期（瓦片进浏览器 HTTP 缓存）；要可管理的缓存请用安卓端 |
| 安卓缓存一直 0 张 | 底图不可达，代拉失败 | 先确认底图能出图再缓存；看设置页「地图瓦片缓存」占用 |
| 页面白屏 / 提示缺少地图页面文件 | 打包漏了 `shared/web/`，或 `vendor/leaflet/` 不完整 | 重新打包（spec 已带 `shared` datas）；源码运行确认 `shared/web/vendor/leaflet/leaflet.js` 存在 |
| 换底图后列表/工具栏状态不同步 | 页面与宿主配置不一致 | 桌面 1200 ms 轮询会写回；等 2 秒或重开地图卡片；安卓由 `onLayers` 即时写回 |
