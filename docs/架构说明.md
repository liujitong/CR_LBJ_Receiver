# 架构说明

> 适用版本：v2.5（2026-11 目录分层重构后）
> 配套：[用户手册](用户手册.md) ｜ [技术参考](技术参考.md) ｜ [高德地图配置手册](高德地图配置手册.md)

## 1. 为什么要分层

v2.4 及以前，7 个 Python 源文件平铺在仓库根目录，其中 `SDR_ALL_LBJ_GUI.py`
单文件 5400+ 行、塞了 26 个类（面板、对话框、主窗口、数据库、线程、启动逻辑），
改一处要在几千行里翻找，模块职责也无法从目录看出来。

v2.5 把源码收进 `cr_lbj` 包，按**职责**而不是文件类型分层，并把 GUI 巨石切成
多个实现模块。根目录只留一个入口 `main.py` 和构建/资源文件。

## 3. 分层职责与依赖方向

| 层 | 目录 | 允许依赖 | 不允许 |
|---|---|---|---|
| 工具 | `utils/` | 标准库 | 任何 Qt / 项目模块 |
| 数据 | `data/` | 标准库、`utils/` | Qt 控件、界面类 |
| 内核 | `core/` | 标准库、numpy/scipy、`data/` | Qt 界面类 |
| 界面基础 | `ui/theme.py`、`ui/widgets.py` | 标准库、PySide6、qfluentwidgets | 业务类 |
| 界面实现 | `ui/components/`、`ui/dialogs/`、`ui/windows/` | 以上全部 + `runtime.py` | 反向依赖 `app.py` |
| 运行时 | `runtime.py` | 以上全部 | 界面实现类 |
| 组装 | `gui.py` | 所有实现模块 | —— |
| 启动 | `app.py` | `gui.py` + `runtime.py` | —— |
| 入口 | `main.py` | `app.py` | —— |

依赖是**单向**的：`runtime → 实现模块 → gui → app → main`，没有环。

`core/` 内部还有一条更短的单向链：

```
rtl_paths.py（纯路径） ← source_stats.py（纯统计） ← usb_direct.py（USB 直连）
                                                        ↑
                                        decoder.py（数据源分发 + DSP）
```

`usb_direct.py` **不能** import `decoder.py`（decoder 反过来要 import 它），
所以它需要的「文件定位」与「统计口径」都下沉到前两个模块。加新的数据源时
同理：基础能力往 `rtl_paths` / `source_stats` 放，实现类自己放一个模块。

## 4. 三个关键设计点

### 4.1 共享运行时 `runtime.py`

原 GUI 文件的模块级部分（Qt import、控件别名 `QPushButton = K.PushButton`、
`UI_SCALE`、`spx()`、`scale_qss()`、`CONFIG_PATH` / `DB_PATH` / `ICON_PATH`、
`FIRST_RUN` 首次运行复制配置、`applyPgTheme()`）抽到这里，是各实现模块**唯一**
的公共依赖。每个实现模块开头一句 `from cr_lbj.runtime import *` 即可沿用原代码，
不需要逐行改 import。

- **路径**：`runtime.py` 位于 `cr_lbj/` 下，故 `SRC_DIR` 取 `__file__` 的**上一级**
  才是项目根；打包后仍用 `sys._MEIPASS` / `sys.executable`，不受影响。
- **缩放共享**：`spx()` 与 `scale_qss()` 改为读 `K.scale()`（`ui/widgets.py` 的
  `setScale()` / `scale()`），而 `app.main()` 里本来就会调 `K.setScale(UI_SCALE)`。
  这样拆分后所有模块读的是同一份倍率，不会各自持有过期的 `UI_SCALE` 副本。

### 4.2 GUI 组装层 `gui.py`

各实现类分散在 `core/ data/ ui/` 下后，方法体里跨模块的裸类名（例如
`MainWindow` 里 `LocoDetailDialog(...)`）在运行时需要能在**该模块的 globals** 里找到。
`gui.py` 做两件事：

1. 按原文件顺序 `from <模块> import *` 把全部名字汇到同一命名空间；
2. 用 `importlib.import_module()` 取回每个实现模块，把聚合后的名字**回填**到
   缺失该名字的模块（只补不覆盖）。

因此实现模块之间不需要互相 import，也不会出现循环依赖。

### 4.3 启动层 `app.py` 与入口 `main.py`

`main()` 负责参数解析、`CoreConfig.load()`、高 DPI 策略、主题、缩放、QApplication
初始化和 `MainWindow` 创建。`main.py` 只有 4 行，是源码运行和 PyInstaller 打包
共用的唯一入口。`SDR_LBJ.spec` 的 `Analysis(['main.py'])` 与之一致。

## 5. 构建

```bash
python build.py                # 清理 -> 打包 -> 清理过程文件 -> 校验
python build.py --no-clean      # 跳过打包前清理（增量）
```

`build.py` 会调用 `SDR_LBJ.spec`，入口为 `main.py`；`cr_lbj` 包由 PyInstaller
静态导入自动收进 PYZ，`spec` 的 `hiddenimports` 里也显式列出了全部实现模块，
避免 `gui.py` 的动态 `import_module` 漏收。

随包数据：`国铁.ico`、`lbj_config.json`、`README.md`、`docs/`（含本文件）、
`tools/rtl/`。机车映射表 `cr_lbj/data/loco_info.py` 同时作为只读数据放一份到
`_MEIPASS` 方便查阅；程序实际导入的是 PYZ 里的模块。

> 源码仓库默认**不保留** `dist/`、`build/`、`__pycache__`、`*.pyc` 等构建产物。
> 含高德 Key 的本机配置请另存为 `lbj_config.local.json`（已加入 `.gitignore`，
> 不入库）；程序读取的是项目根的 `lbj_config.json`。

## 6. 扩展指引

- 新增一个**车型参数** → 改 `cr_lbj/data/loco_info.py` 的 `LOCO_INFO`。
- 新增一个**解码算法 / 信号链** → 放 `cr_lbj/core/`，不要引 Qt 控件。
- 新增一个**数据源** → `cr_lbj/core/` 下独立模块，实现 `open/read/close/getDiagnostics`，
  读流时调 `source_stats.recordBlock()`，诊断直接 `buildDiagnostics(self, 'net'|'usb')`。
- 新增一个**面板** → 放 `cr_lbj/ui/components/`，在 `cr_lbj/gui.py` 的导入列表
  和 `_PART_MODULES` 里各加一行。
- 新增一个**对话框** → 放 `cr_lbj/ui/dialogs/`，同上登记。
- 新增**全局常量 / 主题色 / 缩放规则** → 放 `cr_lbj/runtime.py` 或 `ui/theme.py`。
- 与 Qt 无关的小工具 → 放 `cr_lbj/utils/helpers.py`。

> 登记时保持「按原文件顺序」的导入顺序：靠后的模块可能用到靠前模块在导入期
> 求值的常量，顺序错了会在启动时报 NameError。
