## 1. 总体结构

```
                    ┌──────────────────────┐
                    │  shared/（两端共享）  │
                    │  web/railmap.html    │  地图页面（Leaflet 单文件）
                    │  data/*.csv          │  号段表 / 车型表 / 城市坐标

                    └───────┬──────────────┘
                            │
        ┌───────────────────┴───────────────────┐
        │                                       │
┌───────▼─────────┐                    ┌────────▼────────┐
│  desktop/ (PC)  │                    │  android/ (APK) │
│  Python         │                    │  Kotlin + C++   │
└─────────────────┘                    └─────────────────┘
```

地图页面与数据表是唯一的共享实现：两端加载同一份 `railmap.html`，通过 JS 桥（`window.LBJ` API）注入列车坐标、配置与状态。因此地图行为、底图清单、坐标系转换、跟随逻辑在两端完全一致。

### 线程模型

| 线程 | 职责 |
|---|---|
| GUI 线程 | Qt 事件循环，只做绘制与用户输入 |
| DSP 线程 | 取块 → 前端处理 → 频谱 → 解码 → 回调（不阻塞 UI） |
| 数据源线程 | RTL-TCP / OWRX 网络读取或 USB 异步回调 |
| 后台查询线程 | 车次 / 配属查询、数据更新检查 |

线程间通过 Qt 信号传递解码结果、状态帧与日志；历史记录写入在 DSP 回调内完成，但数据库使用短连接，避免长事务阻塞。

### 数据流

```
数据源线程 → 环形队列 → DSP 线程
                           ├→ 频谱缓冲 → 30 fps 定时器 → 频谱面板 + 瀑布
                           ├→ 解码器 → 解码结果 → 去重 → 信号桥
                           │                              ├→ 当前解码表格
                           │                              ├→ 地图（JS API）
                           │                              └→ 历史库（SQLite）
                           └→ 状态帧 → 仪表板 / 状态条
```

## 3. Android 模块

```

├── cpp/
│   ├── core/
│   │   ├── engine.h/.cpp   引擎：数据源、DSP 线程、状态帧发布
│   │   ├── decoder.h       解码器（与桌面 Python 逐行对应）

│   │   ├── status_frame.h  双缓冲状态帧（276 word）

│   ├── thirdparty/         librtlsdr / libusb
│   └── lbj_jni.cpp         JNI 接口
├── java/xyz/mlxkj/crlbj/
│   ├── core/               设置模型、数据源配置、RTL profile、号段表、关于信息
│   ├── data/               Room 数据库与 DAO
│   ├── engine/             native 绑定、状态帧轮询
│   ├── vm/                 ViewModel（状态、设置、解码事件）
│   └── ui/                 Compose 页面（地图/解码/信息/状态/设置）+ 组件
└── assets/                 来自 shared/（地图页面、数据表、about.json）
```

### 线程模型

| 线程 | 职责 |
|---|---|
| 主线程 | Compose 渲染、输入 |
| DSP 线程（native） | 取块 → 前端 → 频谱 → 解码 → JNI 回调 |
| 读线程（native） | USB 异步回调 / socket 读取 → 环形缓冲 |
| 状态轮询协程 | 每 40 ms 读状态帧，seq 变化才发布 |
| IO 协程 | Room 写入、车次查询、瓦片请求 |

### 解码一致性保证

C++ 解码核心是 Python 实现的逐行移植：

- BCH 伴随式表、同步字、DPLL 参数、BCD 字符表、机车代号表、GBK 表逐项一致；
- 仓库内置 IQ 回放对拍套件（`android/tools/duipai/`）：同一份 960 kS/s 抓包分别跑 C++ 与 Python，逐字段比对，要求差异为 0；
- 车次分类使用共享向量文件生成测试用例，两端消费同一份数据。

## 4. 地图页面内部结构

`shared/web/railmap.html` 是单文件应用：

| 部分 | 内容 |
|---|---|
| 底图注册表 | 7 种底图（高德/百度免 Key、OSM、天地图矢量/影像） |
| 坐标系 | WGS-84 源；按底图转换为 GCJ-02 / BD-09；铁路图层在偏移底图上自动暂停 |
| 列车标记 | divIcon 标记 + 速度/公里标脚注 + 轨迹折线 |
| 跟随 | `follow` 意图 + `userTouched` 暂停；任何新信号恢复跟随 |
| 瓦片缓存 | IndexedDB / DiskLruCache（Android 由原生代拉） |
| 宿主 API | `update / pushTrain / focus / setFollow / status / applyConfig` 等 |

宿主（PC / Android）通过 `host.js(...)` 调用页面 API，页面通过 `notifyHost` 回传状态与配置变更。

## 5. 数据与配置位置

| 数据 | 桌面端 | Android |
|---|---|---|
| 配置 | `%LOCALAPPDATA%\CR-LBJ-Receiver\lbj_config.json` | SharedPreferences（JSON） |
| 历史记录 | `%LOCALAPPDATA%\CR-LBJ-Receiver\history.db` | Room `lbj_history.db` |
| 地图缓存 | 浏览器 IndexedDB（WebEngine profile） | DiskLruCache |
| 内置数据 | EXE 内 `_MEIPASS/shared/` | `assets/` |

桌面端首次启动会把旧版遗留的 `lbj_config.json` / `history.db` 从 EXE 同级复制到用户数据目录，之后一律写入用户目录，程序目录不产生文件。
