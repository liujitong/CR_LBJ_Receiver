## 2. 界面结构

```
┌───────────────────────────────┐
│ 大标题（28sp）      状态胶囊 ──┐│  ← 每页自己的「顶栏」，没有全局 AppBar
│ subtitle                      ││
├───────────────────────────────┤
│  分组卡片（13sp 次级色标题）    │
│  行距 8dp，圆角 8dp，1dp 描边   │
│                               │
├───────────────────────────────┤
│   ╭───────────────────────╮   │  ← 悬浮玻璃胶囊 Dock（5 个页签）
│   │  地图 解码 历史 状态 设置  │   │
│   ╰───────────────────────╯   │
└───────────────────────────────┘
```

* **Dock**（`ui/components/Dock.kt`）：圆角 30dp 药丸 + 半透明底 + 1dp 描边，选中项是
  CR 红浅底小药丸。不用真模糊（`RenderEffect` 要 API 31+，低端机掉帧），
  用「半透明 + 描边」模拟毛玻璃，内容滚到下面会隐约透出来。
* **状态胶囊**（`StatusCapsule`）：`数据源 · 接收中/已停止 · N 秒前`，点开有「开始/停止接收」。
  相对时间每秒自刷新，数据源取自设置（USB 直连 / rtl_tcp / OWRX）。
* **配色**：强调色只有 CR 红 `#DA291C` / CR 蓝 `#003DA5`，其余中性灰阶
  （暗色 `#0B0C0E/#121417/#1A1D21/#262A2F`，亮色 `#F2F2F7/#FFFFFF/#E5E5EA`），
  文字三级（100% / 62% / 38%）。见 `ui/theme/Theme.kt` 的 `LbjPalette`。
* **数字等宽**：速度 / 公里标 / 坐标 / 时刻一律 `FontFamily.Monospace`。
* **详情只走 `ModalBottomSheet`**：解码记录详情、车次时刻表、机车参数，不做整页跳转。

五个页面：`地图`（WebView 全屏）、`解码`、`历史`、`状态`、`设置`。
手动「车次·配属查询」并入设置页「查询·数据」分组，不再单独占页签。
启动器图标使用国铁徽标（`desktop/国铁.ico` 导出的 mipmap PNG + adaptive icon，
前景收在 108dp 画布的 66dp 安全区内，背景白色）。

## 3. 地图页（MapPage.kt 重写）

### 3.1 图源

加载 **桌面/安卓共用**的地图页：

```
file:///android_asset/web/railmap.html
```

* 铁路图源 = **OpenRailwayMap**（WGS-84 栅格瓦片）；
* 底图可切换 **7 种**（用户 v3.1 指定）：
  **高德 街道 / 高德 卫星 / 百度 街道 / 百度 卫星（均免 Key）**、OSM 标准、
  天地图 矢量 / 天地图 影像（需「浏览器端」tk）。默认 **高德 街道**。
  v3.1 之前的 5 张国外底图（街道/影像/地形/浅色/深色/路由）与旧渲染引擎已删除。

### 3.2 坐标系（重要）

底图分三类基准：

| 底图 | 坐标基准 | 处理 |
|---|---|---|
| OSM / 天地图 | WGS-84（天地图 CGCS2000≈WGS-84） | 零偏移，铁路图层可叠加 |
| 高德（街道/卫星） | GCJ-02 | 页面把标记/轨迹自动 `wgs2gcj` 纠偏；铁路图层自动关闭并提示 |
| 百度（街道/卫星） | BD-09 + 百度自有墨卡托投影 | 页面用纯 JS 实现百度 CRS（ll2mc/mc2ll + 瓦片编号换算），标记自动 `wgs2bd`；切百度时重建地图实例；铁路图层自动关闭 |

**Kotlin 侧一律推 WGS-84 原值，不做任何坐标转换**（转换全在共享页面里，两端一致）。

### 3.3 JS 接口（`window.LBJ`，逐字与桌面端一致）

| 调用 | 用途 |
|---|---|
| `LBJ.applyConfig({base,rail,railOpacity,night,follow,zoom,center,tdtKey})` | 一次性下发地图配置 |
| `LBJ.update({trains:[{id,train,lat,lon,speed,km,route,loco,direction,category,time,ts}],follow,showTrail,night})` | 批量推列车 |
| `LBJ.setFollow(b)` / `LBJ.locked()` / `LBJ.centerTo()` / `LBJ.resize()` | 跟随与视图 |
| `LBJ.centerLatLng(lat, lng)` | 居中到指定 WGS-84 坐标（「转到自己位置」用；停止自动跟随 + 页面 toast） |
| `LBJ.setBase(id)` / `LBJ.setRailStyle(id)` / `LBJ.railOpacity(v)` | 图层 |
| `LBJ.status()` / `LBJ.layers()` | 状态与可用图层清单 |
| `LBJ.onCacheProgress(done, total)` / `LBJ.cacheStats(json)` | 宿主回调：缓存进度 / `{count,bytes}` |

页面通过 `window.LBJHost.onLayers(jsonString)` 回报图层变化 → 原生侧落盘到设置
（`vm.updateViewSettings`，**不重建 DSP 链路**，切底图不断流）。

**离线瓦片缓存（宿主侧）**：`LBJHost.cacheArea(urlsJson)` / `LBJHost.cacheStats()`。
`MapPage` 的 `WebViewClient.shouldInterceptRequest` 对全部瓦片主机
（`*.tianditu.gov.cn`、`*.bdimg.com`、`*.autonavi.com`、`tile.openstreetmap.org`、
`*.openrailwaymap.org`）先查磁盘 LRU 缓存（`cacheDir/tile_cache`，上限 300MB），
命中直接返回；未命中用原生 `HttpURLConnection` 代拉并落盘（天地图按 `tdtReferer`
附加 Referer；百度固定附加 `Referer: https://map.baidu.com/`，否则 403）。
页面图层面板「缓存本区域」按钮枚举当前视野 z~z+3 的瓦片 URL 交给宿主缓存，
进度经 `LBJ.onCacheProgress` 回传；设置页「地图」子页显示占用并可清除缓存。
缓存过的区域断网仍可显示。

### 3.4 交互细节

* 右上角五个浮动胶囊：**跟随中/跟随**、**图层**、**回中心**、**转到自己位置**、**缓存本区域**。
* 「缓存本区域」：页面同名按钮在被隐藏的 `#panel` 里，原生胶囊用 JS 代点触发同一逻辑；
  进度由原生浮层显示（`缓存瓦片 d/t…` → `瓦片缓存完成：N 张`），同时经
  `LBJ.onCacheProgress` 回传页面；占用/清除在设置页「地图」子页。
* 「转到自己位置」：复用定位权限申请（`permLauncher`），取系统最后已知位置后调
  `LBJ.centerLatLng(lat, lng)` 居中；无权限/无定位时底部给出可理解提示（4s 自动消失）。
* 天地图 Referer 白名单：设置项 `tdtReferer` 非空时，代拉 `*.tianditu.gov.cn` 瓦片附加
  `Referer: https://<域名>/`；为空仍代拉（统一浏览器 UA）但不附加 Referer。
  全部瓦片主机的代拉/缓存规则见 §3.3。
* 「图层」弹 `ModalBottomSheet`：底图列表 / 铁路图层列表 / 透明度滑杆 / 夜间开关。
* **跟随自锁解除**：Kotlin 每 1.2s 调 `LBJ.locked()`，用户一拖地图就自动把设置里的
  `mapFollow` 置 false，避免「拖动被拉回」。
* 页面自带的右上角 `<select>` 图层面板在手机屏上太小 → 加载完成后 `display:none`，
  能力全部搬进原生面板与设置页。
* **空态**：没有坐标时显示半透明卡片「暂无列车坐标」+ 提示（不是白色大块）。
* **加载失败**：`onReceivedError`（主框架）→ 卡片显示原因 + 「重试」。
* **底部信息条**：最新一列车的车次/方向/速度/公里标 + 「距本机 X km」
  （GPS 取自系统最后已知位置，零功耗；无权限时可点「定位算距离」申请）。
* 外链（非 `file://`）一律转系统浏览器，不在 WebView 里打开。

## 4. 车次·配属查询（设置页「查询·数据」分组 + 解码页自动查询）

### 4.1 车次查询（`data/TrainInfoClient.kt`）

> 桌面端对应文件：`desktop/cr_lbj/data/train_info.py`（字段语义 1:1）。

数据源顺序（设置项 `trainQuerySource` = `auto` / `railgo` / `12306`）：

| 来源 | 接口 | 有 / 无 |
|---|---|---|
| RailGo（首选） | `https://data.railgo.zenglingkun.cn/api/train/query?train=G7` | 有等级/担当局/客运段/配属段/车型/时刻表/开行日/交路；个人托管，可能挂 |
| 12306（兜底） | `search.12306.cn` 查 `train_no` → `kyfw.12306.cn/otn/queryTrainInfo/query` | 官方稳定，**没有**担当/配属 |

`auto` 模式 RailGo 失败自动退 12306，结果里带 `fallbackFrom` 说明原因。

字段映射（节选）：

| 展示项 | RailGo | 12306 |
|---|---|---|
| 车次 | `number` | `station_train_code` |
| 等级 | `type` | `train_class_name` |
| 担当局 / 客运段 / 配属段 | `bureauName` / `runner` / `carOwner` | — |
| 车型 | `car` | — |
| 始发→终到 | `timetable[0]` / `timetable[-1]` | 同（`arrive_time`/`start_time`） |
| 停站分 | `stopTime` | 到发时刻自行相减 |
| 里程 | `distance` | —（无此字段） |
| 开行日 | `rundays[]` | — |
| 交路 | `diagram[]` | — |

实现要点：

* `HttpURLConnection` + `org.json`，**不引入 OkHttp**；
* 任何失败（超时/无网/HTTP 错/非法 JSON）都返回 `ok=false` + 中文文案，界面显示明确原因，
  不弹 Toast、不崩溃；
* 解析函数 `parseRailGo` / `parse12306Search` / `parse12306Detail` 是**纯函数**，
  JVM 单测直接覆盖（真实接口结构 JSON 字面量）；
* 车次号规整 `g 7` → `G7`，并把**全角字母**（中文输入法常见）转半角。

界面：输入框（键盘搜索/回车即查）→ 加载中转圈 → 结果卡（车次大号 + 来源 chip +
始发/终到/时刻 + 担当/配属 + 开行日 + 交路）→ 时刻表前 4 站 + 「展开全部 N 站」
（`ModalBottomSheet` 全屏可滚动，列：序/站名/到/发/停/里程）。

### 4.2 机车配属（`data/LocoRoster.kt`）

> 桌面端对应文件：`desktop/cr_lbj/data/loco_roster.py`；**规则必须完全一致**。

数据（`shared/data/`，两端同一份）：

| 文件 | 内容 |
|---|---|
| `loco_types.csv` | 机车代号 → 短型号 / 中文名（`code,shortCode,name`） |
| `loco_roster.csv` | 型号 + 号段 → 配属单位/备注/制造厂（16622 行 / 131 型号） |
| `loco_specs.json` | 型号 → 轴式/功率/构造速度/简介 |

匹配规则（与桌面端逐条对齐）：

1. 型号一律归一到**短型号**（`DF4`/`SS4`/`HXD1D`）：报文代号优先，其次短型号/中文名；
2. 号段是**闭区间**，`型号精确相等 && 起号 ≤ 号 ≤ 止号`，命中取**第一条**，
   其余重叠号段放 `alternatives`；
3. 别名只有 `DF4B → DF4`、`DF4R → DF4`；**不做泛化前缀回退**（`HXD1D` 绝不能退成 `HXD1`）；
4. 状态三分：`exact`（号段命中）/ `ok`（只认出型号，界面显示「配属未知」+原因）/
   `!ok`（表里没这型号，给出前缀相近型号建议）；
5. 查不到号段**不编造**配属，只说明「号段表内无该编号（可能新造/未收录）」并列出该型号
   已有号段范围。

界面：型号 + 号码两个输入框（型号框留空时自动拆 `HXD1D-0123` 这种粘贴文本）+
「选」型号选择器（`ModalBottomSheet`，可输入过滤，共 131 项）→ 结果卡（配属单位/号段/
制造厂/备注/别名归一/重叠号段）+ 车型参数卡。

### 4.3 解码页自动查询 + 手动跳转

* **自动**：收到新解码时 VM 在 `Dispatchers.IO` 自动调 `TrainInfoClient.query(train)` 与
  `LocoRoster.lookupLoco(loco, locoCode)`，结果内联在解码大卡（车次：等级/担当局/配属段/车型；
  机车：配属单位/制造厂）。按车次号 / 机车（型号+编号）去重缓存，同一车次/机车不重复请求；
  失败静默降级（不弹错、不阻塞解码）。
* **手动**：解码卡上点「车次」或「机车」→ `vm.requestTrainQuery / requestLocoQuery` →
  切到**设置页「查询·数据」分组**并自动预填 + 自动查询（`pendingQuery` 用一次即清，
  避免旋转屏幕重复触发）。

## 5. 第三方数据自动更新（`data/DataUpdater.kt`）

机车配属号段表在上游会更新（新增造车号段），因此支持运行时自动/手动更新。

### 5.1 上游与判定

```
GET https://api.gitcode.com/api/v5/repos/CCCccc233/LBJ_Console/contents/loco_info.csv?ref=resources
→ {"content":"<base64，可能带换行>", "sha":"<blob sha>", ...}
```

* `shape` 与 `sha` 都拿到才继续；`manifest.sha == 远端 sha` 且非强制 → 直接返回
  「已是最新」，不下载内容；
* base64 先去 `\n` / `\r` 再 `android.util.Base64.decode(..., Base64.DEFAULT)`（UTF-8 文本）。

### 5.2 落盘位置

| 文件 | 说明 |
|---|---|
| `filesDir/data/loco_roster.csv` | 运行时快照（头部补 3 行 `#` 注释：来源 + sha + 格式） |
| `filesDir/data/data_manifest.json` | 版本记录 |
| `filesDir/data/loco_roster.csv.bak` | 上一版快照（回滚用） |

`data_manifest.json` 样例：

```json
{
  "loco_roster.csv": {
    "sha": "8c1f0a2d3e4b5c6d7e8f90112233445566778899",
    "fetchedAt": "2026-11-26T03:12:45+08:00",
    "rows": 16622,
    "source": "gitcode:CCCccc233/LBJ_Console@resources"
  }
}
```

### 5.3 校验（不把用户数据弄坏的最后一道门）

`DataUpdater.validate(csv)`：

* 行数 ≥ **15000**（真实 16622）；
* 每行 ≥ 4 列，且 `>1%` 异常即拒；
* 起止号必须是数字（`>1%` 异常即拒）；
* 不同型号数 ≥ **100**（真实 131）——这是「拿错文件」最灵敏的特征。

校验不过 → **丢弃新数据、保留旧文件**，返回 `ok=false` + 原因。

### 5.4 原子替换

```
写 loco_roster.csv.tmp → 旧文件改名 .bak → .tmp 改名成正式文件
```

任一步失败都会把 `.bak` 还原，保证「要么全旧、要么全新」，不会出现半个文件。

### 5.5 触发时机

* **启动静默检查**：设置项 `dataAutoUpdate`（默认开）且「距上次检查 > 7 天」时，
  启动后延迟 2.5s 在 IO 线程后台执行；失败**完全静默**（不弹窗、不阻塞首屏）。
  上次检查时间存 `SharedPreferences("lbj").dataLastCheck`。
* **设置页「立即检查更新」**：结果用文字展示（成功/已是最新/失败原因）。
* 更新成功后 `LocoRosterHolder.refresh()` 重建索引，下一次查询即用新表，
  同时写一行日志 `[数据] 配属表已更新：…`。

### 5.6 加载优先级

`LocoRoster` 读数据时：

```
filesDir/data/loco_roster.csv   （更新过的）
        ↓ 不存在
assets/data/loco_roster.csv     （内置快照）
```

设置页显示当前来源（`外部更新` / `内置快照`）、行数、型号数、更新日期/时间。

## 6. 设置页（菜单式 + 自动保存）

首页是**链接式菜单列表**（图标 + 标题 + 副标题 + 右侧箭头），点击进入独立子页、顶部返回：
**数据源 | 射频 | 门控·AFC | 解码 | 地图 | 查询·数据 | 关于**。
子页返回/切换不丢未提交的草稿。

**没有保存按钮（v3.1 用户要求）**：改动即时自动保存并下发——
开关/单选/滑块立即生效；文本输入失焦/回车/离开子页时保存（400ms 防抖）；
连接类参数（源类型/采样率/增益）变更后自动重建 DSP 链路（`vm.updateSettings`）；
地图/界面类走 `vm.updateViewSettings`（即时下发 WebView，不断流）。

| 组 | 内容 |
|---|---|
| 数据源 | usb / rtl_tcp / owrx 三选一（USB 时隐藏主机端口）、采样率；**切到 USB 弹推荐参数对话框**（240 kS/s / 19.7 dB / DC 偏移 50 kHz，确认覆盖、取消保持不变） |
| 射频 | 频率 / 增益 / PPM / 信道带宽 / DC 偏移 |
| 门控·AFC | 门限 / 迟滞 / 保持、AFC 开关与参数、报文后保持 |
| 解码 | 去重窗口、ETA 上限、本站公里标、线路公里标（车次编排纯日期驱动，无手动方案选择） |
| 地图 | 底图下拉（7 种：高德/百度/OSM/天地图，见 §3.1）、铁路图层下拉（6 种）、不透明度滑杆、夜间/跟随开关、缩放、天地图 tk、**天地图 Referer 域名（tdtReferer）**、默认中心（预设城市下拉 + 经纬度手填）、**地图缓存占用 + 清除缓存** |
| 查询·数据 | 车次数据源 auto / railgo / 12306 + **内嵌「车次·配属查询」手动查询 UI** + 第三方数据（自动检查开关、当前来源/行数/更新日期、「立即检查更新」） |

## 7. 历史页 / 状态页 / 解码页（美化）

* **历史**：分组（按车次号 / 按机车号）+ 长按多选 + 全选 + 批量删除 + CSV 导出；
  卡片行：车次 + 方向方块 + `速度·K公里标·线路` + `机车·类别` + 时间 + 有坐标标记；

  采样率/调谐/增益/tuner/链路），带色调（正常绿、注意黄、异常红）；链路值短文案
  「USB」/「桥」保证 1/3 宽格子不截断。**日志卡可点按折叠/展开**：折叠只显示最新一条，

  **自动查询内联：车次等级·担当局·配属段·车型 / 机车配属单位·制造厂** /
  坐标 / ETA / 收到时间）、最近解码列表、点卡片看详情。

## 9. 已知限制

1. **USB 直连未经真机验证**（无 OTG 设备），模拟器只覆盖网络源与 UI 全链路。
2. 天地图底图需要用户自备「浏览器端」tk；未填时选中该底图只提示不加载。
   tk 若登记了 Referer 白名单，需在设置里填 `tdtReferer` 域名（安卓代拉瓦片附加 Referer）。
3. 12306 没有担当/配属字段，纯 12306 模式下这两行为空。
4. 号段表命中「第一条」——上游表内存在重叠号段，具体归属以原表顺序为准，界面会列出
   其余候选提示歧义。
5. `:app:testDebugUnitTest` 必须走 `tools/test.ps1`（中文路径 + JDK argfile 限制，
   见 `安卓构建与环境.md` §4）。
