> 适用版本：**v3.2.11**（2026-11-26） ｜ 适用端：桌面（Windows exe） / 安卓（APK） ｜ 最后更新：2026-11-26

| 别名 | `crlbjrelease` |
| 证书主体 | `CN=CRLBJREC, OU=Mobile, O=LiuJitong, L=Beijing, ST=Beijing, C=CN` |

> 与 CardWallet（`CN=CardWallet`）**CN 不同**，便于区分两个 App。

### 1.2 签名材料（**不要提交到 git**）

```
android/keystore/crlbjrelease.jks      # 私钥，丢了就再也无法覆盖升级
android/keystore.properties            # 口令（明文），同样不能泄露
```

两者已加入 `.gitignore`。**请务必备份到安全位置**（离线 U 盘/密码管理器）。
一旦丢失：已安装的用户只能卸载重装，无法增量升级。

### 1.3 复现签名的构建

```powershell
# 1) 确保 android/keystore.properties 存在（含 storeFile/storePassword/keyAlias/keyPassword）
# 2) 构建已签名 release APK
$env:JAVA_HOME='D:\Java\jdk-21.0.11'; $env:ANDROID_HOME='D:\Android\SDK'
cd android; .\gradlew.bat :app:assembleRelease

# 3) 校验签名
D:\Android\SDK\build-tools\36.0.0\apksigner.bat verify --print-certs `
    app\build\outputs\apk\release\app-release.apk
```

`app-release.apk` 只含 `arm64-v8a` / `armeabi-v7a`（真机用）；
模拟器验证请用 `assembleDebug`（含 x86_64，debug 签名为本机调试密钥）。

> **升级注意**：从旧的 debug 签名换成正式签名后，已装的旧包必须**卸载重装**
> （Android 不允许签名不同的同包名覆盖安装）。

## 2. Windows（EXE）

### 2.1 现状

| 项 | 状态 |
|---|---|
| 版本资源（文件属性页） | ✅ `CompanyName = 刘纪彤（BG2GBQ）`、`ProductName`、`LegalCopyright` 等已写入，版本号自动跟随 `cr_lbj.__version__` |
| Authenticode 数字签名 | ✅ 已签名（自签名证书 + DigiCert 时间戳） |
| Windows 属性页「发布者」 | ⚠️ 仍显示「未知发布者」——自签名证书链终止于**非受信任根** |

> 关键区别：**文件属性里的 `CompanyName`** 与 **签名证书主体**是两个东西。
> SmartScreen / 属性页顶部的「发布者」只认**证书链能否追到受信任根**。

### 2.2 自签名证书（当前使用）

**v3.2.10 关键修正：证书 DN 必须精简，否则 SmartScreen 会把所有字段摊开显示。**

第一版用 PowerShell `New-SelfSignedCertificate` 生成了 7 个字段
（`C/O/OU/L/S/CN/E`），结果是 SmartScreen 的「发行者」显示成：

```
bg2gbq@mlxkj.xyz, CN, 北京, 北京, BG2GBQ, 刘纪彤, 刘纪彤（BG2GBQ）
```

这不是期望效果（正常应只显示 CN）。现改用 **OpenSSL + `tools/codesign-openssl.cnf`**
生成规范证书：

| 项 | 值 |
|---|---|
| Subject | `C=CN, O=LiuJitong, CN=刘纪彤（BG2GBQ）`（**仅 3 字段**） |
| 编码 | UTF-8（`string_mask = utf8only`） |
| 扩展 | `CA:TRUE, pathlen:0` + `CodeSigning` + `digitalSignature` |
| 算法 | RSA 4096 / SHA256 / 10 年 |

> 自签名证书同时充当"根"，所以必须 `CA:TRUE` 才能通过链验证；
> `pathlen:0` 表示它只能签终端证书、不能再签中间 CA。

生成 / 更新：

```powershell
pwsh tools/make_codesign_cert.ps1    # 用 OpenSSL 生成 cert.pem/pfx/cer + 口令
pwsh tools/sign_exe.ps1              # 给 dist/CR-LBJ-Receiver.exe 签名 + 打时间戳
```

产出（`tools/signing/`，整目录已 gitignore）：

```
key.pem                私钥
cert.pem               PEM 证书
cr-lbj-codesign.pfx    证书+私钥（signtool 用）
cr-lbj-codesign.cer    DER 公钥证书（给用户安装信任）
password.txt           pfx 口令
```

### 2.3 让本机显示「发布者：刘纪彤（BG2GBQ）」

Windows 对「向受信任根添加证书」有**强制人工确认**（会弹安全警告框），
无法脚本静默完成。因此：

**方式一（推荐，双击即可）**：运行 `tools/install_cert.cmd`
（交付包里叫 `安装签名证书.cmd`），弹出「安全警告」时点 **是**。

**方式二（手动）**：双击 `cr-lbj-codesign.cer` → 安装证书 →
「当前用户」→「将所有证书放入下列存储」→ 浏览 → **受信任的根证书颁发机构** → 确定 → 是。

**方式三（管理员，机器级）**：

```powershell
certutil -addstore Root tools\signing\cr-lbj-codesign.cer
certutil -addstore TrustedPublisher tools\signing\cr-lbj-codesign.cer
```

验证：

```powershell
Get-AuthenticodeSignature dist\CR-LBJ-Receiver.exe | Select-Object Status, @{
    n='Signer'; e={ $_.SignerCertificate.Subject } }
# 期望：Status=Valid，Signer=C=CN, O=LiuJitong, CN=刘纪彤（BG2GBQ）
```

撤销：

```powershell
certutil -user -delstore Root <证书指纹>
certutil -user -delstore TrustedPublisher <证书指纹>
```

### 2.4 ⚠️ 关于 SmartScreen 仍提示「无法识别的应用」

即使证书已受信任、`Status=Valid`，**SmartScreen 仍可能拦截**，原因是两套完全不同的机制：

| 机制 | 判断依据 | 自签名能否解决 |
|---|---|---|
| 签名验证（属性页「发布者」） | 证书链能否追到**本机受信任根** | ✅ 能（导入证书后显示发布者名） |
| SmartScreen 信誉（「无法识别的应用」拦截） | 微软云端对**该文件/发布者**的下载声誉 | ❌ 不能：自签名文件永远没有云端声誉 |

所以本机第一次运行仍会看到拦截框，处理方式：

1. 点 **更多信息** → **仍要运行**（一次性放行，之后不再弹）；
2. 或把 exe 所在目录加入 Defender 排除（仅影响扫描，不影响 SmartScreen）；
3. 要**彻底不弹**，只能买 **CA 代码签名证书（首选 EV）**，
   或使用微软 **Azure Trusted Signing**（个人可申请，约 $9.99/月，需身份验证）——
   它们能让签名被全球 Windows 信任并获得云端声誉。

> 结论：自签名只解决"发布者显示为谁"，解决不了"SmartScreen 首次拦截"。

自签名无法做到。必须向 CA（如 Sectigo / DigiCert / SSL.com / Certum）申请
**代码签名证书**，然后用其私钥替换 `tools/signing/cr-lbj-codesign.pfx`：

* **OV（组织验证）**：约 ¥1000~2500/年，签名后仍可能需要一段 SmartScreen 声誉积累；
* **EV（扩展验证）**：约 ¥3000~6000/年，**立即**获得 SmartScreen 信誉（新发布者也不弹警告），
  且强制要求硬件令牌（USB Key / 云签名服务），不能再导出 .pfx 文件。

## 3. 构建流水线中的位置

```
python desktop/build.py
  └─ PyInstaller（SDR_LBJ.spec 自动生成 version_info.txt：发布者/产品/版权）
      └─ dist/CR-LBJ-Receiver.exe
          └─ pwsh tools/sign_exe.ps1        ← 手动执行（或接入 CI）
              └─ 已签名 exe（+ 时间戳）
```

安卓：

```
gradlew :app:assembleRelease
  └─ signingConfigs.release（读 android/keystore.properties）
      └─ app-release.apk（CN=CRLBJREC）
```

## 4. 安全约定

1. **私钥绝不入库**：`android/keystore/`、`android/keystore.properties`、
   `tools/signing/` 均在 `.gitignore`。
2. 口令不要贴在聊天/issue/README 里；`tools/signing/password.txt` 与
   `android/keystore.properties` 只留本机。
3. 备份策略：keystore + 口令一起离线备份两份（丢失=无法升级已发布 App）。
4. 若私钥泄露：立即换证书（新 CN/新 keystore），并让用户卸载重装；
   Windows 端需向 CA 申请吊销（CRL/OCSP）。
