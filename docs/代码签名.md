# 代码签名（Windows / Android）

> 适用版本：**v3.2.10**（2026-11-26） ｜ 适用端：桌面（Windows exe） / 安卓（APK） ｜ 最后更新：2026-11-26

本文说明两端的签名现状、如何复现签名、以及**让 Windows 显示「发布者：刘纪彤（BG2GBQ）」需要什么**。

## 1. 安卓（APK）

### 1.1 当前签名

| 项 | 值 |
|---|---|
| keystore | `android/keystore/crlbjrelease.jks`（PKCS12） |
| 别名 | `crlbjrelease` |
| 证书主体 | `CN=CRLBJREC, OU=Mobile, O=LiuJitong, L=Beijing, ST=Beijing, C=CN` |
| 算法 | RSA 4096 / SHA384withRSA |
| 有效期 | 30 年（2026-11 → 2056-09） |
| SHA-1 | `37:05:B5:2D:FE:F9:97:CD:2D:98:97:22:D2:5D:56:05:6C:7C:23:76` |
| SHA-256 | `14:BB:E3:4D:00:42:17:FA:9E:9F:F5:BD:F1:95:E8:F6:B2:87:EC:BF:14:52:BF:CC:18:9C:7A:40:29:32:3E:AD` |

> 与 CardWallet（`CN=CardWallet`）**CN 不同**，便于区分两个 App。

### 1.2 签名材料（**不要提交到 git**）

```
android/keystore/crlbjrelease.jks      # 私钥，丢了就再也无法覆盖升级
android/keystore.properties            # 口令（明文），同样不能泄露
```

两者已加入 `.gitignore`。**请务必备份到安全位置**（离线 U 盘/密码管理器）。
一旦丢失：已安装的用户只能卸载重装，无法增量升级。

### 1.3 复现签名的构建

```powershell
# 1) 确保 android/keystore.properties 存在（含 storeFile/storePassword/keyAlias/keyPassword）
# 2) 构建已签名 release APK
$env:JAVA_HOME='D:\Java\jdk-21.0.11'; $env:ANDROID_HOME='D:\Android\SDK'
cd android; .\gradlew.bat :app:assembleRelease

# 3) 校验签名
D:\Android\SDK\build-tools\36.0.0\apksigner.bat verify --print-certs `
    app\build\outputs\apk\release\app-release.apk
```

`app-release.apk` 只含 `arm64-v8a` / `armeabi-v7a`（真机用）；
模拟器验证请用 `assembleDebug`（含 x86_64，debug 签名为本机调试密钥）。

> **升级注意**：从旧的 debug 签名换成正式签名后，已装的旧包必须**卸载重装**
> （Android 不允许签名不同的同包名覆盖安装）。

## 2. Windows（EXE）

### 2.1 现状

| 项 | 状态 |
|---|---|
| 版本资源（文件属性页） | ✅ `CompanyName = 刘纪彤（BG2GBQ）`、`ProductName`、`LegalCopyright` 等已写入，版本号自动跟随 `cr_lbj.__version__` |
| Authenticode 数字签名 | ✅ 已签名（自签名证书 + DigiCert 时间戳） |
| Windows 属性页「发布者」 | ⚠️ 仍显示「未知发布者」——自签名证书链终止于**非受信任根** |

> 关键区别：**文件属性里的 `CompanyName`** 与 **签名证书主体**是两个东西。
> SmartScreen / 属性页顶部的「发布者」只认**证书链能否追到受信任根**。

### 2.2 自签名证书（当前使用）

```
tools/signing/cr-lbj-codesign.pfx   # 证书+私钥（gitignore）
tools/signing/cr-lbj-codesign.cer   # 公钥证书，可分发给用户安装
tools/signing/password.txt          # pfx 口令（gitignore）
```

证书主体：

```
CN=刘纪彤（BG2GBQ）, O=刘纪彤, OU=BG2GBQ, L=北京, S=北京, C=CN, E=bg2gbq@mlxkj.xyz
```

签名 / 重新生成：

```powershell
pwsh tools/sign_exe.ps1 -MakeCert   # 生成新证书（会覆盖旧 pfx）
pwsh tools/sign_exe.ps1             # 给 dist/CR-LBJ-Receiver.exe 签名 + 校验
```

### 2.3 让本机显示「发布者：刘纪彤（BG2GBQ）」

以**管理员**身份运行：

```powershell
pwsh tools/install_codesign_trust.ps1
```

它会把 `.cer` 导入「受信任的根证书颁发机构」和「受信任的发布者」。
之后本机属性页/签名校验即显示发布者名（仅本机；别人电脑仍显示未知）。

撤销：

```powershell
pwsh tools/install_codesign_trust.ps1 -Uninstall
```

### 2.4 要让**所有电脑**显示发布者 → 需要购买 CA 代码签名证书

自签名无法做到。必须向 CA（如 Sectigo / DigiCert / SSL.com / Certum）申请
**代码签名证书**，然后用其私钥替换 `tools/signing/cr-lbj-codesign.pfx`：

* **OV（组织验证）**：约 ¥1000~2500/年，签名后仍可能需要一段 SmartScreen 声誉积累；
* **EV（扩展验证）**：约 ¥3000~6000/年，**立即**获得 SmartScreen 信誉（新发布者也不弹警告），
  且强制要求硬件令牌（USB Key / 云签名服务），不能再导出 .pfx 文件。

#### 申请时需要提供的资料（请逐项确认后回复）

| 字段 | 说明 | 建议填写 |
|---|---|---|
| **主体类型** | 个人 / 个体工商户 / 公司 | ？ |
| **法定名称（CN）** | 证书上显示的名字，也是 Windows「发布者」显示的文字 | `刘纪彤（BG2GBQ）` 或公司全称 |
| **组织名（O）** | 公司/个体户名称；个人证书可为空或填姓名 | ？ |
| **部门（OU）** | 可选 | `BG2GBQ` |
| **国家（C）** | 两字母代码 | `CN` |
| **省/州（ST）** | 中文或拼音 | `北京` / `Beijing` |
| **城市（L）** | 中文或拼音 | `北京` / `Beijing` |
| **联系邮箱（E）** | CA 验证与证书联系邮箱 | `bg2gbq@mlxkj.xyz` |
| **联系电话** | CA 会电话回拨核实（OV/EV 必需） | ？ |
| **通信地址** | 证书登记地址（可与营业执照一致） | ？ |
| **域名（可选）** | 若申请含域名的证书 | `mlxkj.xyz` |
| **营业执照/身份证明** | 个人：身份证；企业：营业执照（扫描件） | ？ |
| **邓白氏编码（D-U-N-S）** | EV 证书通常要求企业有此编码 | ？ |
| **CSR** | 证书签名请求（可用 `keytool`/`certreq` 生成，我可代做） | 我来生成 |
| **私钥保存方式** | 文件（OV 常见）/ 硬件令牌（EV 强制） | ？ |

> 只要你把上表「？」项补全（尤其是**主体类型、法定名称、电话、地址、是否已有营业执照/D-U-N-S**），
> 我就能：① 生成符合要求的 CSR；② 拿到证书后接入 `tools/sign_exe.ps1`；
> ③ 把签名流程写进构建脚本，做到"打包即签名"。

## 3. 构建流水线中的位置

```
python desktop/build.py
  └─ PyInstaller（SDR_LBJ.spec 自动生成 version_info.txt：发布者/产品/版权）
      └─ dist/CR-LBJ-Receiver.exe
          └─ pwsh tools/sign_exe.ps1        ← 手动执行（或接入 CI）
              └─ 已签名 exe（+ 时间戳）
```

安卓：

```
gradlew :app:assembleRelease
  └─ signingConfigs.release（读 android/keystore.properties）
      └─ app-release.apk（CN=CRLBJREC）
```

## 4. 安全约定

1. **私钥绝不入库**：`android/keystore/`、`android/keystore.properties`、
   `tools/signing/` 均在 `.gitignore`。
2. 口令不要贴在聊天/issue/README 里；`tools/signing/password.txt` 与
   `android/keystore.properties` 只留本机。
3. 备份策略：keystore + 口令一起离线备份两份（丢失=无法升级已发布 App）。
4. 若私钥泄露：立即换证书（新 CN/新 keystore），并让用户卸载重装；
   Windows 端需向 CA 申请吊销（CRL/OCSP）。
